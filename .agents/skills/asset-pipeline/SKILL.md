For any new or replaced character sprite, follow the [character creation and registration rules](../../../DESIGN.md#새-인물-그림의-제작과-등록). Set the size against a reference before generating, then run `pnpm test:character-registration` and review the mixed cast in both reading formats.

For the all-character minimum-five requirement follow [the emotion coverage review](../../../docs/architecture/evidence/all-character-emotions-2026-11-11/review.md). The current slot owner is `packages/asset-registry/src/character-emotions.json`: verify distinct everyday/joy/anger/sorrow/mirth images for every individual, not only file counts or group aliases. Preserve old catalogue rows; the reviewed role map supplies filters/search. The common image preparation verifies all three receipts, including `emotions-v3`; run the dedicated235card editor/native smoke after runtime and Web builds.

Supporting-character expression batches also follow [the second expansion review](../../../docs/architecture/evidence/supporting-character-expansion-2026-11-11/review.md). The common preparation command checks both reviewed receipts; retain small-child/animal stature and all previous catalogue rows. The editor/native smoke accepts `KNOL_EXPRESSION_RECEIPT` to exercise each batch, including search/cancel/apply for every newly covered identity. New IDs require the matching API catalogue at an authorized deployment.

For the four-story expression additions follow the [selection/generation review](../../../docs/architecture/evidence/character-expression-expansion-2026-11-11/review.md). `generatedExpressionAsset` is a current-checkout generated asset, never restored from legacy. Keep source PNGs and exact WebP derivatives separate, validate with `python3 scripts/prepare-expression-assets.py`, keep previous catalogue rows/manuscripts intact, and update exact Runtime Contract paths plus API catalogue checks when publishing new IDs.

For white-matte character repairs follow the [reviewed replacement receipt](../../../docs/architecture/evidence/transparency-repair-2026-11-11/review.md). Keep stable IDs and tracked generated PNG/WebP pairs; verify with `python3 scripts/prepare-transparency-assets.py`. `generatedTransparencyRepair` assets come from the current checkout, never the fixed legacy baseline. Update the exact Runtime Contract path allowlist, provenance, source hashes and restore tests together, then rebuild runtime before Web.

카드(이미지 고르기·서재 표지·그림책 쪽 목록)는 빌드에서 만든 미리보기 `previewSrc`를, 무대·읽기·인쇄는 버전 붙은 원본 `src`를 쓴다. 주소·생성·권리·캐시 규칙은 [그림 미리보기와 버전 캐시](../../../docs/architecture/image-previews-and-caching.md)가 소유한다. 등록 그림을 바꾸면 미리보기는 빌드가 다시 만들고, 생성 설정을 바꾸면 `image-previews.json`의 버전과 경로를 함께 올린다.

그림책→놀스토리의 숏스토리 추천 무대는 [조합 목록](../../../packages/asset-registry/src/picturebook-stage-recipes.json)이 소유한다(원화 ID+revision 키, 작품 파일과 분리). 새 조합은 `assembly-review`로 넣고, `/picturebook?review=recipes`에서 가로 16:9·세로 9:16 실제 무대를 본 뒤 `pnpm exec vitest run packages/asset-registry/tests/picturebook-recipes.test.ts`(리비전·권리·중복 인물)를 통과해야 `approved`와 `reviewedAt`·`evidence`를 쓴다. 그림을 만드는 쪽은 자산 등록과 조합 갱신까지만 하고 승인하지 않는다. 세로 화면의 주인공은 `subject`로 지정하고, 공중의 인물은 바닥까지 이어진 자락으로 높이를 만든다(배치는 `geometry.bottom`을 바닥선에 맞춤). 새 그림이 필요한 쪽은 [제작 요청](../../../docs/architecture/picturebook-image-production-requests.md)에 원화 ID·검토한 후보와 탈락 이유·필요한 행동·기준 ID·구도를 남긴다. [설계](../../../docs/architecture/picturebook-to-chapters-design.md#조합-레코드-예시와-우선순위)

1. Read the [layout ownership ADR](../../../docs/decisions/0004-stage-layout-owned-by-runtime-core.md) and [authoring storage contract](../../../docs/architecture/authoring-storage-contract.md); inspect the resolver and provenance implementation before editing.
2. StoryDocument stores stable IDs; archives carry portable user-audio attachments. Keep source bytes, runtime derivatives and thumbnails distinct. Never replace a master with a runtime optimization.
3. Preserve existing IDs and resolve them to versioned runtime paths. Share common bytes rather than generating one asset package per work/student.
4. For custom audio reuse archive MIME/signature/SHA/provenance/size validation. Preserve explicit unused attachments and attachment order.
5. `audio-resources` stores shared bytes and per-work metadata separately. Importing another work with the same audio ID must not overwrite the original work's name, kind or provenance; copies preserve metadata and bytes.
6. Verify file/Excel/Google round trips and two-work import/copy/reload/re-export when audio storage changes. Run `pnpm test:media-provenance` for affected source/provenance work.
7. Generated runtime assets require `pnpm runtime:build` before `pnpm build`; then verify the served result. Respect private media boundaries and existing permissions.

Record changed owners/contracts and evidence through [documentation governance](../../../docs/architecture/documentation-governance.md). Do not infer public release rights from a valid hash.

Common-service audio follows [service rights](../../../docs/architecture/audio-service-rights.md) and [ADR0021](../../../docs/decisions/0021-scene-integrated-audio-rights.md). Only reviewed, scope-specific approvals enter the shared catalogue; preserve scene-only/standalone/preview/reference-export limits rather than treat every source as CC0. Run `pnpm test:service-audio`; build checks source hashes/rights/evidence and runtime ZIP contents. Excluded IDs stay in authored files as non-playable references, with a clear editor notice. Do not re-enable a retired source to satisfy a historical test or infer common-library approval from a user-entered provider tag.

For searchable sound properties read [audio attributes](../../../docs/architecture/audio-attributes-and-import.md) and [ADR0019](../../../docs/decisions/0019-audio-search-attributes-and-sources.md). Preserve original name, provider evidence and per-work tags; a provider tag alone does not establish rights. Check normal decoding, actual renderer paths and external worksheet edits; do not call metadata-only rows playable assets.

사용자에게 보이는 기능 이름과 설명은 [제품 용어 기준](../../../docs/architecture/editor-terminology-and-time.md#제품-용어-사용-기준--2026-10-19)을 따른다. 내부 키·현재 파일 계약과 과거 검증 기록은 용어 정리로 바꾸지 않는다.

For publication checks distinguish `story-service` from `standalone-assets`. Owner permission lives in the hash-pinned project-media authorization; it is not a CC0 dedication. Service-only images and scene-only approved audio retain their restrictions. Runtime distribution review binds exact package members and public SDK notices; regenerate and review evidence after runtime changes instead of relabelling an opaque binary. See [source/use review](../../../docs/architecture/evidence/media-rights-2026-11-01/checkpoint.json). Generated same-byte copies may use `usageReferencesFrom` only with an exact source SHA and no reference chain.

Provided KnolStory scene backgrounds are character-free; actors are separate selectable sprites. Covers and ShortStory pages explicitly allow scene illustrations. Do not globally hide or delete the old illustration catalogue. Preserve exact-catalog migration gates and the body/costume/shoe timeline when changing visual mappings; inspect ghost appearance separately from living companion actors. New generated sprites keep uniform body scale and transparent headroom for sitting/bending, not equal silhouette heights. See [layered scene review](../../../docs/architecture/evidence/layered-stories-2026-11-02/review.md) and the current `catalog-layered-scenes.ts` transform. Generated project files tracked in the checkout are not fixed-baseline legacy media; restoration validates them without trying to fetch them from story-maker.

When publishing new registered image IDs, check the API image's bundled catalogue too; a static Web-only release can leave uploads rejecting newly registered assets. Use `node server/operations/check-image-catalog.mjs IMAGE OUTPUT.json` on the candidate and deployed image. The read-only/network-none probe does not replace authenticated upload tests. Preserve backup/rollback and DB integrity for an authorized API update. See [API catalogue alignment](../../../docs/architecture/evidence/api-catalog-alignment-2026-11-02/checkpoint.json). Local/static development must still work without a production API.


Before creating another immutable delivery candidate or Docker context, compare available disk space with all planned copies plus operating-system/runtime headroom. If space is insufficient, stop that copy before filling the volume; preserve originals, authored work, final candidates, backup/rollback and historical evidence. Remove only clearly identified disposable task-generated intermediates. Do not hard-link a live preview candidate into another context: link-count changes modify ctime, and the strict preview correctly rejects changed file identity even when content hashes match. Create the context before starting its preview, use a separate copy with enough room, or a read-only archive stream. If Docker has already stopped, distinguish Desktop/VM recovery from application deployment, verify health and existing data hashes afterward, and record any actual API outage rather than call a static release fully healthy.
