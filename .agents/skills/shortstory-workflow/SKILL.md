# 숏스토리 작업 절차

1. [숏스토리 화면 설계](../../../DESIGN.md#숏스토리-작업-화면-개선-기준)에서 변경할 사용자 행동을 고른다. [원본과 내 그림책](../../../docs/architecture/four-work-shortstory.md)에서 진입·사본·작품별 쪽 위치의 기존 계약을 확인한다. UI 작업 전 실제 화면을 열고 클릭 전후에 작품 제목·현재 쪽·다음 행동이 어디에 나타나는지 확인한다.
2. [숏스토리 화면](../../../apps/web/app/shortstory/shortstory-workspace.tsx), [보관함](../../../apps/web/lib/shortstory-library.ts), [쪽 모델](../../../packages/compatibility/src/shortstory.ts)을 역할별로 확인한다. 화면 정리는 기존 모델로 먼저 구현한다. 저장·복구·화면 전환·온라인을 바꿀 때는 [저장 계약](../../../docs/architecture/authoring-storage-contract.md)을, 파일·시트 왕복을 바꿀 때는 [현재 양식](../../../docs/architecture/authoring-workbook-v2.md)을 확인한다. 읽기와 인쇄의 Web/CSS 범위는 [ADR 0009](../../../docs/decisions/0009-product-scope-shortstory-and-exports.md)를 따른다.
3. 정상 진입점에서 세로로 한 흐름을 끝낸다. 화면 전환에 앞서 현재 쪽과 작성 중인 입력을 보존한다. 원본에서 사본으로 넘어갈 때는 원본의 현재 쪽을 새 사본의 같은 순서에 대응시킨다. 원본과 사본의 쪽 ID는 서로 다르다. 원본에서 쓴 내용은 독립 사본에만 저장하고, 기존 개인 원고·표지·쪽 ID·Asset ID를 보존한다. 같은 사본을 다시 열거나 로그인에서 복귀할 때 새 사본을 만들지 않는다. 기존 계정·권한·온라인 기록은 화면 표시와 분리해 다룬다.

## 삽화 작업

- [화면 설계](../../../DESIGN.md#숏스토리-작업-화면-개선-기준)의 삽화 기준에 따라 자료 준비와 쪽 편집을 함께 확인한다. 화면에서 기존 삽화를 배경 목록 안에 노출하는 것만으로 삽화 중심 편집을 완성했다고 판정하지 않는다.
- 자료를 추가할 때는 [자산 작업 스킬](../asset-pipeline/SKILL.md)을 따른다. 원작·놀스토리 장면 삽화와 자유 창작용 삽화의 쓰임을 구분해 살피고, 같은 장면의 변형 수보다 여러 이야기에서 쓸 수 있는 장소·상황·행동의 폭을 확인한다. 자유 창작용 자료에는 기존 줄거리의 사건과 독립된 활동·문제·발견이 그림에서 드러나야 한다. 기존 장면의 배경이나 자세를 바꾼 수량만으로 이 조건을 충족했다고 판단하지 않는다. 전체 자료의 사건 유형을 대조해 실수·경쟁·갈등·협력·탐험·발견 등으로 새 흐름을 만들 수 있는지 확인한다. 수상한 단서·기이한 현상·신기한 발견도 사건 유형의 일부다. 장면의 행동과 문제를 그림에서 확인하고, 제목으로 사용자가 쓸 원인과 결말을 좁히지 않는다. 기존 파일의 배경·인물 조합과 자산 참조를 조용히 치환하지 않는다.
- 기존 인물이 나오는 삽화를 새로 준비할 때는 해당 인물의 실제 놀스토리 기준 이미지와 관련 변형을 먼저 확인한다. 완성한 삽화를 기준 이미지 및 같은 인물이 나오는 다른 쪽과 나란히 보고, 다른 인물로 보이거나 서로 바뀌지 않았는지 확인한다. 새 인물이 반복 등장하면 이후 삽화에서 재사용할 대표 이미지와 식별 요소를 남긴다.
- 사건의 후속 삽화를 만들 때는 원래 사건과 직전 장면을 함께 참조한다. 인물·복식·장소·날씨·주요 소품의 상태를 이어가고, 고장·분실·수리 같은 사건의 변화가 장면 사이에서 설명되는지 확인한다. 원사건 ID와 연속 순서를 자료에 기록하고, 같은 사건 검색으로 묶여 나오는지 확인한다.
- 원작 장면 삽화와 별도의 창작용 삽화를 한 검사용 그림책에 섞어 배치한다. 쪽 순서를 바꾼 뒤 삽화와 글이 함께 이동하고, 읽기·보관 후 재열기·작품 파일 왕복에서 같은 결과가 보이는지 확인한다.

## 변경 범위별 검증

저장 데이터를 쓰는 검사는 독립 브라우저 컨텍스트와 검사용 그림책으로 실행한다. 실제 화면 점검에는 프로젝트 브라우저 지침에 따라 ego-browser를 사용하고, 반복 검사는 해당 E2E를 재사용한다. 변경의 완료 조건을 먼저 회귀 검사에 추가하고, 현재 동작에서 실패하는 이유를 확인한 뒤 구현한다. 아래에서 변경에 영향을 받는 흐름을 선택한다.

| 변경 범위 | 실제로 확인할 결과 | 회귀 검사 출발점 |
|---|---|---|
| 서재·읽기·사본 진입 | 제공 원본에서 다른 쪽으로 이동하고 내 사본으로 쓴다. 원본에서 보던 쪽의 제목과 본문이 열리고, 사본의 작품 제목이 표시되며, 글 입력에 바로 접근한다. 저장 후 서재 복귀와 새로고침에서 같은 사본과 수정 내용이 남고 원본은 그대로 읽힌다. | [원본·쪽 위치](../../../tests/e2e/four-work-shortstory.spec.ts) |
| 편집·보관 | 그림과 한글 본문을 바꾸고 쪽을 이동하거나 복제한다. 읽기 전환, 재열기, 작품 파일 왕복 후 결과와 순서를 비교한다. 저장 실패나 충돌에서는 초안을 파일로 보관할 수 있는지 확인한다. | [숏스토리 편집](../../../tests/e2e/shortstory.spec.ts), [저장 충돌](../../../tests/e2e/shortstory-conflict.spec.ts) |
| 계정·온라인 | 인증 전후 활성 책·쪽·읽기/쓰기를 확인한다. 기기 보관과 온라인 상태를 구분하고, 실패·다시 시도·사본 열기에서 기록이 중복되거나 덮어쓰이지 않는지 확인한다. 모의 계정과 실제 서비스 결과를 구분해 기록한다. | [숏스토리 온라인](../../../tests/e2e/shortstory-online.spec.ts) |
| A4 | 표지·본문·마지막 인사의 순서, 긴 한글 글, 이미지, 빈 쪽 여부를 인쇄 미리보기나 PDF에서 확인한다. 화면의 인쇄 DOM, PDF 결과, 실물 출력의 증거를 따로 적는다. | [외부 출력](../../../tests/e2e/external-shortstory-print.spec.ts) |

화면을 바꿨다면 데스크톱과 좁은 세로·짧은 가로에서 첫 행동, 글과 그림, 키보드 초점 및 팝업 닫기 후 복귀를 확인한다. 완료 기록에는 검사한 환경, 직접 확인한 동작, 남은 범위를 적는다. 현재 변경에 영향을 받지 않은 검증은 기존 기록을 참조한다.
