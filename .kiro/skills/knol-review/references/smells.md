# 기본 냄새 목록 (Fowler, Refactoring 3장)

저장소 기준이 우선한다. 저장소 문서가 허용한 것은 표시하지 않는다. 모두 판단 사항이며 위반이 아니다. 도구(ESLint, tsc)가 이미 잡는 것은 건너뛴다. 이 저장소 코드는 한 줄에 여러 문장을 잇는 압축 형식을 많이 쓴다. 그 형식 자체는 냄새가 아니다.

각 항목은 *무엇인가* → *어떻게 고치나*.

- **알 수 없는 이름**: 하는 일이나 담은 것을 드러내지 않는 함수·변수·타입. → 이름을 바꾼다. 정직한 이름이 안 떠오르면 설계가 흐린 것이다. 도메인 이름은 제품 용어 기준과 계약 문서의 말을 따른다.
- **중복 코드**: 같은 논리 모양이 변경 안의 여러 곳에 있다. → 공통 모양을 뽑아 양쪽에서 부른다.
- **기능 욕심**: 자기 데이터보다 다른 객체의 데이터를 더 만지는 함수. → 그 데이터가 있는 쪽으로 옮긴다. 예: 작품 해석을 Web에서 하면 Runtime Core로.
- **데이터 뭉치**: 같은 몇 필드나 인자가 늘 함께 다닌다. → 하나의 타입으로 묶는다.
- **기본형 집착**: 도메인 개념을 문자열·숫자로 대신한다. → 작은 타입을 준다. 예: Asset ID, 컷 ID, 밀리초 시간.
- **반복되는 분기**: 같은 종류에 대한 같은 switch·if 사슬이 여러 곳에 있다. → 다형성이나 공유 표 하나로.
- **산탄총 수술**: 논리 변경 하나가 여러 파일의 흩어진 수정을 부른다. → 함께 바뀌는 것을 한 모듈로 모은다.
- **여러 이유의 변경**: 한 파일이 서로 무관한 이유로 고쳐진다. → 모듈마다 바뀌는 이유가 하나가 되게 나눈다.
- **추측성 일반화**: 요구에 없는 추상화·인자·hook. → 지우고 실제 필요가 생길 때까지 되돌린다.
- **메시지 사슬**: 호출자가 알 필요 없는 긴 `a.b().c().d()` 탐색. → 첫 객체의 메서드 하나 뒤로 숨긴다.
- **중개자**: 거의 위임만 하는 클래스나 함수. → 없애고 실제 대상을 직접 부른다.
- **거부된 유산**: 물려받은 것 대부분을 무시하거나 덮어쓰는 하위 구현. → 상속 대신 조합.
