# ADR 0017 — 작품 점수와 누적 선택 저작

Status: Accepted for current authoring scope (2026-10-10).

## 결정

작가가 정의하는 정수 점수, 선택 효과, 선택 표시 조건, 순서 있는 조건 경로를 StoryDocument에 포함한다. 공통 도메인 검증과 Runtime Core가 조건·누적·복원 의미를 소유하고 Web 편집기와 한글 Excel/Google 시트는 같은 데이터를 편집한다. 신뢰·용기·욕심은 선택 가능한 창작 예시이며 학생 성적 체계나 운영 정책으로 연결하지 않는다.

- StoryDocument schema6으로 새 의미를 구분한다. 이전 Next 문서1–5의 점수 없는 내용은 명시적으로 올리고, 구버전 선언으로 점수 필드를 우회하지 못하게 한다.
- workbook3에 점수 항목·선택 점수·점수 조건·조건 경로와 부모 있음 flag를 추가한다. 이전 workbook2는 해당 새 필드가 없는 이전 사양일 때만 변환한다. archive2/API payload1 포장은 바꾸지 않는다.
- 누적 점수는 컷 경로와 실제 선택 ID 기록에서 재계산한다. 따로 저장한 점수 합계를 콘텐츠 SSOT나 독립 읽기 상태 기준으로 삼지 않는다. 뒤로·재선택·재시작·복원에도 같은 검증을 적용한다.
- Ren’Py는 Core가 만든 표시 가능한 선택·결정된 장면을 받는다. `.rpy`를 저작 파일로 바꾸거나 두 번째 Web 플레이어를 만들지 않는다.
- 조건 경로는 첫 만족 우선, 모두 실패하면 기존 기본 도착이다. 종료/미연결은 구분하며 잠긴 선택 전부가 실패하면 대기와 수정 안내를 제공한다.
- 정수 범위·항목 수·효과 수·조건 수·경로 수를 제한한다. 임의 코드를 실행하지 않는다. ShortStory 문서/인쇄에는 게임 점수를 넣지 않는다.

## 이유와 한계

같은 합류 컷에 도착한 서로 다른 선택 이력을 구분해야 누적 선택이 뒤의 줄거리와 결말에 영향을 준다. 안정적인 ID와 명시적인 표 행은 이름을 바꿔도 관계를 유지하며 Excel·시트·파일·향후 JSONB에서 같은 창작 규칙을 사용하게 한다.

중첩 조건·boolean 플래그·항목별 min/max·표시 정책은 현재 범위 밖이다. 실제 서버/DB·학급 정책은 이 결정으로 확정하지 않는다. [계약과 작성 방법](../architecture/score-narrative-contract.md), [검증/후속 계획](../architecture/score-narrative-development-plan.md).

이 ADR은 [0016](0016-authoring-format-contract-and-scope.md)의 당시 workbook2/문서5 버전 설명을 이번 확장 범위에서 대체한다. 콘텐츠 SSOT·현재 Next 보호·legacy codec 제외·운영 정책 구분은 유지한다. 과거 감사와 manifest는 당시 범위의 기록으로 보존한다.
