# 이야기 연결과 갈래 구조 — 2026-11-25

작가가 지금 쓰는 컷이 어느 갈래에 있는지, 독자가 앞에서 어떤 선택을 할 수 있고 다음에 어디로 가는지 확인하면서 원고를 계속 편집하게 한다. 규칙은 [DESIGN.md · 이야기 연결과 갈래 구조](../../DESIGN.md)가 소유한다.

## 바꾸기 전에 막히던 편집 동작

- ‘현재 컷 연결 살펴보기’는 `선택지·분기조건 편집`을 켜야 보이는 상세 칸 안의 모달이었다. 컷을 누르면 닫혀서 연결을 펼쳐 둔 채 쓸 수 없었다.
- 폰에는 ‘이야기 지도 보기’가 없었다(설정 → 분기조건 편집을 켜야 전체 흐름).
- 흐름 지도는 컷마다 카드를 가로로 그렸다. 8컷 예시도 1,157px(390px 화면에서 346px만 보임)이고, 카드마다 ‘1장 · 2컷에서 ‘…’를 선택하면 → …’가 반복됐다. 안내는 ‘위에서 아래로’, 실제는 왼쪽→오른쪽이었다. 80컷이 넘거나 검색하면 그림이 사라졌고, 다시 열면 처음 위치로 돌아갔다.

## 바뀐 사용자 동선

1. 갈래 있는 작품의 쓰기 화면에서 `이야기 연결`을 편다(넓은 화면 왼쪽 옆 칸, 태블릿 세로·폰은 현재 컷 아래). 위에서 아래로 `1장 2컷 갈림길 · ‘숲으로 들어간다’ 고르면 · 1장 2컷에서 1컷 지나 여기로` → `지금 · 3장 1컷 · 갈림길 · 2갈래가 만나는 곳` → `A. ‘선녀를 돕는다’ → 4장A 1컷 · … · 이야기 끝` / `C. ‘되돌아간다’ · 용기 1점 이상일 때만 · 도착 컷을 정해 주세요`.
2. 길을 누르면 그 컷으로 옮겨 글상자에 초점이 가고, 영역은 펼친 채 새 컷 기준으로 바뀐다. `← 방금 보던 컷`, 접힌 `내 편집 이동 경로`로 되돌아간다. 펼침 상태는 작품별 편집 UI 설정이라 새로고침해도 남는다.
3. `전체 지도`는 갈래 구조를 먼저 보인다. 순서대로 이어지는 컷은 `2장A 1~2컷 · 2컷`으로 묶이고, 길마다 `● 3장 1컷에서 다시 만나요`, `■ … · 이야기 끝`, `도착 컷을 정해 주세요 · 이 컷에서 수정` 중 어디서 끝나는지 말한다. `현재 컷으로`, 다시 열면 보던 위치, 검색 결과의 갈래 문맥(`◆ 21장 1컷에서 B. “당신이 떠날까 봐 겁이 나오.” 길 · 5번째 컷`)이 있다.

## A2UI 반영

- 이야기 연결: `connectionsSurface`(editor-surfaces.ts) — `More` → `Column` → `Fork`(`PathChoice`·`Notice`+`Button`)·접힌 `More`·`ToolGroup`. 카탈로그 부품만 쓰며 `validateSurface`로 허용 부모·요약 길이·같은 일 중복을 검사한다(처음 구성이 `Fork`를 `More`에 바로 넣어 검사기에 걸렸고, `Column`을 사이에 두어 고쳤다). 같은 컷으로 가는 다른 선택은 이벤트 문맥의 길 id로 구분한다.
- 쓰기 설계도(`packages/ui/src/a2ui/screens/basic.json`)의 `context`에 `connections`를 넣고 ‘이야기 지도 보기’를 그 안의 `전체 지도`로 옮겼다. 설계도 비교 검사가 실제 화면과 맞춘다.
- 렌더러: 화면 줄로 그리는 `Notice`에 `actions`가 있으면 글 옆에 단추를 둔다(‘연결 정하기’).
- 흐름 지도의 갈래 구조: 카탈로그 사용자 정의 컴포넌트 `StoryStructure`(`x-host`, `currentLineId`·`grouped`), `structureSurface`가 이름 있는 구역에 두고 지도가 구현을 등록한다.

## 계약 유지

연결 정보는 Runtime Core의 `analyzeStoryFlow`·`findUpstreamBranches`를 읽기만 한다(`lib/story-connection-trail.ts`, `lib/story-structure-map.ts`). 선택지 기본 도착·순서 진행·점수 조건·기본 경로·도착 미지정(`''`)·이야기 끝(`null`)을 그대로 구분하고, 같은 도착이라도 선택·조건을 합치지 않는다. 독자의 실제 선택·점수를 가정하지 않는다. 컷 이동은 작업 공간의 `selectCut`(임시 보관·한글 조합 보호)을 쓴다.

### 함께 고친 실패

- `reading-surface` ‘native reader keeps bottom dialogue and compact reading tools’(1280·820·844 실패, 이번 변경 전에도 같은 값으로 실패): 원인은 검사 기준이었다. Ren'Py 대사 상자는 본문 아래에 쪽 넘김 줄(25)과 읽기 도구 줄(44, 손가락 크기)을 둔다. 무대가 화면을 채워 1:1로 그려지면 ‘본문 아래 +20px부터 무대 끝’이 57px이 되어 50px 기준을 넘는다(좁은 화면은 축소되어 통과). 화면은 정상이어서(대사 상자가 장면 아래 끝에 붙고 도구가 본문 바로 아래 상자 안에 있음) 검사를 보이는 대로 바꿨다: 대사 상자가 장면 아래 끝에 붙는지, 읽기 도구가 본문 아래 50px 안·장면 안에 있는지. 844×390은 R1(2026-11-24, 높이 500px 이하 가로 폰도 세 도구)에 맞춰 기대 도구를 고쳤다.

## 갈래 기준 장 번호 (사용자 후속 요청)

사용자 요청: ‘10장에서 a를 고르면 11a장, b를 고르면 11b장, 점수제면 11a·11b·11c’처럼 편집자가 헷갈리지 않게 장 번호를 체계화한다.

- 규칙(`packages/story-domain/src/legacy/chapter-branch-numbering.ts`): 번호 = 읽는 단계(되돌아가는 고리 제외, 가장 긴 길), 글자 = 앞 갈림길에서 고른 길의 순서(선택지 순서, 점수 조건 순서·기본 경로 마지막), 갈래를 따라 물려받고 갈래 안의 갈래는 글자를 잇고(13장AA), 길이 만나는 장은 공통 글자만 남긴다. 같은 이름이 생기는 드문 경우 글자 하나를 더 붙인다.
- 적용: 제공 작품(`connectCatalogChapterIdentity`)과 편집기의 ‘읽는 순서로 장 정리’(`chapterArrangement`, 장 번호와 갈래 글자 다시 매기기). 용어 안내와 장 지도 안내 문구도 같은 뜻으로 고쳤다.
- 제공 작품 비교(218장): 150장의 이름이 바뀌었다. 흥부는 그대로, 별주부는 6장 이후가 6장B·7장BA·7장BB(5장에서 B를 고른 뒤의 갈래), 선녀와 나무꾼은 13장A·B·C·D → 13장AA·AB·BA·BB, 25장A~J → 25장AABB·ABBA·…처럼 어느 갈림길의 어느 선택에서 왔는지 읽힌다(글자 최대 4개, 6장).
- 저장 순서·컷·연결·선택 ID는 바꾸지 않는다. 사용자가 아직 없어 이전 번호의 제공 보관본을 맞추는 호환 처리는 두지 않았다.

## 남은 범위
