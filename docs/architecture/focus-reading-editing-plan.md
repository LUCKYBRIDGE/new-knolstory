# 읽기·편집 집중 화면 분석과 개선 계획 (2026-11-22)

사용자 요청: 읽기와 편집 화면에서 지금 읽고 쓰는 것에 더 집중할 수 있어야 한다. 필요하면 탭을 더하는 것도 방법이다. 병합·배포가 아니라 더 나은 발전을 위한 분석과 계획을 원한다.

근거 자료: `docs/architecture/evidence/focus-plan-2026-11-22/measure.tsv`(측정값). 캡처(`*.jpg`)는 저장소 규칙상 커밋하지 않고 같은 폴더에 로컬로만 둔다. 측정은 별주부전 기본 작품을 폰 390×844, 태블릿 820×1180, 데스크톱 1440×900에서 연 첫 화면 기준이다.

## 1. 지금 상태 (측정)

| 화면 | 기기 | 첫 화면 조작 요소 | 상시 안내 문구 | 작품이 차지하는 면적 |
| --- | --- | --- | --- | --- |
| 놀스토리 읽기(플레이) | 폰 / 태블릿 / 데스크톱 | 5 / 8 / 8 | 2 | 82% / 81% / 90% |
| 놀스토리 편집 | 폰 | 26 | 3 | 52% |
| 놀스토리 편집 | 태블릿 | 43 | 14 | 38% |
| 놀스토리 편집 | 데스크톱 | 55 | 30 | 29% |
| 그림책 읽기 | 폰 / 태블릿 / 데스크톱 | 18 / 20 / 18 | 7–10 | 49% / 29% / 45% |
| 그림책 쓰기 | 폰 / 태블릿 / 데스크톱 | 25 / 34 / 33 | 5–10 | 43% / 47% / 44% |

‘작품이 차지하는 면적’은 무대(미리보기)·글상자·읽는 쪽 카드가 첫 화면에서 덮는 비율이다.

**결론**: 놀스토리 *읽기*는 이미 몰입형이다(화면 80–90%가 작품, 조작 5–8개). 문제는 **편집 화면(특히 태블릿·데스크톱)**과 **그림책 읽기**다. 편집은 화면이 클수록 도구·안내가 더 늘어나 작품 비율이 떨어진다(폰 52% → 데스크톱 29%).

## 2. 문제 분석

### 2-1. 놀스토리 편집: 모든 것이 한 화면에 동시에 있다
데스크톱 첫 화면(`editor-desktop.jpg`)에 동시에 보이는 것:
- 왼쪽: 이야기의 시작 안내, 이야기 지도 보기, 이 장의 컷 목록(17개 이상).
- 가운데: 무대 미리보기, 현재 컷(화자·연결된 이미지·종류·재생), 글상자 글, 컷 배경, 인물·자료 미리보기.
- 오른쪽: 다음 컷 미리보기, 이 컷 뒤에 새 컷 넣기, 여기서 이야기 나누기, 현재 컷 메모, 메모 추가, 창작 메모 보기.
- 아래·위: ‘현재 컷 상세·메모·정리’, 상단 안내 줄.

‘쓰기’라는 핵심 작업의 글상자는 화면 높이의 약 14%다. 쓰는 동안 필요 없는 컷 목록·메모·다음 컷이 같은 무게로 눈에 들어온다.

### 2-2. 작업 종류(탭)가 이미 있는데 ‘설정’ 서랍에 숨어 있다
코드에는 작업 화면 구분이 이미 있다(`EditingScreen`: 기본편집·글 편집·배경 편집·인물 편집·음향 편집·연출 편집·음향·연출 함께). 하지만 이 전환은 ‘설정’ 서랍(`editor-desktop-menu.jpg`) 안에 있고, 같은 서랍에 성격이 다른 것들이 섞여 있다.
- 구조 바꾸기(컷 추가, 장 추가, 장 순서)
- 편집 화면 전환
- 화면 배치(자동·가로·세로)와 보기 설정
- 작품 설정(정보·표지, 이야기 기획, 창작 메모)
- 파일·저장(저장, 다른 이름, 가져오기, 교환·보관, 이전 원고)
- 나가기(전체 화면, 저장하고 서재로)

학생은 ‘지금 무엇을 하는 중인지’를 화면에서 알 수 없고, 다른 작업으로 가려면 ‘설정’을 열어야 한다. 인물·음향·연출은 ‘편집 설정’에서 먼저 켜야 나타나서 더 찾기 어렵다.

### 2-3. 안내 문구가 상시 노출된다
데스크톱 편집 첫 화면에 12자 넘는 안내가 30개다(예: ‘움직임과 소리는 재생으로 확인해요…’, ‘이전·다음 컷은 원고 순서예요.’, ‘썸네일로 이미지 찾기’). 처음에는 도움이 되지만, 계속 쓰는 사람에게는 소음이다.

### 2-4. 그림책 읽기: 읽기 화면인데 작품이 화면의 29–49%
태블릿(`picturebook-read-tablet.jpg`) 기준:
- 머리 영역(서재로 링크, 작은 제목, 제목, 설명, 버튼 3개)이 약 220px.
- 왼쪽 220px 칸에는 ‘전체 구성’ 접힌 상자 하나만 있고 나머지는 비어 있다.
- 그림은 카드 폭의 일부라 태블릿에서도 작다.
- 아래에 책 카드와 ‘작품 도구’가 이어진다.
읽기는 놀스토리 플레이처럼 ‘그림 + 글 + 쪽 넘김’만 크게 있으면 된다.

### 2-5. 기기별로 같은 기능의 자리가 다르다
- 폰 편집: 그림책 구상·컷 목록이 아래 접힘으로 간다.
- 태블릿: 다음 컷·새 컷 넣기·컷 목록이 무대 아래에 늘어선다.
- 데스크톱: 3단으로 펼쳐진다.
기기를 바꾸면(교실 태블릿 ↔ 집 PC) 같은 기능을 다시 찾아야 한다.

## 3. 개선 원칙

1. **한 번에 한 작업**: 화면은 지금 작업(읽기, 쓰기, 장면, 소리, 연출, 흐름)에 필요한 것만 보여 준다. 작업 전환은 늘 보이는 **작업 탭**으로 한다.
2. **작품이 주인공**: 읽기 화면은 작품 70% 이상, 편집 화면은 작품(무대+글) 50% 이상. 상단은 한 줄, 조작 6개 이하.
3. **설정은 설정만**: 작업 전환·작품 정보·파일은 ‘설정’ 서랍에서 꺼내 제자리에 둔다.
4. **안내는 필요할 때만**: 상시 문구는 첫 사용 안내(한 번 보고 닫기)나 ‘?’로 옮긴다. 실제 상태 알림(저장 실패 등)만 상시로 남긴다.
5. **기기마다 같은 구조**: 탭 순서와 이름은 폰·태블릿·데스크톱이 같다. 화면 크기에 따라 달라지는 것은 ‘옆에 펼칠지, 아래 접을지’뿐이다.
6. **과제 범위와 같은 단위**: 탭은 과제 편집 범위(그림·인물 배치·음향·연출·선택지)와 같은 단위로 나눈다. 막힌 범위의 탭은 아예 보이지 않는다(지금 규칙 유지).

## 4. 제안: 작업 탭 구조

### 4-1. 놀스토리 편집 — 작업 탭

상단 한 줄: `‹ 서재` · 작품 제목 · 장·컷 이동 · `재생` · `저장 상태` · `⋯`(설정)
그 아래 작업 탭:

| 탭 | 보이는 것 | 지금 어디에 있나 | 과제 범위 |
| --- | --- | --- | --- |
| **쓰기** (기본) | 무대 작게(또는 접기) + 큰 글상자 + 화자·종류. 이전/다음 컷 한 줄. 그림책 구상(있을 때) 옆 칸 | 기본편집·글 편집 | 늘 있음 |
| **장면** | 무대 크게 + 배경 고르기 + 인물 배치 | 배경 편집·인물 편집 | 그림 고르기·인물 배치 |
| **소리** | 음향 타임라인 | 음향 편집 | 음향 |
| **연출** | 효과·전환 | 연출 편집 | 연출 |
| **흐름** | 이야기 지도, 선택지·점수, 장 순서 | 이야기 지도 보기·선택지 편집·장 순서 | 선택지·점수 |
| **원고** | 이 장의 컷 목록을 원고처럼 이어 보기·고치기, 창작 메모 | 컷 목록·메모·연결 요약 | 늘 있음 |

‘설정(⋯)’에는 작품 정보·표지, 이야기 기획, 파일·저장, 화면 배치, 보기 설정만 남긴다.

- ‘쓰기’ 탭은 글을 쓰는 사람의 화면이다. 데스크톱에서도 글상자가 화면 높이의 35% 이상이 되도록 무대를 작게 두고, ‘무대 크게 보기’로 잠깐 키운다.
- ‘원고’ 탭은 지금 왼쪽 컷 목록·메모를 한 곳으로 모은 것이다. 긴 글을 고칠 때는 컷 단위보다 이어진 원고로 보는 편이 낫다.
- 지금 `EditingScreen` 값과 과제 범위(`EditScope`) 검사를 그대로 쓰므로 데이터 구조는 바꾸지 않는다.

### 4-2. 그림책 — 읽기와 쓰기

**읽기**: 몰입형으로 바꾼다.
- 상단 얇은 줄: `‹ 서재` · 제목 · `3 / 8` · `목차` · `⋯`.
- 그림을 화면 폭 가득, 글은 그 아래 큰 글씨, 쪽 넘김은 화면 양쪽 탭·스와이프·←→.
- 책 정보·A4·사본 만들기·보관함은 `⋯` 또는 마지막 쪽 뒤 ‘책 정보’ 쪽으로.
- 목표: 작품 면적 70% 이상(지금 29–49%).

**쓰기** 작업 탭: `쓰기`(쪽 제목·글) · `그림`(삽화·배경·인물) · `쪽`(추가·순서·삭제) · `책`(정보·표지·저장·인쇄). 지금 ‘작품 도구’와 ‘쪽 추가·순서·삭제’로 접어 둔 것을 탭으로 정식화한 것이다.

### 4-3. 놀스토리 읽기
이미 몰입형이라 구조는 유지한다. 손볼 점:
- 책 소개 화면에서 읽기를 시작하면 첫 장면 전에 ‘무대 준비’ 화면을 거친다. 이번 측정은 준비 시간을 재지 않았으므로, 기기별 준비 시간을 따로 재고 필요하면 줄인다.

### 4-4. 공통
- **집중 모드**: 편집에서도 `전체 화면`이 상단·탭을 자동으로 숨기고, 화면 가장자리로 다시 부른다.
- **첫 사용 안내**: 상시 안내 문구를 탭별 ‘처음 한 번’ 안내로 옮긴다. ‘?’를 누르면 다시 볼 수 있다.

## 5. 단계별 계획

각 단계는 따로 병합·배포할 수 있는 크기다. **단계는 정해진 순서가 아니라 방향이다.** 해 보면서 알게 된 것(측정값, 실제 사용 모습, 다른 작업과의 겹침)에 따라 순서를 바꾸거나, 두 단계를 합치거나, 필요 없어진 단계는 건너뛴다. 바꿀 때는 이유를 이 문서의 ‘진행 기록’에 남긴다.

| 단계 | 내용 | 목표(측정) | 위험·대응 |
| --- | --- | --- | --- |
| **1. 그림책 몰입 읽기** | 4-2 읽기. 얇은 상단, 그림 전폭, 목차 서랍, 스와이프 | 작품 면적 70% 이상, 조작 8개 이하 | 범위가 작고 독립적이다. 먼저 해서 ‘몰입 화면’ 기준을 정한다 |
| **2. 편집 작업 탭 골격** | 4-1의 탭 줄을 만들고 기존 `EditingScreen` 전환을 탭으로 옮긴다. 설정 서랍에서 작업 전환 제거 | 작업 전환까지 1번 탭. 설정 서랍 항목 절반 이하 | e2e가 ‘설정 → 편집화면’ 경로를 많이 쓴다 → 도우미 함수 하나로 바꿔 한 번에 고친다 |
| **3. 쓰기 탭 정리** | 쓰기 탭에서 컷 목록·메모·다음 컷을 ‘원고’ 탭으로 옮기고 글상자를 키운다 | 데스크톱 작품 면적 50% 이상, 조작 25개 이하 | 다른 세션이 `story-editing-workbench`를 고치는 중이라 그 작업과 순서를 맞춘다 |
| **4. 원고·흐름 탭** | 컷 목록을 원고 보기로, 이야기 지도·선택지·장 순서를 흐름 탭으로 | 긴 글 고치기에서 화면 이동 횟수 감소 | 분기 작품의 원고 순서 표시 규칙을 정해야 한다 |
| **5. 안내 정리·집중 모드** | 상시 안내를 첫 사용 안내로, 전체 화면 집중 모드 | 상시 안내 문구 10개 이하(데스크톱) | 처음 쓰는 학생이 길을 잃지 않는지 교실 관찰로 확인 |
| **6. 그림책 쓰기 탭** | 4-2 쓰기 탭 | 그림책 쓰기 조작 20개 이하 | 1단계와 같은 상단 규칙 사용 |

모든 단계 공통 검증: 이 문서의 측정 스크립트로 전후 수치 비교, 폰·태블릿·데스크톱 캡처, 과제 범위별(글만·글과 그림·모든 편집) 탭 노출 확인, 기존 e2e.

## 6. 결정이 필요한 것

1. **편집 탭 이름과 개수**: 쓰기·장면·소리·연출·흐름·원고(6개)로 할지, 처음엔 쓰기·장면·흐름 3개로 시작하고 소리·연출은 켰을 때만 보일지.
2. **무대와 글상자의 비중**: ‘쓰기’ 탭에서 무대를 기본으로 작게 둘지(글 중심), 지금처럼 크게 둘지(장면 중심).
3. **그림책 읽기의 쪽 넘김**: 스와이프·양쪽 탭을 넣을지, 지금처럼 버튼만 둘지.
4. **진행 순서**: 1단계(그림책 몰입 읽기)부터 할지, 2단계(편집 작업 탭)부터 할지.

## 7. 진행 기록

- 2026-11-22 · 1단계(그림책 몰입 읽기) 구현(#74). 쪽 영역 비율: 태블릿 29→49%, 데스크톱 45→63%, 가로 태블릿 74%. 폰은 상단 버튼 줄이 두 줄이라 47%로 그대로였고, 세로 화면은 16:9 그림과 글이 화면보다 짧아 70% 목표가 맞지 않았다. 목표를 ‘그림·글·쪽 넘김이 첫 화면에 함께 보인다’로 바꿨고, 네 화면 모두 충족했다.
- 2026-11-22 · 2단계 착수 전 확인: 편집기는 폰 세로·가로, 태블릿, 데스크톱마다 배치 규칙이 따로 있어 탭 줄 하나가 모든 배치에 영향을 준다. 기존 작업 화면 전환(`EditingScreen`)을 그대로 쓰고, 편집기 본체 파일 대신 작업 공간 쪽에 탭 줄을 두는 방법부터 시험한다.
