# 컷 종료 범위 저작 계약 — 진행 중

2026-10-11. 승인 도안의 종료 컷 편집을 실제 저작·Core·저장에 연결한다. 전체 이미지 도안 구현 목표는 계속 진행 중이며 이 문서는 첫 연결의 범위와 남은 작업을 구분한다.

## 현재 구현

효과음 일괄 추가는 명시적으로 선택한 컷마다 새 cue ID로 추가하고, 이번 cue만 제거하는 undo로 연결했다. 연속 소리 구간과 구분한다. [검증](sound-batch-validation.md). 갈래 한정 실행 범위는 여전히 별도다.

추가: 컷의 배경음/주변 소리 play 시작점 이동도 선택 채널·종료점 보존과 충돌 거부/undo로 연결했다. [소리 시작점 검증](audio-start-move-validation.md). 장 기본 지시·갈래 한정/일괄 범위는 별도다.

2026-10-11 후속: 효과 하나의 시작 컷 이동·취소/되돌리기를 연결했다. 기존 종료점과 cue 설정은 유지하고 두 컷을 원자적으로 갱신한다. [계약·검증](effect-start-move-validation.md). 아래 첫 연결 기록의 ‘시작 컷 이동 미완료’는 당시 범위이며, 현재 소리 시작점·갈래 한정·일괄 적용은 계속 남아 있다.

StoryDocument7의 following 효과와 play 배경음/주변 소리에 선택적 `endLineId`가 있다. 효과의 시작은 효과를 저장한 컷이고, 컷 소리의 시작은 play 지시가 있는 컷이다. 장 기본 소리에 종료 컷이 있으면 해당 장에 실제 진입해 기본 소리를 적용한 시점부터 시작한다. 종료 컷까지 포함하고 다음 방문 컷 진입 전에 해당 항목만 종료한다. 효과 ID를 통해 다른 following 효과를 지우지 않으며 소리는 다음 컷의 새 play 지시가 우선한다. 범위 정보는 Core에서 해석·제거해 Ren’Py에는 재생/정지와 해석된 효과만 전달한다.

반복 방문은 시작 컷에 재진입하면 다시 시작한다. 현재 방식은 실제 경로에서 종료 컷에 처음 도착한 방문을 기준으로 끝난다. 분기가 종료 컷을 우회하면 효과/소리는 계속 유지된다. UI에 이 조건을 명시한다. **아직 특정 갈래/경로만 적용하는 선택과 범위 시작 컷 이동까지 완료한 것은 아니다.**

문서1–6은 7로 명시적 승격하며 이전 버전에 종료 컷 필드가 들어 있으면 거부한다. archive2/JSONB payload1은 유지한다. 없는 종료 ID는 문서 검증에서 거부해 원고를 보호한다. 표7은 효과/연속 소리 탭에 종료 컷 ID 일반 열을 추가한다. 기존 표2–6은 미설정 종료를 추가하고 기존 값을 보존한다. 이전 표에 미래 열이 있으나 모두 미설정인 경우 저작 값이 없으므로 허용하며, 실제 종료 값이 있으면 버전 오류다.

편집기는 효과·배경음·주변 소리에서 종료 컷을 고를 수 있다. 마지막 효과 변경 취소는 범위도 함께 되돌린다. 마지막 소리 변경 취소도 추가했으며 작품/컷 단위로 이전 값을 구분해 다른 컷에 복사하지 않는다.

## 종료 컷 삭제 보호 보완

2026-10-11. 삭제 확인창은 살아남을 컷/장 효과·배경음·주변 소리의 종료 참조를 먼저 집계하고 원본 장·컷/항목을 표시한다. 참조가 있으면 삭제 실행을 막고 해당 항목의 종료점을 다른 컷으로 바꾸도록 안내한다. Core도 같은 조건에서 명확한 오류로 거부한다. 종료 필드를 지워 무기한 유지로 바꾸거나 임의 앞뒤 컷으로 remap하지 않는다. 삭제할 컷 자신이 소유한 효과는 함께 없어지는 저작 항목이므로 삭제 차단 참조에서 제외한다. 메모의 의도적 미해결 링크는 기존 보존 계약을 유지한다.

명시 Flow 연결 수에는 goto의 기본 경로뿐 아니라 조건 경로도 포함한다. 기존 삭제는 Flow target을 연결 대기로 바꾸며 영향 수가 그 동작과 일치하도록 했다. 현재 버전·형식·실제 재생 의미는 바꾸지 않는다.

리뷰에서 삭제 후보 검증 전에 체크포인트가 저장되는 순서를 확인해 수정했다. Core 삭제 후보가 validation/종료 참조 보호를 통과한 뒤에만 삭제 전 복구 기록을 만들고 새 작품을 적용한다. 거부된 삭제로 복구 기록을 갱신하지 않는다.
