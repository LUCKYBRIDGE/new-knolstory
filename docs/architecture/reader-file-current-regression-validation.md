## 현재 파일 왕복

기존 기기 snapshot에 원래 private 자료와 전체 저작 내용을 둔다. 이는 신규 업로드 경로가 아니다. 현재 `.knolstory` 내보내기의 전체 project와 원래 두 resource의 bytes/base64/metadata/ID를 비교한다. 실제 Excel 반출을 새로 가져오려 하면 확인창 전에 거부하고 현재 전체 작품/resources를 유지해야 한다.

새 가져오기 검증은 명시적 등록 사본을 사용한다. 원래 private 음악/효과음 ID만 각 등록 음악/효과음 ID로 바꾸고 나머지 원고·Flow·StageComposition·자유 배치·메모·연출/오디오 속성을 보존한다. 현재 생성기로 문서8을 만들고 독립 사본 가져오기→Excel 왕복→공개 TSV 모의 응답→재열기를 전체 project 비교로 확인한다. 원본 artifact hash도 그대로다. 이 변환을 실제 사용자 작품에 자동 적용하지 않는다.

TSV는 제한 표이며 보존 행이 포함된 현재 문서를 사용한다. 모든 새 저작 필드의 정식 편집 양식은 워크북8이다. 모의 fetch 응답은 실제 Google 앱에서 편집/다운로드한 새 결과나 Excel 추가 기능 연결 검증이 아니다.

## 공개 시트의 진행 중 수정 보호

두 검사에서 금지 private 첨부 응답을 지연시키고 그동안 현재 글을 수정한다. 응답 완료가 새 확인창/IDB resource 기록/작품 덮어쓰기를 만들지 않아야 한다. 첨부 없는 현재 제한 표를 다시 요청한 뒤에도 응답 대기 중 최신 글과 전체 작품이 보존되어야 한다.

실제 확인창에서 취소→전체 원고 유지→재요청을 수행한다. 정상 경로는 독립 사본과 보관된 원작 전체를 비교하고, 저장 실패 경로는 확인창·오류·현재 글/전체 문서·취소/재열기를 유지한다. 다른 검사 블록은 수정 전과 동일하다.

## 실제 native 저장·읽기

세 native 검사는 기존 기기 자료의 실제 Ren’Py를 사용한다. portrait/desktop 비율을 명시적으로 선택하고 배경·인물 도구를 열어 원래1/2인물 조건을 확인한다. 저장/불러오기/지난기록은 현재 compact 이름과 슬롯 버튼을 사용한다. 다음 진행은 초점/Enter이며 선택 터치는 실제 choicesRect와 letterbox를 따른다. 선택 후 Core의 보관된 경로와 native revision 일치를 확인한다.

- 실제 지난기록은 방문한 갈래만 포함한다. 확인 후 선택 컷으로 되돌려 두 번째 갈래를 읽고 처음 저장한 슬롯을 불러온다. 재열기 후 저장 당시 문구·전체 작품/private 자료가 유지된다. resize/읽기 동선의 같은 iframe을 확인한다.
- 작품 수정 뒤 슬롯은 당시 저장한 글을 보여준다. 첫 불러오기 확인 후 변경 안내가 나오고 ‘변경된 작품에서 이어읽기’를 명시적으로 눌러야 현재 수정한 문장으로 복귀한다. 전체 project에서 해당 text/updatedAt만 달라야 한다.
- 번호가 붙은 갈래 장의 A/B 경로가 각각 자기 엔딩만 방문하고 합류 컷으로 이어진 뒤 종료한다. 각 실제 path에 반대 갈래가 없어야 하며 읽기 뒤 전체 문서와 원래 private 자료가 같다.
