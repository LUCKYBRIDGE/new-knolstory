# 편집 화면 이미지 도안 비교 v3

현재 편집 개편은 [DESIGN의 여섯 작업 화면](../../DESIGN.md#편집-작업-영역--2026-10-19-후속-설계)이 소유한다. 아래 후보 이미지는 당시 비교 이력이며 현재 구현으로 간주하지 않는다. [현재 화면 캡처](evidence/editing-workbench-2026-10-19/gallery.html).

2026-10-10. 사용자는 실제 배경·캐릭터로 여러 버전/여러 상황을 준비하고 나중에 종합해 구현하기로 했다. 현재 산출물은 도안 이미지와 비교 페이지다. 제품 편집기·Runtime Core·Ren’Py·저작/저장 계약은 변경하지 않는다.

공통 승인 방향은 [기존 도안 문서](editor-redesign-design.md), 현재 디자인 기준은 [DESIGN](../../DESIGN.md)이다. 종이색 글 상자·화자 이름표·한글 대사/행간을 유지한다. 그림은 원본 자산 bytes를 이미지 태그로 배치하며 새로 생성하거나 다시 그리지 않는다.

## 세 방향

| 안 | 기본 구성 | 추가 도구 | 비교할 점 |
|---|---|---|---|
| A 균형형 | 장면 아래 넉넉한 글 입력칸, 웹에서 좁은 컷 목록 | 웹/가로 태블릿은 옆 패널, 휴대폰/세로 태블릿은 아래 창 | 초보자가 글과 배치를 번갈아 하기 쉬운가, 장면/글의 중복 표시 부담 |
| B 장면 집중형 | 장면을 크게 보고 글 상자를 눌러 직접 수정 | 웹/태블릿은 장면 위 작은 편집 창, 휴대폰은 하단 창 | 배치 몰입감, 긴 글/키보드, 도구가 인물·글을 가리는 정도 |
| C 대본 집중형 | 웹/태블릿은 장면과 넓은 원고를 나란히, 앞뒤 컷 글 맥락 | 옆 패널/하단 창 | 긴 한국어 작성, 앞뒤 원고 구분, 장면 확인 공간 |

모든 안에서 글 입력·수정과 배경/캐릭터 배치가 기본이다. 연출·소리·선택지는 필요할 때 하나씩 연다. 현재 대본과 앞뒤 원고는 한 문서의 다른 표현이며 복제된 데이터 모델이 아니다. 기본 제공 작품의 원문·Asset ID·Flow·StageComposition을 재작성하지 않는다.

## 종합할 때의 판단 항목

1. 처음 열었을 때 글 입력과 배경/인물 조작이 바로 보이는가.
2. 글 수정↔배치↔추가 도구↔미리보기↔복귀에 반복 조작이 적은가.
3. 추가 도구를 닫아도 컷·원고·배치·선택·입력 초안이 유지되는가.
4. 한국어 긴 글, 입력기 조합, 키보드, 화면 회전에서 가독성을 확보하는가.
5. 도구가 장면을 가리는 안은 대상 인물/글과 부딪히지 않는가.
6. 자료 선택과 적용/취소가 구분되고 다른 설정을 건드리지 않는가.
7. 터치 조작 영역과 초점/스크롤/보조기술이 실제 구현에서 충분한가.

A의 기본 글 입력, B의 직접 글 상자 편집, C의 앞뒤 원고 확인 등 유용한 부분을 섞어 최종안으로 만들 수 있다. 지금 특정 안을 구현 기준으로 확정하지 않는다.

## 확인한 범위와 다음 단계

Chromium으로30개 PNG를 렌더하고 이미지/글꼴 로드와 페이지 가로 넘침을 확인했다. 대표 A/B/C·휴대폰·세로 태블릿·긴글/4인·자료 선택 화면을 직접 보고 도안의 겹침/잘림을 수정했다. 키보드는 시각 도안이며 OS 입력기 실측/동작 검증이 아니다. 미리보기·자료선택·분기·소리 버튼도 구성 예시이며 기능 구현 완료를 뜻하지 않는다.

도안 단계의 다음 검토는 긴 글 입력 시의 높이, 태블릿 세로 창, B의 대상 가림, C의 원고 집중도다. 최종 종합 후 실제 개편에서는 StoryDocument/원본 저장과 Core→Ren’Py 단일 재생 경계를 유지하고 UI 입력 overlay만 연결한다. 도안 HTML을 영구 Web Player로 사용하지 않는다.
