# 점수·선택 조건·조건 경로 저작 계약

기준일: 2026-10-10. 작품의 누적 선택을 표현하는 저작 기능이다. 학생 성적·과제 평가와 연결하지 않는다. 구현과 증거 판정은 [실행 계획](score-narrative-development-plan.md), 버전 결정은 [ADR0017](../decisions/0017-story-score-authoring.md)을 따른다.

## 작가가 정하는 점수

작품 메뉴 → 이야기 점수에서 **이름·뜻과 계산 기준·시작 점수**를 직접 정한다. 신뢰·용기·욕심은 선택 가능한 예시이며 작품에 자동 추가하지 않는다. 예를 들어 ‘신뢰’는 이웃을 돕거나 약속을 지키는 정도, ‘용기’는 위험을 감수하고 나서는 정도로 정의할 수 있다. 도덕적 정답이나 학생 평가 기준을 프로그램이 정하지 않는다. 이름을 바꿔도 연결은 점수 ID로 유지한다. 연결된 점수를 삭제하려면 먼저 이를 사용하는 선택 효과·조건을 수정해야 한다.

점수 항목은 최대32개다. ID는 공백뿐인 문자열을 허용하지 않으며200자 이하, 이름은80자 이하, 설명은2,000자 이하다. 시작 점수·효과 값·비교 값은 -1,000,000부터1,000,000까지 정수다. 누적 계산도 같은 범위를 벗어나면 진행을 거부한다. 소수·문자열 수식·임의 JS/Python 실행을 지원하지 않는다.

## 편집과 읽기의 연결

선택지마다 표시 조건과 점수 효과를 편집한다. 조건은 같은 묶음의 비교를 **모두 만족**하거나 **하나 이상 만족**해야 한다. 비교는 같음·다름·초과·이상·미만·이하다. 조건이 없으면 그 선택지는 항상 표시된다. 선택지 하나의 효과는 최대16개이며 작성한 순서대로 더하기 또는 설정을 적용한다. 더하기에 음수를 입력하면 감점이고, 설정은 기존 값 대신 지정 값으로 바꾼다.

다음 컷 지정 흐름에는 최대16개 조건 경로를 둔다. 위에서부터 검사해 처음 만족한 경로로 이동하고, 모두 실패하면 기존 기본 도착으로 이동한다. 같은 조건 묶음에는1–8개 비교를 둔다. 지정 컷·이야기 종료·아직 미연결의 의미를 유지한다. 미연결은 종료로 바꾸지 않는다. 선택지가 모두 잠기면 대기 상태와 조건 수정 안내를 표시하며 임의로 다른 경로를 선택하지 않는다.

예시 작품의 흐름:

| 선택/판단 | 설정 | 결과 |
|---|---|---|
| 이웃을 돕는다 | 신뢰에2 더하기 | 첫 선택 뒤 신뢰2 |
| 그냥 지나간다 | 신뢰를0으로 설정 | 첫 선택 뒤 신뢰0 |
| 음식을 나눈다 | 표시 조건 신뢰2 이상, 신뢰에2 더하기 | 앞선 도움을 선택해야 표시됨 |
| 음식을 혼자 보관한다 | 욕심에1 더하기 | 두 선택이 같은 합류 컷으로 가도 점수는 다름 |
| 합류 뒤 첫 조건 경로 | 신뢰4 이상과 욕심0 이하를 모두 만족 | 함께하는 결말 |
| 두 번째 조건 경로 | 신뢰2 이상 또는 욕심0 미만 중 하나 이상 만족 | 다시 만나는 결말 |
| 기본 경로 | 앞의 조건을 만족하지 않음 | 혼자 찾는 결말 |

이 수치는 예제의 창작 규칙이다. 작가는 점수 이름·효과·기준·도착 컷을 바꿔 자신의 작품을 만든다. 기본 경로를 함께 정하면 예상하지 않은 선택 조합도 의도한 결과로 처리할 수 있다.

Runtime Core는 실제 선택 ID 기록과 컷 경로를 재생해 현재 점수를 계산한다. Ren’Py에는 계산을 마친 장면과 표시 가능한 선택지만 전달한다. 독립 점수 합계를 파일에 덧붙여 두 개의 기준을 만들지 않는다. 뒤로·재선택·재시작은 이후 기록의 효과를 제거하고 다시 계산한다. 저장한 읽기 기록을 복원할 때도 선택 ID·당시 조건·도착 경로·범위를 검사한다. 필요한 선택 ID가 없거나 현재 작품의 조건과 맞지 않는 기록을 추측해서 복원하지 않는다. 중간 컷에서 시작하는 미리보기는 시작 점수를 사용하며 앞선 선택을 임의 생성하지 않는다. 읽기의 접힌 ‘이야기 점수 확인’으로 작가가 현재 값을 확인할 수 있다.

## Excel·Google 시트 작성

현재 다중 탭 workbook은 **v5**, 놀스토리40개 편집 탭과2개 안내 탭이다. 공통 [양식 안내](authoring-workbook-v2.md)의 한글 제목·메모·숨겨진 내부 키·미설정 규칙을 그대로 사용한다. 다음4개 탭이 추가된다.

| 탭 | 작성 내용 | 연결 |
|---|---|---|
| 점수 항목 | 점수 ID, 배열 순서, 점수 이름, 뜻과 계산 기준, 시작 점수 | 작품 정보의 점수 항목 있음 |
| 선택 점수 | 선택 컷 ID, 선택지 ID, 적용 순서, 점수 ID, 점수 처리, 적용 점수 | 선택지의 점수 변경 있음 |
| 점수 조건 | 컷 ID, 조건 위치, 선택지 또는 경로 ID, 조건 순서, 조건 묶음, 점수 ID, 비교 방법, 비교 점수 | 선택지 표시 조건 또는 조건 경로 |
| 조건 경로 | 판단 컷 ID, 경로 ID, 판단 순서, 도착 종류, 도착 컷 ID | 컷 흐름의 조건 경로 있음 |

1. ‘점수 항목’에 정의를 쓰고 ‘작품 정보’의 점수 항목 있음을 있음으로 둔다.
2. 선택 결과를 계산하려면 ‘선택지’의 점수 변경 있음을 있음으로 두고 ‘선택 점수’에 같은 컷/선택지 ID와 점수 ID를 쓴다. 점수 처리는 더하기/설정이다.
3. 선택지 표시를 제한하려면 ‘선택지’의 표시 조건 있음을 있음으로 두고 ‘점수 조건’의 조건 위치를 선택지 표시로 정한다. 조건 묶음은 같은 조건의 모든 행에서 동일하게 쓴다.
4. 합류 후 판단하려면 ‘컷 흐름’의 기본 도착과 조건 경로 있음을 정한다. ‘조건 경로’에 경로를 쓰고 ‘점수 조건’의 조건 위치를 조건 경로, 소유 ID를 해당 경로 ID로 쓴다.
5. 배열·적용·조건·판단 순서는0부터 시작하는 중복 없는 정수다. 전체 열을 옮길 때 숨겨진 둘째 행 key도 함께 이동한다. ID나 key를 임의 번역하지 않는다.
6. Excel에서 저장하거나 Google 시트에서 Microsoft Excel(.xlsx)로 다운로드한 뒤 앱의 가져오기 검증을 통과해 내 사본으로 적용한다. 탭·항목 오류가 나면 기존 작품은 유지하고 파일을 고쳐 재시도한다.

같은 선택을 조건부로 표시하고 점수를 변경하려면 ‘점수 조건’과 ‘선택 점수’에 각각 행을 둔다. 점수 정의 이름이나 설명만 바꿔도 기존 참조 ID는 유지한다. 빈 목록과 설정 부재도 있음 열로 구분하며, 자식 행만 쓰고 부모 있음 설정을 빠뜨리면 오류다. 실제 메모와 선택 목록은 exporter의 공통 사양에서 만들어진다.

## 파일·JSONB·이전 Next 보호

StoryDocument는 **schemaVersion6**이다. `project.scores`, 선택지의 `condition`/`effects`, 다음 컷 지정 흐름의 `routes`가 새 의미를 보관한다. 공식 `.knolstory`의 **formatVersion2**, API snapshot의 **payloadVersion1**은 그대로다. JSONB snapshot은 같은 검증 문서를 보관하고 복원하므로 새 점수 필드도 동일하게 보존한다. 실제 PostgreSQL 서버가 구축되었다는 뜻은 아니다. [저장 계약](authoring-storage-contract.md).

점수 필드가 없는 기존 Next 문서1–5는 schema6으로 명시적으로 읽는다. schema5 이하라고 표시하면서 점수 필드를 넣은 파일은 거부한다. 기존 workbook2는 새 점수 탭과 flag가 없는 이전 사양일 때만 v3으로 변환한다. ShortStory의 문서 모델은 변경하지 않으며 공통 workbook4 교환 규약만 사용한다. 숏스토리에 게임 점수·조건 진행을 추가하지 않는다. 기존 story-maker 파일 호환은 범위에 포함하지 않는다.

## 검증과 남은 범위

[예제 파일](evidence/score-narrative/score-story.knolstory), [Excel 편집 반출](evidence/score-narrative/score-excel-edited.xlsx), [Google 편집 반출](evidence/score-narrative/score-google-edited.xlsx)을 사용한다. 실제 두 외부 앱에서 신뢰의 설명·첫 선택 효과2→3·함께하는 결말 기준4→5를 수정했다. 변경한3개 값 외 모든 내용의 재반입 일치를 [계약 검사](evidence/score-narrative/external.log)로 확인했다. Web/Ren’Py 실행 및 최종 회귀 통과 결과는 [실행 계획](score-narrative-development-plan.md)에서 별도로 판정한다. 이전 형식 감사의 날짜·수치·manifest를 새 검증으로 덮어쓰지 않는다.

현재 지원은 정수 점수와 한 단계의 모두/하나 이상 비교다. boolean 플래그, 중첩 조건 묶음, 점수별 상한/하한·표시 정책, 임의 수식은 구현되지 않았다. 실제 기기·보조 기술 검증과 서버·학급 운영은 별도 후속 목표다.

시간 입력·한글 용어는 [현재 편집 계약](editor-terminology-and-time.md)을 따른다. 점수 확장 당시 workbook3은 같은 점수 규칙을 갖고 있었으며 현재4에서 시간 표시 단위만 초로 바뀌었다.
