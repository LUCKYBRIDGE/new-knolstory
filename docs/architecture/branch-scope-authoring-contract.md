# 실제 선택에 따른 연출·소리 조건

기준일2026-10-14, 여러 선택 결합 후속2026-10-22. [ADR0022](../decisions/0022-branch-conditioned-direction.md)의 저작 계약이다. StoryDocument가 조건을 보관하고 Runtime Core가 실제 읽기 기록으로 해석한다. Ren’Py에는 조건을 제거한 RuntimeScene만 전달한다.

## 저작과 형식

StoryDocument schema8의 효과 cue, 재생 동작의 음악/주변 소리 cue, 개별 효과음 cue에 선택적 `branchCondition: {sourceLineId, choiceId}`를 둔다. 장 기본 소리에도 같은 계약을 적용한다. 두 항목은 존재하는 갈림길 컷과 그 컷의 선택지 ID를 가리키는 길이200 이하 비어 있지 않은 문자열이다. 임의 항목·부분 참조·유지/정지 동작의 조건은 거부한다. 초기 단일 선택 계약은 그대로 유지하며 여러 선택의 결합은 아래 후속 계약을 따른다.

표시 문구·도착 컷을 바꿔도 선택지 ID가 유지되면 조건은 유지된다. 같은 컷에 합쳐지는 여러 선택지를 구분한다. 정적 도달 가능성을 저작 허용 조건으로 쓰지 않는다. 참조된 선택지/갈림길의 제거 또는 진행 방식 변경은 참조를 먼저 해제해야 한다. 삭제되는 컷이 소유한 cue 자체의 참조는 삭제를 막지 않는다.

archive formatVersion2/API payloadVersion1/JSONB 저장 envelope1/RuntimeScene 버전은 유지한다. workbook8의 `presentationEffects`, `audioTracks`, `audioSounds` 일반 열은 `branchConditionPresent`, `branchSourceLineId`, `branchChoiceId`다. 조건 없음은 false와 미설정 ID, 있음은 true와 두 ID다. 원고를 숨긴 payload는 추가하지 않는다. Excel·Google 시트는 이 공통 양식을 사용한다.

문서1–7과 workbook2–7은 기존 저작 데이터·자산·무대·흐름·종료 컷을 보존해 현재 버전으로 올린다. 구버전 선언에 실제 조건 데이터를 넣으면 거부한다. 기존 JSONB snapshot은 원본 저장 콘텐츠의 fingerprint를 검증한 다음 문서를8판으로 올린다. 저장된 원본이나 fingerprint를 새 버전으로 덮지 않는다. 읽기 선택 기록·편집 방문 경로·기기 UI는 작품 파일에 들어가지 않는다.

## 실제 읽기 의미

현재 cue 진입 이전에 방문한 참조 갈림길의 **가장 최근 방문**에서 해당 선택지를 실제로 고른 경우에만 cue를 시작한다. 같은 목적지라도 선택지 ID가 다르면 조건은 다르다. 선택 기록이 없거나 갈림길의 현재 방문에서 아직 고르지 않았으면 조건은 거짓이다. 조건부 작품의 읽기 복원은 필요한 선택 기록을 목적지로 추정하지 않는다.

cue 시작 컷/실제 장 진입에서 거짓이면 건너뛴다. 이후 조건이 참이 되어도 이미 지나온 cue를 뒤늦게 시작하지 않는다. 다시 시작 위치에 진입하면 새 기록으로 평가한다. 이어지는 효과·연속 소리는 참조 갈림길 재방문 대기 또는 다른 선택으로 조건이 거짓이 되면 해당 cue만 끝낸다. 관련 없는 기존 연출/소리는 건너뛴 조건부 cue 때문에 사라지지 않는다. 기존 종료 컷 포함·우회·재진입과 일반 재생/유지/정지 의미는 유지한다.

효과음은 실제 컷/장 진입 때 조건을 확인한 목록만 재생한다. 작가가 지정한 대기 시간·음량·목록 순서는 그대로다. 이 조건은 선택지 자체의 표시 조건이나 선택 점수와 별개이며 점수 없는 작품도 사용할 수 있다.

## 편집과 검증

조건은 추가 편집의 해당 cue 상세에 한 선택기로 둔다. 기본 글쓰기 화면에 조건 도구를 상시 펼치지 않는다. ‘모든 갈래’로 조건을 해제하고 기존 효과/소리별 변경 취소로 되돌릴 수 있다. 선택한 조건의 ‘갈림길부터 재생’은 그 컷에서 정상 Core 읽기를 시작한다. 독자가 실제 선택해야 하며 선택/점수 기록을 만들어 넣지 않는다. 중간 컷부터의 미리보기는 이전 선택을 추정하지 않는다.

완료 조건은 같은 목적지 두 선택지, 반복/재선택/되돌림, 조건 없음/잘못된 참조, 조건부 연출·세 소리 종류, 취소·전체 원고/무대·파일/양식/JSONB·재열기·native 읽기 복귀다. 로컬 자동 검증은 [실행 기록](branch-scope-validation.md)이 소유한다. 물리 삼성 IME/학교 기기·새 외부 앱 편집·배포는 별도 목표다. Excel ChatGPT 추가 기능 연결은 사용자 결정으로 제외했다.

사용자에게 보이는 기능 이름과 설명은 [제품 용어 기준](editor-terminology-and-time.md#제품-용어-사용-기준--2026-10-19)을 따른다. 내부 키·현재 파일 계약과 과거 검증 기록은 용어 정리로 바꾸지 않는다.

## 여러 선택 조건의 그리고/또는 -- 2026-10-22

기존 단일 선택 형태를 보존하면서 `branchCondition: {mode:'all'|'any', terms:[{sourceLineId,choiceId}, ...]}`를 추가한다. 조건 항목은1~8개이며 정확한 선택 쌍의 중복·중첩 묶음·알 수 없는 키·잘못된 참조는 거부한다. 항목 순서를 보존하고 항목이 하나인 묶음도 임의로 단일 형태로 바꾸지 않는다. 단일 선택을 열거나 저장하는 것만으로 묶음으로 바꾸지 않는다. schema8/workbook8 안의 추가 계약이며 archive2/API1/JSONB envelope1/RuntimeScene은 유지한다. 구버전 선언 아래 조건 데이터를 허용하지 않는다.

`all`은 모든 선택, `any`는 하나 이상의 선택이 실제 읽기 이력과 맞는 경우다. 각 항목은 해당 출발 컷의 가장 최근 방문을 기준으로 한다. 아직 방문하지 않았거나 다시 방문해 선택을 기다리는 출발 컷은 그 항목이 거짓이다. 같은 도착 컷·같은 선택 문구로 선택 ID를 추정하지 않는다. 이어지는 효과와 연속 소리도 전체 묶음을 다시 평가하므로, `any`의 한 항목이 거짓이 되어도 다른 참인 항목이 있으면 유지된다. 거짓이 되어 종료한 cue를 다른 컷에서 뒤늦게 시작하지는 않는다.

기존 효과·배경음·주변 소리·이어 재생 묶음·개별 효과음과 장 기본 소리에 같은 규칙을 사용한다. 삭제 보호·진행 방식 변경·컷 복제·선택 소유 컷 이동·나누기/합치기·이어읽기 복원은 모든 조건 항목의 정확한 참조를 확인한다. 점수 조건과 선택 이력 조건은 대상을 구분하며 이 묶음 안에 점수 비교를 섞지 않는다.

편집은 분기조건 기능을 켠 뒤 해당 연출/음향 상세에서 한다. ‘선택 조건 추가’를 여는 동안에는 원고를 변경하지 않고 실제 선택지를 고르면 조건을 추가한다. ‘모두 고른 경우 · 그리고’와 ‘하나라도 고른 경우 · 또는’을 표시한다. 이미 고른 정확한 선택은 중복 추가하지 못한다. 항목 삭제·결합 방식 변경은 기존 해당 효과/소리 변경 취소를 사용한다. 묶음의 미리보기는 ‘처음부터 선택 확인’으로 실제 선택 이력을 만들어 재생한다. 단일 조건의 기존 선택 컷 미리보기는 유지한다.

표 형식에서는 세 설정 표(`presentationEffects`, `audioTracks`, `audioSounds`)에 `branchConditionMode`를 추가한다. 미설정은 기존 단일 조건, `all/any`는 묶음이다. 묶음은 `branchConditionPresent=true`, 기존 두 단일 선택 ID는 미설정으로 두고 `branchConditionTerms`의 행에 실제 선택을 편집한다. 소유 위치는 `ownerTable, chapterId, lineId?, cueId?, channel?, ownerOrder?`로 정확히 연결하고 항목은 `position, sourceLineId, choiceId`로 기록한다. 연출은 효과 순서와 원래 ID(있을 때)를 함께 확인한다. ID 없는 효과에 새 ID를 만들지 않는다. 이어 재생은 원래 묶음 ID를 사용한다. 순서는0부터 연속이고1~8개다. 다른 소유자·순서/ID 불일치·단일/묶음 값 충돌·고아 행은 거부한다. 세 mode 열과 새 표가 모두 없는 이전 workbook8만 기존 단일 양식으로 보완한다. 부분 누락은 손실 위험으로 거부한다. 셀의 예약 문자열과 이스케이프된 ID도 원래 문자열로 복원해 비교한다.
