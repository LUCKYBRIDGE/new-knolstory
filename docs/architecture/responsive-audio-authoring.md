# 표시 영역 구도와 연출·오디오 제작

## 인접 컷의 장면 미리보기 — 2026-10-20

기본편집의 이전/다음 원고 컷은 Core가 해석한 고정1280×720 `RuntimeScene`을 현재 단일 Ren’Py 인스턴스에 `renderSceneThumbnail`로 요청한다. protocol1의 선택적 명령이며 `requestId`와 edit모드 scene을 검증한다. bridge는 현재 장면의 seq/revision·audio·크기를 바꾸지 않고 최대2요청을 유지한다. 현재가 play이면 실행하지 않는다.

Ren’Py8.5.3의 기존 `knol_stage` screen을 별도 표시 없이 `render_to_surface`로 렌더하고320×180 PNG를 `sceneThumbnail`로 반환한다. 임시 scene·첫 글 페이지·화자 스크롤·대사 측정 캐시는 finally에서 복원하고 현재 컷의 interaction/audio/Flow를 실행하지 않는다. 실패는 `sceneThumbnailFailed`로 식별한다. pinned SDK 내부 ScreenDisplayable adapter를 사용하므로 SDK 변경 시 실제 native 재검증이 필요하다.

Web은 origin/source·requestId·sceneId·revision과 제한된PNG data URL을 검사한다. 원고와 해석된 scene 내용으로 캐시 키를 만들고 메모리 캐시24개·응답 대기12초를 제한한다. 컷/작품/구도 변경 뒤 오래된 응답은 무시하며 현재 주변 두 컷만 생성한다. 이미지와 캐시는 작품 파일·브라우저 원고 저장·온라인 데이터에 추가하지 않는다. 동영상/전체 대사 페이지 재생이 아닌 첫 글상자를 포함한 정지 미리보기다. 제품 배치 기준은 [DESIGN](../../DESIGN.md#기본편집의-컷-배치와-보조-공간--2026-10-20-사용자-확정), 현재 검증은 [완성 작업 기록](evidence/editor-completion-2026-10-20/checkpoint.json)이 소유한다.

최신 결정:16:9/9:16만 사용하고4:3은폐기했다. 큰종이패널 대신 반투명짙은녹색 대사창·밝은본문·민트화자와작은투명도구를쓴다. 짧은원고는실제페이지높이로상자를낮추며 같은컷내페이지는최대실측높이로고정한다. 글씨설정은페이지글분량과독립,배경/인물좌표불변이다. 아래4:3·고정4/6줄빈공간은이전후보이며 [현재읽기도안](reading-interface-design.md)의최신절이우선한다.

최신사용자결정:4:3을폐기하고16:9/9:16만제품에서생성한다. 대사창은짙은반투명ADV오버레이로바꾸고기준4/6줄분량은유지하되짧은글의빈줄예약은제거한다. 실제페이지높이로패널만조절하며독자font변경이페이지문장·경계를바꾸지않고배경·인물도불변이다. 아래4:3확장은과거기록이다. [최신읽기기준](reading-interface-design.md)을따른다.

후속 사용자 수정: `dialogueStyle.paginationFontSize`(기본32)는 페이지 문장/분량을 정하는 기준이고 표시 `fontSize`와 독립한다. 글씨 크기를 바꿔도 동일 양식의 페이지 내용·개수는 유지하며 실제 렌더 높이에 맞춰 패널만 커지거나 작아진다. 배경·인물 rect는 그대로다. 가로4줄/세로6줄은 기준 분량이며 사용자 글씨에서의 강제 줄 수가 아니다. 4:3은1280×960캔버스 안의1280×720그림 영역(artworkRect)과 하단 확장으로 구성한다. 배경·인물·효과는 원래 그림 영역으로clip하고 패널만 하단으로 내린다. [읽기 개편](reading-interface-design.md)의 후속 수정 절을 따른다.

2026-10-18: 사용자가 [읽기 종합 개편안](reading-interface-design.md)을 확정했다. 최신 로컬 후보는1280×720/720×1280의 두 무대와contain, 전체 장면 위의 하단 전체 폭 오버레이, 기본 본문4/6줄을 사용한다. 배경·인물은 전체 무대 기준이며 패널/글씨 크기에 따라 이동·축소하지 않는다. 글씨 크기90/100/115/130%와 기본값 복원은 기기 설정으로 저장한다. 아래 동적viewport·가변 높이·40%/2줄 내용은 이전 구현/후보 기록이며 새 계약과 구분한다. 구체적인 현재 상태·한계는 상세 개선안과 STATUS를 따른다.

## 본문 높이 맞춤 — 2026-10-18 사용자 수정

Core의 `textboxRect`는 최소 상자와 아래쪽 기준을 제공한다. Ren’Py는 실제 NotoSansKR의 같은 본문 폭·글자 크기·줄간격으로 내용 고유 높이를 측정하고 상자만 위로 늘린다. 이는 글꼴 조판이며 Core의 무대/인물 배치 알고리즘을 Python으로 복제하지 않는다. 무대 논리 크기·배경·actor rect/배율/직접 배치는 그대로 소비한다. 실제 표시한 `textboxRect`와 `dialogueRects`를 기존 렌더링 응답으로 보고한다.

본문의 viewport·마우스휠/드래그 스크롤·세로 스크롤바는 제거한다. 화면 높이를 넘는 원고는 원문·공백·개행·글꼴 크기를 유지해 native 본문 페이지만 나눈다. 이전 글/다음 글로 페이지를 이동하며 마지막 페이지 전의 native 진행 입력은 컷 진행 이벤트를 보내지 않는다. 선택지는 마지막 페이지에서만 표시하고 해당 영역의 높이를 남긴다. Web 의미 계층은 전체 원문을 제공하므로 보조기술의 컷 이동을 별도의 페이지 상태에 묶지 않는다. 원고나 StoryDocument에는 페이지 구분을 저장하지 않는다.

측정은 현재 장면 하나에 한정해 캐시하고 새 장면 명령에서 페이지를 처음으로 되돌린다. 글 상자 확장으로 인물의 아래쪽이 더 가려질 수 있지만, 이를 피하려고 인물을 축소하거나 이동하지 않는다. [실제 글 상자 검증](evidence/dialogue-fit-2026-10-17/native-final/result.json)은 여러 화면의 높이·기준선과 상자 위 캐릭터 픽셀 불변, 초장문/선택지 진행을 확인한다. 물리 기기·청취·스크린리더 전체 검증은 별도다.

## 모바일 읽기와 분량 안내 후보 — 2026-10-18 미배포

당시 모바일 후보는 세로 글 상자를 화면의2/5까지 허용했다. 본문과 작은 페이지 조작 줄을 이 높이 안에 배치하고, 짧은 글에는 불필요한 최대 높이를 강제하지 않는다. 이 높이로도 담기 어려울 때 문장/문단→단어→문자 묶음 순으로 나눈다. 실제 컷·원고·인물 좌표는 변경하지 않는다. 읽던 문자 위치를 유지해 화면 회전 때 재분할한다.

읽기 도구는 모든 기기에서 상자 아래에 항상24px 한 줄로 표시한다. 좁은 모바일은 지난기록·빠른저장·설정이고, 설정에는 저장·불러오기·자동ON/OFF·빠른불러오기를 둔다. 넓은 화면은 여섯 기능을 직접 제공한다. 글씨는 본문 물리 크기의절반, 테두리·도구 모음 바탕·개별 사각 배경 없이 구분색·초점/선택/비활성 상태로 버튼임을 알린다. 가로 도킹 글 상자는 좌우8% 여백으로 폭84%와 본문 약2줄을 기준으로 사용하며 인물 배치는 유지한다. 세로40% 기준은 유지한다. 본문 페이지 버튼은 우측 하단에 작은 크기로 정렬한다.

편집기 안내는390×844 참고치로 한 줄 한글 약18자×약9줄, Enter 없는 연속 한글 약162자를 표시한다. 문자 묶음 기준 글자 수와 예상 행 수를 함께 보여주며, Enter·빈 줄은 별도 행을 소비한다. 이 값은 글꼴·기기·문장 경계에 따른 추정이며 강제 제한이 아니다.

RuntimeEvent의 선택적 `loadProgress`(2026-10-31)는 `ready` 전에만 보낸다. bridge가 `renpy.wasm`·`renpy.data`·`game.zip`의 실제 받은 바이트를 빌드가 넣은 원본 크기(`window.knolRuntimeTransfer`)와 비교해 `{stage:'download',ratio}`를, 모두 받은 뒤 `{stage:'start'}`를 보낸다. 엔진 요청과 응답은 그대로 두고 복제본만 센다. protocol1을 유지하며 모르는 host는 버리고, 어떤 host도 이 이벤트를 기다리지 않는다. 표시 규칙은 [DESIGN 진행률](../../DESIGN.md#무대-준비의-진행률--2026-10-31-사용자-결정)이 소유한다.

RuntimeEvent의 sceneRendered는 선택적인 dialoguePage(index,count)를 보고한다. 같은revision의 페이지 변경도 host가 반영하며 자동읽기 키에 포함한다. 중간페이지는 부모창→bridge의동일출처/장면/revision검증된nextDialoguePage명령으로글만넘기고마지막에서만Core가컷을진행한다. 수동입력과겹쳐도해당명령은다음컷이벤트를생성하지않는다. 오디오잠금/전환중에는이동하지않는다.

[통합 캡처와 목업](evidence/reader-details-2026-10-18/mockups/index.html), [구현·검증 근거](evidence/reader-details-2026-10-18/checkpoint.json). 실제Core는 세로의 연결화자한명중앙/가로좌우인물유지를기존대로소비한다. 후보는 아직운영에배포하지않았으므로 로컬export를운영이미지로자동승격하지않는다. 이전목업은당시검토기록이다.

## 구현 계약

StoryDocument v5의 기존 의미를 유지하며 선택적 `Chapter.audio`, `StoryLine.audio`, `presentation.backgroundFocal/backgroundFit`, `StageActorEntry.motion`을 추가했다. 구형 작품에는 새 필드가 필요 없다. 문서에는 자산 ID와 의미 있는 설정만 저장하고, 화면 픽셀이나 Ren’Py 코드·캐시 경로를 저장하지 않는다.

RuntimeScene contractVersion 1에는 선택적 `viewportVersion:1`, 논리 무대 크기, `textboxRect`, `dialogueStyle`, 배경의 최종 `rect`, actor motion version1, audio version1을 추가했다. 새 호스트는 이 계약을 이해하는 공유 Ren’Py presenter와 함께 배포해야 한다. 기존 렌더러로 새 확장을 보내 동작한다고 가정하지 않는다.

Runtime Core가 실제 표시 영역의 비율을 받아 모든 위치를 계산한다. 세로는 논리 폭720, 가로는1280을 사용하며 높이는 비율에서 계산한다. Web은 그 결과와 동일한 좌표계로 iframe·편집 손잡이를 투영한다. Ren’Py는 동일 인스턴스의 가상 화면 크기를 바꾸고 전달된 배경·인물·글상자를 표시한다. Web 이야기 렌더러는 없다.

## 기본 구도와 호환

화면 구도 선택은 현재 표시 영역, 데스크톱16:9, 휴대폰 세로9:20, 가로20:9를 제공한다. 선택은 편집기 보기 상태이며 작품의 인물 좌표를 변경하지 않는다. 배경 중심 x/y와 화면 채우기/전체 이미지 보기 선택은 작품 설정으로 저장한다. 새 표시 영역의 기본값은 화면 채우기이며, 전체 장면 그림을 보존해야 하는 컷은 전체 이미지 보기로 여백을 허용할 수 있다. 실제 원본 이미지 크기를 사용해 cover/contain과 중심에 따른 최종 사각형을 Core에서 계산한다.

표시 영역을 전달하지 않는 기존 호출은1280×720의 기존 계산을 유지한다. 새 편집·재생에서는 투명 여백을 포함한 캔버스 높이 대신 실제 알파 실루엣의 높이를 기준으로 크기를 보정한다. 일반 사람 대비 작은 인물의 기본 실루엣 높이는98%이며, 사용자가 지정한 배율은 그 위에 그대로 적용한다. 기존 Asset ID, stage actor key, xAnchor, 배율, 중앙·원본 방향, 무인물·POV 컷은 보존한다. 동물·소품·탈것의 별도 비율은 유지한다.

모바일 세로 기본 글상자는 높이 약66% 지점에서 시작하고 인물 발끝 기준은85%다. 얼굴이 위로 잘리지 않도록 보정하며 하반신은 글상자 뒤에 가린다. 좌우 일부 잘림을 허용해 전신을 보여주려는 과도한 축소를 피한다. 여러 인물은 표시 공간에 맞춰 안전 배치를 적용한다. 새 기본값의 시각적 변화는 문서 데이터의 자동 재작성이나 마이그레이션이 아니다.

세로 편집에서는 읽기 좋은 무대 때문에 입력 영역이 사라지지 않도록 전체 편집 흐름의 스크롤과 활성 입력 영역의 최소 높이를 확보했다. 가로 편집은 무대와 도구를 나눠 표시한다.

## 연출과 오디오 규칙

화면 효과는 무대 전체에, look은 배경·인물에, 인물 강조와 motion은 지정 인물에 적용한다. 인물별로 서서히 등장·퇴장 또는 출발 가로 위치에서 최종 배치로 이동 중 한 동작을 선택한다. 동작 시간과 시작 대기를 저장한다. 효과의 기본 지속 시간은 UI에 안내하고 전환 시간은 직접 설정한다. 같은 컷의 문서·구도 갱신은 연출을 재시작하지 않는다. 확인형 전환 완료는 revision 대신 컷 진입 identity에 묶어, 화면 크기나 동작 설정을 바꿔도 진행을 다시 잠그지 않는다. 엔딩으로 넘어가는 것은 새 컷 진입이 아니므로 마지막 컷의 효과음을 반복하지 않는다. 구도 미리보기의 글 크기는 실제 표시 배율에서 읽기 좋은 크기를 확보하도록 계산한다. 실제 진입·재시작은 별도 presentationEntry로 구분한다. 동작 줄이기는 최종 인물 상태를 즉시 적용하고 기존 화면 효과·전환의 규칙도 따른다.

장 진입 시 장 기본 음악 지시를 적용하고 컷의 명시적 음악 재생/변경·정지 지시를 적용한다. 생략/유지는 앞 컷의 상태를 이어받는다. 실제 방문 경로를 해석하므로 선택지 합류에서 다른 가지의 음악이 섞이지 않는다. 동일 경로의 음악·반복 설정은 컷 이동이나 표시 영역 갱신 때문에 다시 시작하지 않으며 음량은 갱신한다.

이전으로 이동하면 축소된 방문 경로의 음악 상태를 복원한다. 처음부터/다시 읽기는 새 audio session으로 음악을 처음부터 시작한다. 새로고침의 이어읽기는 저장된 컷·선택 경로를 복원하고 그 컷의 원하는 음악을 처음부터 시작한다. 음악의 초 단위 재생 위치는 작품·이어읽기 저장 대상이 아니다. 엔딩에서는 마지막 음악 지시를 유지하며, 편집 모드로 돌아오면 음악과 효과음은 정지한다.

효과음은 장 진입당 장 설정 최대4개, 컷 진입당 컷 설정 최대4개를 각 음량·지연으로 실행한다. 장 안의 다음 컷에서는 장 효과음을 반복하지 않는다. 이전 컷의 미실행 효과음은 취소한다. 전환 화면이 있는 컷은 전환 완료 후 효과음 지연과 인물·화면 연출을 시작한다. 같은 컷 수정은 효과음을 반복하지 않는다. 오디오를 사용하는 재생에서 아직 게임 내부 입력이 없으면 Ren’Py가 ‘소리 켜고 시작’ 화면을 표시한다. 실제 무대 입력 전에는 음악·효과음과 연출 시계를 실행하지 않고 host 진행도 보류한다. 무대를 누르면 음악·효과음·연출을 함께 시작한다. 이후 컷 이동은 다시 잠그지 않는다.

## 자산 보관

기본 공유 자산은 숲·밤 음악, 종·발걸음 WAV4개이며 생성 방법과 원본은 `apps/web/public/assets/audio/README.md`에 기록했다. 오디오도 이미지처럼 안정적인 자산 ID를 사용하고 registry에서 런타임 경로로 해석한다.

사용자 WAV/MP3/OGG는 `knolstory-audio-assets-v1` IndexedDB에 저장한다. 파일 서명, 크기, SHA-256을 검증하고 `audio:custom:<hash>:<extension>` ID를 발급한다. `.knolstory` 파일의 최상위 `audioResources` 첨부 표에는 실제 사용한 자료의 bytes를 base64로 보관한다. StoryDocument의 project에는 바이너리가 없다. 전체 파일20MB, 파일당5MB, 가져오는 오디오 첨부 표의 base64 총합20MB 한도를 적용한다. 파일 경계와 native 설치 경계 모두 안전한 ID·경로·해시를 검증한다.

이전 파일처럼 첨부 표가 없는 작품도 읽는다. 사용자 오디오를 참조하는데 파일과 보관함 모두에 자료가 없으면 가져오기를 거부하고 현재 작품을 보존한다. 다른 브라우저로 파일을 복원할 때도 자산 ID와 bytes를 함께 복원한다. 기본 자산만 있는 작품은 IndexedDB 오디오 보관함이 불가능해도 재생·파일 내보내기에 불필요한 의존을 갖지 않는다.

## 클릭으로 시작하는 효과 — 2026-10-21

‘클릭하면’ 효과의 입력 우선순위는 오디오 시작/화면 전환 → 남은 본문 페이지 → 아직 실행하지 않은 클릭 묶음 → 선택지 또는 다음 컷이다. 한 입력은 한 단계만 처리한다. 선택지 컷도 효과 묶음을 먼저 실행하며 그동안 선택지 버튼은 숨긴다. 화면 터치·Enter/Space·텍스트 보기의 진행 버튼은 같은 Core 진행을 사용한다. 좌우 터치 설정의 이전 이동은 효과 실행과 구분한다. 자동 넘기기는 수동 클릭 묶음 앞에서 기다리고 마지막 묶음 뒤에 다음 대기를 새로 시작한다.

StoryDocument의 `trigger:'on-click'`과 선택 `clickStep:1..3`은 저작 정보다. 같은 순서는 함께 실행하고 미설정이면 해당 컷의 클릭 효과만 센 목록 순서를 사용한다. 정확한 선택 조건을 적용한 뒤 남은 번호를 정렬해 빈 클릭 없이 진행한다. 이전 효과와 함께/다음에 맞추기는 이전 클릭 순서와 현재 시간을 복사하며 지속적인 의존 관계를 만들지 않는다. 다른 시작 기준에 맞추면 클릭 순서를 제거한다.

Core가 현재 경로 방문의 `PlaybackState.effectStep`을 소유한다. 실행하지 않은 클릭 효과는 RuntimePresentation에서 제외하고 실행한 효과만 기존 시작 기준으로 정규화한다. RuntimeScene의 `effectSteps:{current,total}`은 입력을 위한 해석 결과다. Ren’Py가 원고나 조건을 해석하지 않는다. 새로 나타나는 안정적인 originEntry의 시계는 실제 묶음 실행 시점에 시작하고 기존 효과는 같은 컷의 revision/크기 변경으로 재시작하지 않는다. 이전 컷에서 이어지는 효과는 실행된 상태로 유지한다.

진행 저장은 현재 묶음 실행 수를 보존하고 범위를 검증한다. 새 컷·이전 이동·같은 컷의 새 방문·처음부터 재생은 새 진행으로 시작한다. 정확한 애니메이션 프레임/밀리초 복원은 기존 진행 저장과 마찬가지로 보장하지 않는다. 시점 전환 제목 컷의 클릭 묶음은 수동 실행하며 마지막 묶음 이후 추가 입력으로 다음 컷에 간다. 화면·배경 효과는 제목 위에 표시하고 숨겨진 인물 대상을 화면 전체로 바꾸지 않는다.

## 원본 음원 사용 구간 — 2026-10-21

Core는 [저장 계약](authoring-storage-contract.md#원본-음원-사용-구간--2026-10-21)의 시작·끝을 RuntimeMusic/RuntimeSound의 선택 필드로 전달한다. 자료 경로는 검증된 원래 경로이며 사용 구간 문자열을 붙이지 않는다. Ren’Py 경계에서만 고정 SDK의 `from`·`to` 오디오 지정으로 변환한다. 반복 재생은 지정 구간을 반복하며, 한 번 재생은 선택한 끝에서 멈춘다. 효과음 대기 시간은 원본 시작 위치와 별도로 적용한다.

같은 세션에서 같은 자료·사용 구간·반복 여부가 컷 사이에 이어지면 기존 음악 채널을 재시작하지 않는다. 음량만 변경해도 재시작하지 않는다. 사용 구간이나 반복 여부가 달라지면 새 구간의 시작부터 재생한다. 정지·새 재생 세션은 기존 규칙을 따른다. 진행 저장의 정확한 음원 밀리초 복원은 추가하지 않는다. 진단 이벤트의 자료 경로는 구간 지정을 제거한 경로로 유지한다. 자료 자르기/분할 기능 전체나 서로 다른 소리를 매끄럽게 잇는 편집까지 완료한 것으로 해석하지 않는다.

## 효과음 사용 구간 분할 — 2026-10-21

효과음 하나를 원본 시간 S에서 둘로 나누면 앞 조각은 기존 ID와 원본 시작·재생 대기를 유지하고 원본 끝만 S로 바꾼다. 뒤 조각은 새 ID와 원본 시작 S를 갖고, 원래 끝의 미설정 여부·자료 ID·음량·정확한 선택지 조건을 보존한다. 뒤 조각의 재생 대기는 `기존 대기 + S - 기존 원본 시작(미설정이면0)`이다. 같은 목록에서 앞 조각 바로 뒤에 삽입하고 한 번의 음향 변경으로 처리한다. 별도 문서 필드·양식 버전은 추가하지 않는다.

분할은 원본 사용 시작과 유효 끝의 엄격한 내부 정수 밀리초만 허용한다. 끝은 작성된 사용 끝 또는 알려진 자료 길이이며 둘 다 없으면 거부한다. 알려진 자료보다 긴 기존 구간은 자동으로 맞추지 않고 먼저 수정하도록 안내한다. 범위별 효과음 최대4개·뒤 조각 대기 최대10초를 유지한다. 거절은 목록을 변경하지 않는다. 장 진입 효과음과 컷 효과음은 기존 Core 구분과 최대8개 native 채널을 따른다. 화면 전환 종료 시 기존 `knol_finish_transition`이 효과음 시계를 다시 시작한다.

두 구간은 기존 예약 효과음으로 각각 재생되며 정밀 오디오 편집기의 샘플 단위 이음은 보장하지 않는다. 실제 검사도 두 번의 구분된 시작·파일 보존 범위를 증명한다. 원본 바이트는 변경하지 않는다. 배경음·주변 소리의 단일 채널을 같은 방식으로 여러 항목에 복제하지 않는다. 그 트랙의 여러 구간 편집은 별도 모델과 재생 연결이 필요하다. [현재 집중 검증](evidence/sound-split-2026-10-21/checkpoint.json).

## 연속 소리의 컷 구간 분할 — 2026-10-21

컷에 작성한 `music`·`ambience`의 `play` 지시를 나눌 때, 앞 지시는 그대로 두고 `endLineId`만 분할 바로 전 컷으로 변경한다. 분할 컷에 원래 지시를 독립 복사하며 원본 사용 구간·음량·반복·페이드·원래 종료의 미설정 여부를 보존한다. 기존 `maintain`은 복사 지시로 바꾸고 취소 시 정확히 복원한다. 다른 채널·효과음·글은 유지한다. 현재 StoryDocument·양식·RuntimeAudio의 기존 필드를 사용하며 새 형식/재생 계약을 만들지 않는다.

유효 범위는 같은 장의 작성 순서에서 원래 종료 또는 다음 명시적 재생/정지 앞까지다. 분할 컷은 시작 뒤·유효 범위 안이어야 한다. 조건부 원본 지시는 자동 분할하지 않는다. 모든 내부 컷에 대해 전체 작품의 실제 도착 후보를 `storyFlowTargets`로 대조한다. 바로 전 컷만 유입되고 전 컷의 도착 후보도 현재 컷 하나일 때 허용한다. 따라서 내부 건너뛰기·선택지·점수 경로·합류·순환은 변경 전에 거부한다. 검사에 필요한 유입 목록은 한 번 구성한다. 장 기본 지시와 복잡한 갈래의 자동 분할은 미구현 범위다.

분할의 목적은 구간별 설정의 독립 편집이다. 원본 파일·사용 구간·반복 상태가 같으면 기존 Ren’Py 채널 identity가 같으므로 경계에서 재시작하지 않는다. 바뀐 원본 범위/반복은 기존 규칙대로 재시작한다. 동영상식 고정 컷 길이·샘플 단위 이음·같은 컷 안의 여러 소리 예약을 뜻하지 않는다. 변경 취소는 기존 `CombinedRangeUndo`로 두 컷의 해당 채널을 검증·복원하며 이후 수정된 대상은 덮어쓰지 않는다. [현재 파일·실제 native 검증](evidence/continuous-audio-split-2026-10-21/checkpoint.json).

## 원본 사용 구간의 독립 미리 듣기 — 2026-10-21

Web의 HTML audio는 편집 자료 미리 듣기만 담당하며 이야기 재생을 대체하지 않는다. `AudioPickerField`가 장면 전용 정책을 먼저 검사한 뒤 허용된 자료에만 `AudioAudition`을 제공한다. 작성 구간·음량을 전달하고 실제 디코더 길이로 유효 재생 범위를 계산한다. 끝에서 멈춤·시작점 복귀·음량 적용은 DOM 미디어 상태만 변경하며 원고를 갱신하지 않는다. 음량 자체의 편집은 기존 음향 변경·취소 경로를 사용한다.

위치 이동 중 중복 이동을 요청하지 않고 데이터 준비·seek 완료 후 구간 검사를 이어간다. 재생 중20ms 간격과 미디어 이벤트로 끝을 확인한다. 브라우저·디코더 일정에 따른 오차가 있으므로 샘플 단위 절단/정확한 청취 품질 보장으로 해석하지 않는다. 자료/구간/활성 상태 변경·정지·완료·오류·컴포넌트 해제에서 재생 또는 검사 타이머를 정리한다. 실제 컷의 대기·반복·페이드·갈래는 Ren’Py 검증 범위로 유지한다.

## 장 기본 소리의 컷 구간 분할 — 2026-10-21

장 `music`·`ambience`의 무조건 `play` 지시를 선형 컷 구간에서 나눈다. 기존 컷 분할의 연결·유효 범위 검사를 재사용하되 첫 컷 합성은 검증 중에만 사용하고 원본 첫 컷 객체를 최종 문서에 그대로 복원한다. 장의 앞 구간 종료만 분할 직전 컷으로 변경하고, 뒤 컷에는 기존 장 지시를 독립 복사한다. 원래 종료의 존재 여부·원본 사용 범위·반복·음량·페이드는 유지한다. 새 문서·양식·RuntimeAudio 필드를 추가하지 않는다.

첫 컷의 해당 채널은 미설정 또는 `maintain`만 허용하며 재생·정지·조건부 재생을 덮어쓰지 않는다. 유효 종료·이후 명시적 변경과 전체 작품의 연결 검사는 기존 [컷 분할](#연속-소리의-컷-구간-분할--2026-10-21)을 따른다. 장 막대의 실제 표시 범위 안에서 후보를 표시하고 실행 직전 현재 문서로 다시 검증한다.

편집용 `CombinedRangeUndo`는 선택적 장 음향 스냅샷과 뒤 컷 스냅샷을 가진다. 취소는 두 대상의 해당 채널만 이후 수정 여부를 검사하고 복원한다. 장 제목·다른 채널·장 효과음·첫 컷의 후속 편집·뒤 컷 본문은 보존한다. 장/뒤 컷이 삭제되거나 해당 소리가 수정되면 취소하지 않는다. 이 스냅샷은 작품 파일·독자 진행 저장 필드가 아니다. [현재 파일·native 검증](evidence/chapter-audio-split-2026-10-21/checkpoint.json). 조건부 장 음향과 비선형 구간의 자동 분할·같은 컷 안의 음악 조각 편집은 남아 있다.

## 선택 조건을 보존하는 소리 구간 분할 — 2026-10-21

앞선 조건부 원본의 일괄 거부를 제한적으로 대체한다. 장 기본 또는 컷 `play`의 `branchCondition`이 소리 시작보다 앞에 있는 선택 컷을 참조하고, 시작 뒤 유효 종료까지 기존 선형 연결 검사를 통과하면 분할을 허용한다. 앞·뒤 지시의 `{sourceLineId,choiceId}`를 정확히 보존한다. 현재 파일 검증이 실제 선택 ID 참조를 확인하며 미완료/미방문 선택을 허가로 만들지 않는다.

Core는 같은 도착 컷으로 가는 서로 다른 선택도 실제 선택 기록으로 구분한다. 조건 성립 경로에서는 동일 음원 identity로 이어지고, 불성립·기록 없음 경로에서는 기존 다른 소리 상태를 유지한다. 구간 안의 새로운 선택·점수 경로·합류·우회는 기존 그래프 검사로 거부한다. 미래/현재 시작 컷의 선택 조건은 허용하지 않는다. 이 변경은 복잡한 갈래를 임의로 펼치거나 자동 합류를 추가하는 기능이 아니다.

조건·자료·원본 구간·음량·반복·종료의 존재 여부와 취소 의미는 기존 장/컷 분할 계약을 따른다. 검증은 장/컷×배경음/주변 소리×참/거짓/기록 없음의 Core 대조, 같은 목적지의 실제 두 선택 native 재생과 작품 파일 재열기, 현재 archive·workbook·XLSX 바이트·JSONB 왕복을 포함한다. [이번 근거](evidence/conditional-audio-split-2026-10-21/checkpoint.json). 외부 Excel/Google 앱에서 직접 편집·저장한 증거와 실물 기기 증거는 별도다.

## 여러 음원의 순서 재생 -- 2026-10-22

기존 단일 `play`·유지·정지의 의미는 그대로 두고 장/컷의 배경음·주변 소리에 `action:sequence`를 추가한다. 묶음 ID와 순서 있는1~16개 조각을 보관하며 각 조각은 고유 ID·음원 ID·유한한 원본 사용 끝과 선택적 시작·음량·시작/끝 페이드를 가진다. 각 조각을 한 번씩 앞 조각 바로 다음에 재생하고 마지막에서 정지한다. 묶음 전체의 정확한 선택 조건·종료 컷을 지원한다. 중간 무한 반복이나 조각별 다른 선택 조건을 추정해 넣지 않는다.

기존 단일 소리를 바꿀 때는 접힌 ‘여러 소리 이어 붙이기’에서 반복 해제·한 번씩 재생을 안내하고 명시적으로 시작한다. 첫 조각의 원본 구간·음량·페이드·묶음 조건/종료 컷을 보존하며, 끝이 없으면 확인된 자료 길이를 사용한다. 길이를 알 수 없으면 끝을 먼저 지정하도록 안내하고 기존 원고를 유지한다. 조각 추가는 선택 조각의 설정을 복사하고 새 ID를 만든다. 순서 이동·삭제·사용 구간·음량·페이드·분할을 선택 조각의 상세에서 편집한다. 분할은 앞 ID와 바깥 페이드만 유지하고 중간 이음에 새 페이드를 넣지 않는다. 기존 채널별 변경 취소는 묶음 전체를 보존한다.

Core는 실제 방문 경로에서 활성 묶음과 원래 진입 ID를 해석한다. 뒤 컷이 유지하면 같은 진입 ID를 전달하므로 Ren’Py의 순서 시계가 다시 시작되지 않는다. 실제 시작 컷 재방문·새 읽기 세션·묶음 설정 변경은 새로 시작한다. 편집 재생/새로고침 복원은 처음부터 다시 재생하며 초 단위 독자 재생 위치를 원고에 저장하지 않는다. 정지·다른 소리로 대체·종료 컷 이후·편집 복귀는 남은 조각 예약도 취소한다. 배경음과 주변 소리는 독립 시계를 가진다. 실제 음향 잠금 해제 후 시작하며 Web은 대체 오디오 재생기를 만들지 않는다. 클립 중 사용 제외 자료가 있으면 묶음 채널 전체를 정지하고 원고는 보존한다.

통합 화면은 작성한 적용 컷 구간과 현재 컷의 각 조각 길이/누적 순서를 표시하고, 조각 막대를 누르면 정확한 ID의 상세를 연다. 초 단위 막대는 현재 읽기 경로에서 실제 소리가 어디까지 진행했는지를 추정하지 않는다. 현재 조각 구간/순서는 상세 목록에서 편집하며 기존 효과용 지연·길이 끌기로 음원 조각을 잘못 변환하지 않는다. 묶음의 시작/종료 컷 변경과 취소는 [시작 컷 이동](#순서-음원의-시작-컷-이동--2026-10-22) 기준을 따른다. 컷 경계 자동 나누기는 연속 시계 보존 정책이 추가되기 전까지 명시적으로 거부한다. 순서 시작 컷의 글 나누기도 같은 이유로 차단한다.

여러 조각의 모든 음원 참조를 파일 첨부·개인 음원 복원·서비스 자료 준비에 포함한다. 서비스 자료는 경로 수 최대42개 검증과 기존24MB 원본/32MB base64예산을 함께 지키며 한도를 넘으면 재생 준비를 거부한다. 두 채널 각16조각과 효과음8개로 실제 장면의 서로 다른 참조는 최대40개다. [현재 구현·검증 범위](evidence/music-sequence-2026-10-22/checkpoint.json).


## 순서 음원의 시간 막대 직접 편집 -- 2026-10-22

여러 음원의 현재 컷 시간 보기에서 선택한 조각만 직접 조작한다. 설정에서 끌기를 켠 뒤 순서 바꾸기·앞부분 조정·뒷부분 조정을 고른다. 이동은 선택 조각을 뺀 목록의 가장 가까운 삽입 경계를 사용하며 공백을 만들지 않는다. 앞/뒤 조정은 누적 시간과 원본 시간을 정확하게 변환하고 뒤 조각을 함께 이동시킨다. 원본 시작0이상·끝보다 작은 시작·확인된 자료 길이를 검증하며 길이를 알 수 없는 음원은 기존 작성 끝을 넘겨 늘리지 않는다.

보조선을 선택 조각의 양끝으로 가져오기, 보조선에서 두 조각으로 나누기, 접힌 숫자 입력과 앞뒤 맞춤을 제공한다. 분할은 내부 위치만 허용하고16개 한도를 지키며 기존 ID·음량·바깥 페이드와 원본 구간을 보존한다. 끌기는 기본 꺼짐이며 자동 맞춤·보조선 표시를 끄거나 Shift로 일시 해제할 수 있다. 드래그 중 배율·시간축·보조선·대상 정보가 바뀌면 편집을 취소한다. 드래그 직후 다른 조각을 누르는 실제 클릭을 누락시키지 않는다.

시간 변경 취소는 해당 작품·컷·채널의 현재 순서가 직전 결과와 일치할 때만 이전 채널을 복원한다. 이후 본문·다른 채널 수정은 보존하며 선택 채널의 후속 수정은 덮어쓰지 않는다. 작품 파일·저장 버전·native 재생 계약은 바꾸지 않는다. 장 기본 순서 묶음의 현재 컷 초 단위 편집과 컷 경계 자동 분할은 이번 범위가 아니다. 컷 시작 이동은 아래 후속 기준을 따른다. [직접 조작·파일 검증](evidence/sequence-time-edit-2026-10-22/checkpoint.json).


## 초 단위 작업 영역의 화면 조작 -- 2026-10-22

시간 보기의 확대·축소·전체 보기·위치 찾기는 별도 초 단위 영역의 handle로 전달한다. 컷 목록의 비활성 DOM 크기를 사용하지 않는다. 배율은 UI 상태이며 작품 파일에 추가하지 않는다. 전체 보기에서 시간축 우측 최소24px 클릭 영역과 끝 눈금까지 포함한다. 시간 영역에도 비수동 wheel listener를 연결해 Ctrl 확대와 Shift 가로 이동을 제공하고 해제 시 정리한다. 키보드 +/−·화살표·Home/End도 같은 영역을 사용한다. 시간 화면을 조정하는 동안 문서 전체가 원본과 같은지 검증한다. [화면·원고 근거](evidence/time-viewport-controls-2026-10-22/checkpoint.json).


## 순서 음원의 시작 컷 이동 -- 2026-10-22

컷의 배경음·주변 소리 순서 묶음을 새 시작 컷으로 옮길 수 있다. 묶음·조각 ID, 원본 사용 구간·순서·음량·페이드·정확한 선택 조건과 종료 컷을 보존한다. 새 시작 컷에서 첫 조각부터 재생하며 Runtime Core의 owner 기반 진입 ID가 이 시작을 구분한다. 이전 컷에서 얼마나 재생됐는지를 새 시작 컷에 추정해 이어 붙이지 않는다. 별도 문서 필드·native 계약은 추가하지 않는다.

소리 상세의 시작 컷 이동은 도착 컷의 해당 채널에 어떤 설정이라도 있으면 덮어쓰지 않는다. 순서 묶음에 종료 컷이 있으면 새 시작 컷과 같은 장이며 새 시작보다 앞서지 않아야 한다. 통합 컷 구간 조정은 시작과 종료를 함께 지정하여 기존 종료 뒤로 옮기는 경우도 새 유효 종료를 확인한다. 기존 종료·다른 소리 변경을 가로지르는 통합 범위는 기존 구간 충돌 검사를 따른다.

통합 컷 막대 끌기에서도 순서 묶음의 시작/끝을 조정한다. 끌기 시작 시 작품·장·컷·배율·모드·원고를 기록하고 도중 변경 시 원고를 수정하지 않고 취소한다. 다음 포인터·키보드 선택도 누락시키지 않는다. 변경 취소는 두 컷의 해당 채널만 검증하여 복원하며 이후 본문·다른 채널은 보존한다. 컷 경계에서 실제 경과 시간을 추정하는 순서 묶음 자동 분할은 계속 차단한다. [구현·파일·native 근거](evidence/sequence-origin-move-2026-10-22/checkpoint.json).


## 컷 표시 조건과 음향 편집의 경계 -- 2026-10-23

편집 요약·통합 시간축은 숨겨질 수 있는 컷도 원고 순서에 남겨 해당 설정을 편집한다. 실제 재생 결과로 가장하지 않으며 표시 조건에 따라 달라질 수 있음을 안내한다. 컷 ID·막대 인덱스를 재생에서 필터링된 배열의 위치로 대체하지 않는다.

컷 표시 조건이 있는 소리 구간의 자동 분할은 아직 지원하지 않는다. 숨긴 분할 컷의 새 소리가 실행되지 않거나 숨긴 끝 컷 때문에 소리가 달라질 수 있어, 컷/장 배경음·주변 소리 모두 원고 변경 전에 거부하고 이유를 알린다. 기존 표시 조건 없는 선형 구간의 분할과 조건부 선택 이력 보존은 유지한다. [회귀·한계](evidence/editor-visibility-integration-2026-10-23/checkpoint.json).

### 인접 장면 캡처의 native 축소 -- 2026-10-26

인접 장면은 기존1280×720 논리 Render의 구도를 유지하고, 고정 SDK의 native Render 축소 후320×180 PNG로 캡처한다. 현재 장면·페이지·스크롤·원고·음향 상태를 바꾸지 않으며 실패에도 복원한다. SDK 내부 adapter이므로 버전 변경 시 실제 장면/글 배치·DPR·원고 보존을 다시 확인한다. [실제 검증과 메모리 한계](evidence/thumbnail-render-2026-10-26/checkpoint.json)를 따르며 이 변경을 실물 장시간 충돌 해결로 판정하지 않는다.
