요청: 폰과 태블릿에서 화면을 더 단순하게, 중요한 행동에 집중하게 다듬는다.

### 1-2. 바꾼 것

**학급 공통**
- 폰 세로(≤720px)와 폰 가로(높이 ≤500px)에서 페이지 제목은 화면 읽기용으로만 남기고(탭이 위치를 말함), 폰 가로에서는 브랜드 줄도 접는다(탭의 `서재`가 같은 일).
- 교사 학급 띠를 한 줄로: `우리 반 · 학생 3명 | 학생 접속 코드 ABC234`. 장식 문구 제거.
- 글자형 단추(`linkBtn`)와 `과제 안내` 접기를 44px로.

**교사 과제**
- 카드는 제목·종류·과제 안내 → `제출 1 / 3명 · 받는 학생 · 우리 반 모두 · + 마감일 정하기` → **`진행 보기` · `과제 마감`** 순서.
- 받는 학생 바꾸기, 편집 범위, 시작 작품, 숏스토리 → 놀스토리 이어 쓰기 과제 만들기, 외부 제출 링크, 과제 지우기는 카드 맨 아래 **`과제 설정 더보기`** 한 곳에 접었다. 받는 학생 칩은 밖에 그대로 보인다(누가 받는지는 평소에도 필요한 정보).
- 위에서 말한 평상시 안내 문구 7개를 지웠다. 읽기·활동 과제가 하나도 없을 때의 빈 상태 안내는 남겼다.

**교사 학생**
- 이름 `수정` 단추는 이름을 바꾼 뒤에만 나타난다(≤960px 카드 표). 320–360px에서는 `관리` 단추가 화살표만 남아(읽는 이름 ‘1번 관리 펼치기’는 그대로) 이름 칸이 61px → 80px 넘게.
- 행 단추·이름 칸 44px.
- 폰 가로에서도 `학생 만들기`를 접어 시작(`PhoneFold`의 폰 판정에 짧은 가로 화면 포함).
- 표 위 ‘학생 3명’은 표의 이름(caption)으로만 남기고 화면에서는 학급 띠 하나로.

**학생 할 일**
- 이름 띠를 할 일 머리 줄로 합쳤다: `[2번] 3반 2번 하늘 ……… ✓ 1 / 4개 끝냈어요`. ‘나의 이야기 자리’, ‘오늘의 이야기 숙제’ 장식 문구 제거(목록 이름 ‘할 일’은 영역 이름으로 유지).
- 카드의 “쓰기 화면에서 작품을 만든 뒤…” 반복 문구 제거. 시작할 수 없는 경우의 안내(선생님께 확인)는 유지.
- 폰 가로에서 머리·카드 여백을 줄여 첫 `과제 쓰기`가 첫 화면 안으로.

**계정 메뉴**
- 로그인 뒤: `로그인됨` → **이 계정의 목적지(교사 대시보드 / 내 학급·과제, 강조 단추)** → 관리자·교사 등록 → 온라인 보관 → Google 연결 → 로그아웃.
- 로그인 뒤의 일반 설명 문단과 ‘구름 표시…’ 문장 제거. 로그인 전에는 한 줄(“로그인하면 작품을 온라인에도 보관할 수 있어요.”).
- `로그인 상태 다시 확인`은 여러 실패 흐름의 복구 수단이라 그대로 맨 아래에 두었다.

**읽기 메뉴**
- 머리를 `읽기 메뉴` + 한 줄(`작품 제목 · 1장 · … · 1번째 장면`)로 합쳤다.
- 짧은 가로 화면에서 머리 줄이 실제로 숨도록 규칙 순서를 고쳤다. 844×390에서 `계속 읽기` 위치 145px → 121px, 마지막 항목까지 메뉴 안에서 닿는다.

**작품 설정**
- 늘 뜨던 저장 안내를 지우고, ‘이야기 기획’·‘창작 메모’에서만 “기획과 메모는 읽기 화면에 나오지 않아요.”를 보인다.

- 새 검사 `tests/e2e/mobile-focus.spec.ts`(17개): 교사 과제 다섯 크기에서 첫 화면 주 행동·44px·가로 스크롤·더보기 안의 다섯 도구·지운 문구, 교사 학생 이름 칸 폭과 `수정` 표시 시점·폰 가로 접힘, 학생 다섯 크기에서 첫 `과제 쓰기`, 계정 메뉴 목적지 순서, 읽기 메뉴 머리 한 줄·짧은 가로에서 숨김·마지막 항목 도달, 작품 설정 안내가 기획에서만 보임.
- 기존 학급 목업을 `tests/e2e/classroom-mock.ts`로 옮겨 `classroom.spec.ts`와 새 검사가 함께 쓴다.

### 1-5. 실제 계정 데이터로 다시 확인 (같은 날 추가)

사용자가 ego lite에 교사(관리자)·학생 계정으로 로그인한 뒤, 운영 서버에서 학급 데이터를 **읽기(GET)만** 받아 이 브랜치의 로컬 화면에 그대로 넣어 일곱 크기에서 다시 쟀다. 쓰기 요청은 모두 막았다. 학생 비밀번호는 받자마자 지웠고, 실제 이름이 담긴 데이터와 캡처는 저장소에 넣지 않았다. 학급 규모는 학생 25명, 작품 쓰기 과제 4개, 읽기 과제 1개였다.

목업에서는 드러나지 않았던 문제 두 가지를 이 확인에서 찾아 고쳤다.
- **교사 학생 탭**: 실제 학급에는 저장 공간 정보가 있어서, `학급 저장 공간` 카드와 늘 펼쳐진 설명이 `학생 만들기`와 학생 목록 사이에 끼어 있었다. 320×700에서 첫 학생 줄이 767px까지 밀렸다. 카드를 학생 목록 아래로 옮기고 설명은 `저장 공간 안내`로 접었다. 80%가 넘을 때 나오는 경고는 그대로다. 수정 뒤 첫 학생 줄은 568px로, 첫 화면 안에 들어온다.
- **학생 할 일(폰 가로)**: 이름 아래 저장 공간 줄과 카드의 ‘이 과제에서 고칠 수 있는 것’ 줄 때문에 첫 `과제 쓰기`가 화면 밖으로 약 20px 밀렸다(844×390에서 위치 363px). `과제 쓰기`를 과제 안내 바로 아래로 올리고, 편집 범위와 바탕 작품 줄은 그 아래에 두었다. 폰 가로에서는 이름 아래 저장 공간 줄을 숨긴다. 수정 뒤 위치는 323px로, 첫 화면 안에 들어온다.

실제 데이터로 잰 최종 결과: 교사 과제와 학생 할 일은 일곱 크기 모두 주 행동이 첫 화면 안에 있고, 44px 미만 조작과 가로 스크롤은 없다. 교사 학생 탭은 폰 가로 두 크기와 1024×768에서 첫 학생 줄을 보려면 한 번 스크롤해야 한다.

## 2부. 편집 화면·읽기 무대 — 진단과 개선안 (코덱스 작업 병합 뒤 구현)

측정에서 44px 미만으로 나왔지만 문제가 아닌 것(다음에 같은 측정을 할 때 참고):
- 아래 빠른 막대 단추는 보이는 높이가 24px이지만 `.quick button:before{inset:-10px 0}`로 누르는 영역이 44px이다.
- `이전 읽은 컷`·`다음으로`(34px 폭)는 키보드용 ‘대사·해설 텍스트 보기’ 안의 단추로, 화면에 보이는 터치 조작이 아니다.

### 2-3. 구현 순서 제안
1. E1·E4(편집 머리 줄, 태블릿 아래 도구 접기) — 첫 화면 글상자 위치가 가장 크게 바뀜.
2. E2·E6·R1(폰 무대 띠, 짧은 가로 두 열·막대 축소). R1은 `story-player-menu.tsx`의 `phone` 판정(글상자 폭 <660px)에 높이 조건을 더하는 일이라 코드는 작지만, 막대 위치가 무대 안전 영역과 맞물리므로 `stage-layout.ts` 병합 뒤에 한다.
3. E3·E5·E7·R2는 정책 확인·원인 확인 뒤.

각 단계는 `tests/e2e/mobile-focus-audit.ts`의 `auditScreen`으로 같은 일곱 크기를 다시 재고, `control-reachability.spec.ts`(stories-runtime)로 누르기가 겹치지 않는지 확인한다.

## 3. 확인하지 못한 것
- 실제 휴대폰·태블릿(사파리, 안드로이드 크롬). 이번 확인은 모두 Playwright 크로미엄으로 했다. 운영 계정 데이터는 1-5처럼 로컬 화면에 넣어 확인했고, 이 브랜치가 운영에 배포된 상태는 아니다.
- 터치 태블릿의 `pointer:coarse` 규칙은 실제 기기에서만 켜진다. 측정의 태블릿 숫자는 고운 포인터 기준이다.
- 과제 20개·학생 30명을 채운 학급의 스크롤 길이. 실제 학급(학생 25명, 과제 5개)까지만 확인했다.
