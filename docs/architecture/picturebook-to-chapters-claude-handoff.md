# Claude 구현 인계 · 숏스토리에서 놀스토리로

2026-11-20. 이 문서는 작업 순서와 검수 기준을 소유한다. 제품 동작과 자료 분류는 [전환 설계](picturebook-to-chapters-design.md), 실물 후보 ID는 [삽화 조사표](evidence/picturebook-chapters-design/illustration-inventory.csv)가 소유한다. 시작 브랜치는 `codex/picturebook-to-chapters`, 조사 시점 main은 `8a175f01`이다. 여기까지는 설계 문서만 커밋되어 있다. 개발 시작 때 HEAD·작업 상태·main의 이후 변경을 확인한다.

## 첫 납품 범위

개인 그림책의 현재 쪽에서 ‘놀스토리로 보내기’ → 실제 원화와 첫 무대 미리보기 → 해당 장의 빈 첫 컷에서 집필 → 서재와 그림책에서 같은 원고 다시 열기. 별주부전 8쪽을 수직 검증 대상으로 삼되 작품 이름이나 쪽 번호로 분기하는 코드는 만들지 않는다. 빈 추천 목록으로도 모든 단계가 동작해야 한다. 기존 자료의 카탈로그 등록 여부, 권리, 실제 무대 구도 검토 결과를 구분한다.

Claude는 변환·저장·파일 형식·권한·추천/미리보기 UI·기존 자료의 조합 검증·회귀 검사를 담당한다. 새 그림이 필요한 장면은 제작 요청으로 남긴다. 그 장면은 ‘삽화만 참고’로 구현하고 나머지 흐름을 계속 검증한다. 새 그림 제작, 운영 수업 데이터 생성·변경, 배포는 이번 인계에 포함하지 않는다.

## 순서와 코드 출발점

1. **파일 계약부터 검증한다.** 현재 [문서 버전](../../packages/story-domain/src/legacy/story-project-document.ts)과 [필드 스키마](../../packages/compatibility/src/authoring-field-schema.json), [파일 코덱](../../packages/compatibility/src/authoring-archive.ts), [표 코덱](../../packages/compatibility/src/authoring-workbook)을 함께 확인한다. 장별 개요와 선택적 그림책 구상 삽화의 왕복 fixture를 먼저 작성한다. 이전 버전 읽기와 마이그레이션, 서버의 중첩 자산 검증, 장 복제·분할의 참조 정책을 함께 검사한다. 장 참고 필드를 버리는 경로가 남아 있으면 UI 공개 전에 해결한다.
2. **결정적인 변환 함수를 만든다.** 검증된 숏스토리와 쪽별 선택, 주입된 ID 발급기를 입력으로 삼는다. 결과는 독립 프로젝트와 쪽 ID→장·첫 컷 ID 대응표다. 쪽 순서만으로 앞뒤를 잇고, 그림·제목이 같아도 각 장은 독립시킨다. [기존 생성 규칙](../../packages/runtime-core/src/authoring.ts)과 Runtime Core의 장면 컴파일을 사용한다. 학생의 문장을 수정하거나 대사를 자동으로 생성하지 않는다.
3. **추천을 작품과 분리한다.** 원화 ID·리비전에 맞는 검토된 조합과 대안만 읽는다. 학생 직접 조합 / 승인 조합 / 참고 전용을 구별한다. 준비 화면의 변경은 쪽 ID로 임시 보관하고 ‘놀스토리로 보내기’에서 확정한다. 새 이미지 없이도 테스트 전용 승인 fixture로 후보 선택·되돌리기·복합 자세 중복 방지를 검사한다. 운영 목록으로 승격하려면 실제 기존 자료로 가로·세로 첫 무대와 권리를 대조한다.
4. **재시도해도 하나의 원고만 생성한다.** [작업 공간](../../apps/web/lib/workspace-storage.ts)과 [탭 인계](../../apps/web/lib/workspace-takeover.ts)의 현행 쓰기 경로를 따른다. 생성 키는 소유 범위+원본 그림책 ID로 찾고, 전송 요청 ID는 재시도용으로 별도 사용한다. 원본 그림책을 보관한 뒤 변환한다. 대상 writer를 확보한 뒤 최신 인덱스를 다시 읽고 원고와 연결을 한 번에 확정한다. 두 탭의 서로 다른 요청 ID가 같은 원본을 가리키는 경우까지 검증한다. 생성 실패 시 새 편집기로 이동하지 않는다. 링크만 남거나 대상이 휴지통에 있으면 자동 재생성하지 않는다.
5. **정상 진입점에 연결한다.** [그림책 편집기](../../apps/web/app/shortstory/shortstory-workspace.tsx)에서 사용자가 마지막으로 보고 있던 쪽의 장으로 들어간다. 이후 그림책 화면의 ‘보낸 놀스토리 열기’는 대상 작품의 유효한 마지막 집필 컷을 우선한다. [놀스토리 편집기](../../apps/web/components/story-workspace.tsx)에서는 현재 장의 구상과 원화를 펼쳐 본다. 웹은 저작과 자료 선택을, Runtime Core는 장면 해석을, Ren’Py는 무대 표시를 맡는다. 미리보기와 확정에 같은 변환 결과를 사용한다.
6. **계정과 과제 경계를 검사한다.** 원본 읽기에서 개인 사본으로 진입, 게스트 기기 작업, 로그인 계정 전환, 학생의 새 작품·지정 작품·그림 권한 제한을 구분한다. 권한 확인 실패를 게스트 생성 허가로 바꾸지 않는다. 현행 형식별 제출을 유지하고 개인 작품 생성만으로 제출·과제 분량·교사 목록을 변경하지 않는다.

## 시연으로 인수하는 기준

- 별주부전 8쪽을 8장으로 만들고, 4쪽에서 시작하면 4장이 열린다. 각 장에 첫 컷 하나, 장 개요에 원문, 첫 대사는 비어 있다. 학생이 수정한 텍스트와 재배열한 쪽 순서로도 검사한다.
- 추천이 있는 한 쪽만 바꿔도 다른 쪽의 선택은 유지된다. 같은 원화를 두 쪽에 써도 독립적이다. 첫 무대에 없는 자세·권리 미확인 자료는 추천에서 빠지고 학생은 그림책 구상 삽화를 확인할 수 있다.
- 2장에 컷과 대사를 추가한 뒤 그림책으로 돌아가 재진입해도 같은 작품·집필 위치가 복구된다. 원본 그림책을 수정해도 이전 놀스토리의 대사는 보존된다.
- 한글 조합 중 확정, 취소, 연속 클릭, 두 탭, 저장 공간 부족, 손상 보관함, 권한 변경, 연결된 작품 삭제·복구를 재현한다. 실패한 생성이 원본이나 기존 원고를 바꾸지 않는지 비교한다.
- 파일·Excel·온라인 저장 후 재열기, 자료가 누락된 기기에서의 안내, 390px/1280px 미리보기·편집·재생을 검사한다. 서버나 DB 계약을 변경한 경우 전용 테스트 PostgreSQL에서만 통합 검사를 추가한다. E2E 등록 검사, 문서 검사와 제품 용어 검사도 수행한다.

## 이미지 제작자에게 넘기는 항목

한 요청에 원화 ID, 재사용을 검토한 후보 ID, 현재 무대에서 부족한 이유, 필요한 행동·방향·소품·접촉점, 대표 캐릭터/의상, 가로·세로 구도 제약, 여러 장면에서 재사용할 용도를 기록한다. 후보 파일명으로 임시 ID를 운영 원고에 굳히지 않는다. 제작·검토 완료 후 정식 ID와 리비전을 조합 목록에 추가한다. 개인 작품의 기존 장면은 자동으로 교체하지 않는다.

## 후속 정책

교사가 두 과제를 연결하는 절차, 다른 기기에서 원본과 새로 연결하는 절차, 네 작품 동시 출시 여부와 신규 그림 수량은 1차 구현의 선결 조건이 아니다. 이 항목은 사용자 결정과 검증 근거를 남긴 뒤 확장한다.

## 병합·배포 확인 목록 — 2026-11-21

**병합 순서.** PR #55(별주부전 2·6쪽 재확인 근거, 문서 1개) → #56(세 작품 첫 무대 조합) → #57(#56 위에 쌓임: 세로 중심 인물·용어·재제작 그림 34점·안전 영역 검사). 세 PR은 서로 겹치는 파일이 없고 현재 main 위에서 충돌 없이 합쳐진다. #57은 #56이 main에 들어간 뒤 base를 main으로 바꿔 병합한다.

**늘어나는 용량 (#56+#57).** 배포되는 웹 그림 37개 3.8MB, 저장소에만 있는 원본 그림 37개 55.6MB와 검토 근거 이미지 80개 12.2MB, 코드·데이터·문서 11.1MB(카탈로그·출처 기록 포함). Pages 파일당 한도(25MiB)에 걸리는 파일은 없다. 운영 Mac mini는 디스크가 찬 적이 있으므로 배포 뒤 오래된 이미지·빌드 캐시를 정리한다.

**배포 전에 막히는 것.** 이 브랜치에서 `pnpm delivery:check`는 `Runtime changed; renew source review: runtime/game.zip`으로 멈춘다. Ren’Py 실행 묶음(`game.zip`)에 그림책 새 그림의 자리표시(PR #50부터, main에도 해당)가 늘고 프로젝트 스크립트 바이트코드 9개가 바뀌어, [2026-11-13 런타임 출처 검토](evidence/classroom-release-2026-11-13/runtime-review.json) 이후 다시 봉인해야 한다.
