# 그림책의 한 쪽을 놀스토리의 한 장으로 펼치는 설계안

2026-11-20 · 설계 검토용. 기준 main `8a175f01`. 현재 서비스는 원본 그림책의 사본 편집, 각 형식의 파일 왕복과 같은 유형의 과제 제출을 지원한다. 아래 연결은 구현 전이다. [그림책 계약](four-work-shortstory.md) · [저장 계약](authoring-storage-contract.md) · [학급 계약](classroom-design.md).

## 학생이 얻어야 할 결과

학생이 그림책 네 쪽으로 사건을 구상하면, 네 장으로 된 독립 놀스토리 한 편을 만든다. 각 장에 줄거리와 출발 그림이 남고 첫 컷에는 승인된 조합만 놓인다. 같은 장에서 두 번째 컷을 만들어 상대의 반응을 쓰거나 갈래를 나눌 수 있다. 첫 컷은 글이 빈 해설로 시작한다. 시스템이 학생 문장의 화자·결말·감정·선택지를 대신 정하지 않는다. 두 번째 방문은 쓰던 작품으로 이어진다.

## 어떤 그림을 정리할 것인가

[90장 조사표](evidence/picturebook-chapters-design/illustration-inventory.csv)는 기본 네 그림책 원화 34장(8·8·10·8)과 카탈로그에서 shortStoryCollection으로 분류된 별도 삽화 56장(story 2, creative 54)을 ID 기준으로 대조한다. 사용자가 직접 배경과 인물을 조립한 쪽은 조합 수가 정해지지 않으므로 별도 경로로 처리한다. 조사표의 후보와 제작 제안은 운영 자동 배치 허가가 아니다.

| 입력 | 이미 알 수 있는 사실 | 필요한 조사와 정리 |
|---|---|---|
| 기본 그림책 원화 34장 | 원작·쪽·사건과 원화 ID가 확정되어 있다 | 제목이나 번호보다 원화 ID로 연결한다. 학생이 쪽을 옮기거나 삽화를 바꿔도 현재 그림을 기준으로 한다. |
| 합성 재료가 기록된 삽화 8장 | sourceLayers에 사용한 자료 ID와 해시가 있다 | 파일이 같은지 확인한 후 바닥선·크기·순서·시선을 재조립한다. 원래 재료라는 사실만으로 최종 위치가 복원되지는 않는다. |
| 제작 참고 자료가 기록된 삽화 48장 | referenceAssets는 이미지를 만들 때 참고한 자료다. 이 중 24장에는 연속 사건 정보가 있다 | 최종 그림에 실제로 보이는 인물과 행동을 다시 읽는다. 같은 사건 묶음에서는 의상·소품·배경을 먼저 공유하고, 앞뒤 상태가 달라지는 부분만 별도로 준비한다. |
| 학생이 직접 고른 배경 및 좌우 인물 | 쪽 자체에 세 ID가 있다 | 허용 자료는 원래 좌우 순서로 옮긴다. 완성 삽화 위에 학생이 추가한 인물과 삽화 속 인물이 중복될 수 있으면 자동 병합하지 않고 참고 그림에서 원래 구성을 보존한다. |

**재정리는 기존 파일 이동이나 일괄 이름 변경 없이 진행한다.** 공통 자료 원장은 Asset ID를 계속 소유한다. 새로 구축할 것은 ‘이 삽화에서 어떤 무대 재료를 어떤 관계로 쓸 수 있는가’라는 별도 목록이다. 배경은 장소·시간·시점·기후, 인물은 동일 인물 ID·의상·자세·시선·손동작·소품, 두 인물 묶음은 탑승·부축처럼 맞닿는 관계를 기록한다. 의미가 같은 자료가 있으면 대표 ID와 변형 ID를 연결한다. 복장이나 시점이 다른 유사 자료를 하나로 합치지 않는다. 원화·참고 이미지·무대 배경·투명 인물·복합 자세를 구분하고 한 이미지를 여러 사건에서 재사용할 수 있게 한다.

## 무엇을 새로 만들 것인가

우선순위는 **그 동작이 빠지면 사건이 달라지는가 → 기존 재료를 배치해 해결되는가 → 다른 장에서도 쓸 수 있는가** 순이다. 분위기나 표정만 다를 때는 먼저 기존 후보를 조립한다. 정확한 원화 복제율을 목표로 삼지 않는다.

| 별주부전 시범 장면 | 첫 검토 결과 | 제작 판단 |
|---|---|---|
| 3쪽 달콤한 초대 | 노을의 물가·소나무가 대응하고 제안하는 자라와 의심하는 토끼가 있다 | 기존 자료로 서로 마주 보게 조립한다. 얼굴 방향은 비대칭 소품까지 보고 판단한다. |
| 4쪽 바다를 건너 | 먼 육지가 보이는 바다와 등에 탄 토끼·자라 복합 자세가 있다 | 한 덩어리의 자세를 한 번 배치한다. 토끼를 다시 올리지 않는다. 다음 컷을 위해 개별 인물 후보도 연결한다. |
| 7쪽 다시 밟은 땅 | 도약하는 토끼와 물가의 자라가 각각 있다 | 점프하는 방향과 물가 위치가 맞는지 먼저 본다. 정지 자세 전환만으로 사건을 표현할 수 있어 동영상 제작은 후순위다. |
| 1쪽 용궁의 근심 | 아픈 용왕과 결심한 자라는 있지만, 원화에서 중요한 것은 자라가 몸을 낮춰 간청하는 행동이다 | **신규 1순위 후보**는 기존 자라의 얼굴·관복·등껍질을 유지한 옆모습 간청 자세. 용왕까지 함께 그릴 필요는 없다. |
| 2쪽 낯선 육지 | 초상화를 든 자라와 물가 배경이 있지만 원화에서는 갈대 사이를 살핀다 | 초상화가 사건에 맞는지부터 확인한다. 갈대 전경을 현재 무대에서 따로 놓을 수 없으면 인물 없는 갈대 물가 배경 후보를 검토한다. |
| 8쪽 숲으로 돌아간 토끼 | ‘미안해서 도망’이라는 기존 자료는 실제로 서 있는 토끼다 | **신규 우선 후보**는 숲 쪽으로 멀어지는 토끼의 ¾ 뒷모습. 저 자세를 다른 사건의 ‘떠나기’에서도 쓸 수 있게 한다. |
| 5·6쪽 위기와 꾀 | 궁전·놀란 토끼·설명하는 토끼·용왕 자세 후보가 있다 | 왕좌의 높이, 화자 거리와 듣는 방향을 실제 무대로 대조한 뒤 승인한다. 두 쪽이라는 이유로 궁전을 두 장 더 만들지 않는다. |

다음 작품에서는 흥부전 ‘제비 치료’처럼 이미 행동 자료가 있는 장면, 선녀전 ‘두레박을 타고’처럼 인물·도구 접촉이 중요한 장면, 옹고집전 ‘두 옹고집의 다툼’처럼 같은 얼굴을 가진 두 인물을 구분해야 하는 장면을 각각 검토한다. 별주부전 외 26개 원작 장면이나 56개 추가 삽화의 신규 수량은 아직 확정할 수 없다.

**제작 의뢰 한 건의 최소 정보**는 대상 원화 ID·사건, 이미 검토한 대체 후보와 탈락 이유, 기준 인물·의상·소품 ID, 누구를 바라보며 어느 손발이 어디에 닿는지, 앞·뒤 컷에서 함께 쓸 자료, 완성 크기·투명 여백·바닥선·권리 근거다. 완성품은 원화와 비교하고, 실제 편집 화면에서 16:9와 9:16 배치 및 대사창 가림을 확인한다. 승인 시 새 ID와 해시·사용 범위를 등록한다. 위치 조정으로 해결되면 새 그림을 만들지 않는다.

## 재료 목록과 작품 파일을 분리하는 기술안

1. **서비스의 장면 조합 목록.** 키는 원화 ID와 원화 리비전. 값은 조합 버전, 상태(대조 전/조립 검토/승인/참고 전용), 배경 ID, 개별·복합 인물 ID, 기대하는 방향·거리, 현재 StageComposition이 지원하는 배치값, 교체 가능한 자세 후보, 검토 근거다. 원화 속 고정 사건과 학생이 새로 쓴 줄거리가 다를 수 있으므로 무대 없이 시작하는 선택을 제공한다. 공개에 쓰는 모든 ID에 형식·노출 정책·사용 권리·파일 존재 검사를 적용한다. ID 변경이나 파일 리비전 불일치 시 재검토한다. 텍스트 유사도 검색과 AI는 제작자 후보 검색에만 쓰고 학생 원고에 자동 적용하지 않는다.
2. **변환 시 한 번 해석.** 원본 그림책의 쪽 배열을 검증하고, 각 쪽에 새 장 ID와 첫 컷 ID를 발급한다. 쪽 제목 → 장 제목(빈 제목은 번호), 쪽 글 → 기존 장 개요, 그림 → 장별 참고 자료. 작품 제목·지은이·소개를 대응 가능한 필드에 보존한다. 표지 자유 배치는 지원 의미가 같을 때만 옮긴다. 글이나 장 수가 대상 한도를 넘으면 해당 쪽과 이유를 보여 주고 원본을 보존한다. 자르거나 누락해서 성공 처리하지 않는다. 첫 장부터 마지막 장까지 순서대로 재생되고 마지막에 종료되는지 Runtime Core로 검증한다.
3. **승인된 첫 무대만 구체화.** 일치하는 조합이면 실제 첫 컷의 배경·인물 값을 써 넣는다. 표준 슬롯·레이어·자산 해석은 Runtime Core가 맡는다. 그림만 있고 조합이 미승인이라면 ‘구상 그림으로 보관 · 무대는 직접 꾸미기’로 표시한다. 빈 무대에는 명시적인 배경 없음과 빈 인물을 써서 앞 장의 배경을 잘못 이어받지 않게 한다. 이후 조합 개선으로 이미 쓴 작품이 달라지지 않는다.
4. **휴대 가능한 장 참고.** 제안 필드는 장에 선택적으로 붙이는 picturebookSketch(원래 쪽의 배경·왼쪽 인물·오른쪽 인물 ID, 필요 시 검토 버전)다. 이미지 파일 자체와 학생 계정 ID는 복제하지 않는다. 작품 파일만 다른 기기로 옮겨도 등록된 자료로 출발 그림을 볼 수 있다. 장의 개요는 기존 필드를 한 번만 저장하고 학생이 고칠 수 있게 한다. 삽화가 없는 쪽도 줄거리는 보존한다. 참고 그림은 편집에서 펼쳐 보고, 읽기·재생에는 내보내지 않는다.
5. **형식 변경은 정식 계약으로 처리.** 현행 StoryDocument v8과 archive의 엄격한 필드 검사가 있어 TS 타입만 늘리면 재가져오기에서 실패할 수 있다. 차기 문서 버전과 v8 읽기·변환, 중첩 필드 allowlist, 자산 종류·권리 검증, JSONB 스냅샷, 파일·Excel 왕복, 장 복제·분기·삭제 시 참조 처리까지 함께 설계한다. 연결 전 작품을 열면 새 필드는 없는 상태로 의미를 유지한다. 장을 쪼갤 때 어느 장이 출발 그림을 물려받는지 명시한다(제안은 기존 장에만 보존). Ren’Py 계약 변경은 필요하지 않다. [작품 형식 검사](../../packages/compatibility/src/authoring-archive.ts) · [자료 검사](../../packages/asset-registry/src/catalog-media-policy.ts).

### 조합 레코드 예시와 우선순위

아래는 4쪽의 제작자용 **검토 초안**이다. 공개용 레코드는 배경·인물의 revision, 좌우·위치·크기, 가로·세로 확인 결과, 권리 근거를 모두 채워야 한다. 레코드 키는 그림책 번호나 한글 이름에 의존하지 않는다.

```json
{
  "sourceAssetId": "rabbit-turtle.scene.shortstory-classic-04",
  "draftVersion": 1,
  "review": "candidate",
  "backgroundId": "rabbit-turtle.background.classic-sea",
  "actorAssetIds": ["rabbit-turtle.character.classic-riding"],
  "groupedSubjects": ["rabbit-turtle.rabbit", "rabbit-turtle.turtle"]
}
```

자동 배치 판단 순서는 (1) 학생이 직접 구성한 일반 배경·인물은 그 조합을 존중, (2) 완성 삽화 한 장이면 같은 원화 ID·리비전의 승인 레코드만 사용, (3) 혼합·미확인·깨진 레코드는 원화 참고만 제공한다. 참고 자료도 없어진 경우 쪽 제목과 줄거리를 살리고 빠진 자료를 알려 준다. 같은 숏스토리에서 같은 삽화를 여러 번 써도 **쪽 ID마다 독립 장**이 생긴다. 레코드 키는 재료 검색용이고, 쪽 ID는 작품 내 연결용이다.

## 가져오기 미리보기에서 추천 이미지 고르기

그림책 전체를 옮길 때 쪽마다 선택을 요구하지 않는다. 쪽 목록에는 원래 삽화·쪽 제목·첫 무대 준비 여부를 보여 준다. 보고 있던 쪽을 처음 펼치고, 그쪽의 원화와 **실제 추천 재료로 구성한 첫 컷 미리보기**를 나란히 놓는다. 휴대폰은 위아래로 배치한다. 원화에 이미 포함된 그림과 교체 가능한 배경·인물을 시각적으로 구분한다. 다른 쪽을 살펴보거나 직전에 바꾼 쪽으로 돌아와도 선택을 유지한다.

- 승인된 기본 조합이 있으면 미리 선택한다. 학생은 바로 ‘이대로 놀스토리 만들기’를 누를 수 있다. ‘다른 그림 보기’를 열었을 때만 배경·인물별 후보를 보여 준다. 후보에는 실제 썸네일과 ‘토끼 · 의심하는 자세’처럼 눈으로 확인 가능한 차이를 표시한다. 첫 제안은 역할마다 최대 세 개로 제한하고, 추가 후보가 필요하면 편집기의 기존 자료 선택기로 연결한다.
- 예를 들어 3쪽 ‘달콤한 초대’에서 물가 배경과 제안하는 자라를 그대로 두고 토끼 자세만 바꿀 수 있다. 4쪽 ‘바다를 건너’의 탑승 자세는 ‘함께 그린 토끼와 자라’로 표시해 한 번에 선택한다. 개별 인물 한 명을 바꾸는 것처럼 표시하지 않는다. ‘추천대로 되돌리기’는 현재 쪽만 복원한다.
- 학생이 직접 꾸민 쪽은 본인이 배치한 자료를 기본값으로 둔다. 승인 조합이 없으면 ‘그림책 삽화만 참고하기’가 기본이다. 후보가 없거나 그림 편집 권한이 없으면 선택을 강요하지 않는다. 교사 지정 양식·작품 생성 제한은 이 화면에서도 동일하게 적용한다.
- 후보는 원화 ID·리비전에 연결된 검토 목록에서 읽는다. 우선 원화에 직접 승인된 후보, 다음으로 같은 인물·의상·장소의 검토된 대안만 제시한다. 글에서 감정을 추측해 학생의 선택을 덮지 않는다. 같은 삽화를 두 쪽에서 사용해도 미리보기의 선택은 **쪽 ID**로 분리한다. 확정할 때 허용된 ID와 조합을 다시 검사하고 최종 배경·인물·배치를 첫 컷에 복사한다. 원본과 추천 목록에는 쓰지 않는다.
- 검증은 ① 8쪽을 아무것도 고르지 않고 생성 ② 한 쪽의 인물만 바꾸고 다른 쪽을 왕복한 뒤 선택 유지 ③ 미리보기와 생성한 첫 컷의 배경·인물·배치 일치 ④ 취소 시 작품 미생성 ⑤ 미승인·누락 자료·권한 변경 시 조용한 대체 없이 안내 ⑥ 휴대폰·키보드로 비교·선택·되돌리기까지를 포함한다. 미리보기는 Runtime Core의 장면 해석과 기존 Ren’Py 미리보기를 재사용하고, 목록 썸네일은 편집 재료 확인에만 쓴다.

## 기기 안에서 한 번만 만들고 다시 열기

- 개인 그림책에서만 시작한다. 원본을 읽는 학생은 현재의 ‘내 사본으로 쓰기’를 사용한다. 준비 화면은 쪽 수→장 수, 첫 무대가 있는 장과 참고 그림만 있는 장, 지금 열 장을 보여 준다. 기본 진입은 보고 있던 쪽의 장이다. 대사 입력·음향·선택지를 미리 채우지 않는다.
- 그림책 입력 조합을 마치고 보관 성공 → 생성 요청 → 놀스토리 쪽에서 권한·한도·현재 workspace 재확인 → 기존 writer 소유권 안에서 독립 원고를 보관 → 성공 후 해당 컷 열기 순이다. Web Storage의 여러 키는 한 트랜잭션이 아니다. 원고와 연결 인덱스는 같은 workspace 스냅샷에 원자적으로 담는 안을 우선한다. 요청 ID와 예정 작품 ID를 재시도에도 유지하고 크래시 후 같은 원고를 찾아 열어야 한다. 주소에는 짧은 요청 식별자만 사용한다. 쓰기 실패·다른 탭 경쟁·중복 클릭 시 원본이나 기존 활성 작품을 덮지 않는다. [현재 workspace 쓰기](../../apps/web/lib/workspace-storage.ts).
- 기기별 연결 인덱스는 소유 계정 범위, 그림책 ID, 대상 작품 키, 원본 쪽 ID→생성 장 ID를 보관한다. 외부 파일에는 계정과 기기 위치를 넣지 않는다. 원본 그림책을 수정해도 놀스토리를 자동 갱신하지 않는다. 기존 대상은 ‘쓰던 놀스토리 열기’, 삭제·복구·다른 기기 가져오기는 연결 여부를 확인하고 명시적으로 새 작품 생성을 선택하게 한다. 연결 인덱스를 잃어도 완성된 놀스토리와 장 참고 그림은 파일 자체로 열린다.
- 학급에서는 개인 작품 만들기, 지정 작품, 그림·인물 편집 권한을 양쪽 화면에서 확인한다. 글만 편집하는 학생의 무대를 새로 만드는 정책은 교사가 허용한 양식과 연결된 과제로 별도 정의한다. 1차에서는 허용되지 않거나 권한을 확인하지 못한 학생의 새 생성은 차단하고 기존 읽기·보관 경로를 유지한다. 자동 업로드·제출은 하지 않는다. 후속 과제에서는 교사가 두 과제를 명시적으로 연결한 경우에만 학생별 그림책을 시작 자료로 쓴다. 변환으로 생긴 빈 컷과 이미 옮긴 원문을 새 집필 분량으로 세지 않는다.

## 단계별 통과 조건과 남은 결정

| 순서 | 결과물 | 다음 단계로 넘어갈 기준 |
|---|---|---|
| 설계 검토 | 자료 조사표, 쪽→장 규칙, 파일·저장 계약 | 참고 전용 쪽 허용, 동일 그림책 재진입, 수동 그림 우선 규칙에 대한 제품 방향 합의 |
| 자료 시범 | 3쪽 대화·4쪽 탑승·7쪽 도약의 실제 첫 무대, 1쪽·8쪽 신규 후보의 제작 명세 | 초등학생이 설명문 없이 누가 무엇을 하는지 알아보고, 표지/대사창이 있는 가로·세로 무대에서 인물과 접점이 보임. 제작 진행은 이 결과 후 판단 |
| 기술 검증 | 8쪽 테스트 그림책과 변환·왕복 테스트 | 8장·8첫컷, 줄거리·순서 보존, 순차 재생·마지막 종료, 원본 불변, 파일/표/온라인 왕복 뒤 참조 보존, 미승인 원화 및 자체 조립 쪽에 올바른 대체 동작 |
| 개인 집필 | 개인 그림책에서 시작/재열기 | 두 번 눌러도 한 작품, 저장 용량 부족/권한 변경/두 탭 동시 생성/삭제·복구/한글 조합 테스트, 모바일에서 첫 대사를 쓰고 같은 컷으로 복귀 |
| 수업 확장 | 다른 원작과 자유 창작 삽화 검수, 연결 과제 | 서로 다른 학생 자료 격리, 중간본·최종 제출과 개인 원고 분리, 교사의 진행 보기에서 구상과 집필 단계 구분 |

보류할 결정은 새 이미지 총수, 기본 네 작품의 동시 출시 여부, 과제 간 연결과 기기 간 출처 재연결이다. 이번 결과물은 설계와 기존 자료 조사이며, 원화와 후보를 나란히 보는 것만으로 첫 무대 배치나 배포 권리를 검증했다고 보지 않는다.
