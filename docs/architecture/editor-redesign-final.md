2026-10-19 대체 범위: 이 문서의 단일 현재 컷/추가 도구 도안은 당시 기준이다. 현재 여섯 작업 화면·함께 보기·개별 개방은 [DESIGN](../../DESIGN.md#편집-작업-영역--2026-10-19-후속-설계)이 소유하고, [실제 화면 갤러리](evidence/editing-workbench-2026-10-19/gallery.html)로 확인한다. 아래 과거 생성 이미지/manifest는 덮어쓰지 않는다.

2026-10-10. 사용자가 여러 후보를 종합해 하나의 최종안을 결정하도록 요청했다. 최종안은 **글 중심 + 동일 장면 + 앞뒤 컷 맥락 + 필요할 때 열리는 추가 도구**다. 기존 A/B/C는 비교 이력이며 앞으로의 개편 기준은 이 문서다. 제품 코드는 아직 변경하지 않는다.

## 최종 이미지

[최종 종합 이미지](evidence/editor-redesign/final-master.png), [기기/키보드/기능별 상세 이미지](evidence/editor-redesign/gallery-final.html), [각 상태 목록](evidence/editor-redesign/final-manifest.json), [도안 생성 소스](evidence/editor-redesign/final-design.mjs).

웹·태블릿은 장면과 글을 나란히 두고, 글 입력 위/아래에 이전/다음 컷의 장·컷·화자·글 요약을 둔다. 휴대폰 세로는 장면→이전 컷→현재 글→다음 컷 순서다. 현재 글 칸만 강조하며 주변 컷을 펼쳐 편집하지 않는다. 관련 도구는 글/컷, 배경/인물, 연출, 소리, 연결로 묶고 추가 도구 하나만 연다. 작품 관리/기획/파일/복구는 작품 메뉴로 접근한다.

확정된 화자 이름표·종이색 글 상자·대사 글꼴 느낌은 유지한다. 원본 배경BG-forest-roots, 나무꾼M02-neutral, 선녀M01-soft-smile을 사용한다. 새 자산을 생성하거나 기존 bytes를 변경하지 않는다.

## 항상 확인하는 맥락과 이동

- 상단:작품/장 이름, `1장 · 3/12컷`, 앞/뒤 원고 이동, 컷 추가. 장/컷 직접 이동은 장·컷 위치를 눌러 목록에서 선택한다.
- 현재 글:현재 장·컷·대사/해설·화자·글 입력·자동 저장. 화자와 글은 같은 입력 영역에 둔다.
- 앞/뒤 요약:장·컷·화자·원고 한두 줄과 이동 버튼. 더 긴 글/배경/인물/연출/소리 요약은 선택해 확장하며 기본 화면을 채우지 않는다.
- 원고 순서의 앞/뒤 이동과 실제 Flow의 다음 읽기 연결을 구분한다. 분기 컷에는 연결된 도착2~4개와 해당 글 요약을 표시한다. 작품 끝/미연결/교사 승인/조건 미충족은 각 상태로 표시하고 다음 원고 컷을 임의 도착으로 만들지 않는다.
- 이동은 현재 입력 조합/초안을 보호하고 저장 실패 시 전환을 멈춘다. 도구 닫기/미리보기 복귀는 같은 컷·선택·스크롤/초점을 복원한다. 기존 Asset ID·Flow·StageComposition은 UI 정리로 바꾸지 않는다.

## 연출·소리의 타이밍과 범위

관련 값은 한 도구 안에서 함께 편집한다:대상/종류→시작 기준→대기 시간→지속/반복→시작 컷/끝 컷→끝 이후 동작→적용되는 경로와 컷 목록→미리보기/되돌리기.

현행 연출은 `cut/following`과 전체following 해제이며 임의 `startCutId/endCutId`가 없다. 최종 도안은 정확한 컷 범위를 편집하는 **새 기능**을 포함한다. 구현 전에 범위의 콘텐츠 SSOT·선택효과 종료 identity·기존범위/개별cue충돌·분기·컷삭제/이동·취소·파일/workbook/JSONB 왕복 계약을 결정한다. 기존 clearFollowingEffects로 다른 효과까지 지우는 편법은 허용하지 않는다.

배경음/주변 소리는 시작 컷의 play와 경로상 이후 컷의 maintain/stop이다. 장기 기본값과 컷 override를 구분한다. 시작은 해당 컷 진입/전환완료이며 현재 background music에 arbitrary delay가 없는 점을 숨기지 않는다. 효과음의 대기는 현재 지원한다. 효과음 범위는 매 적용 컷 진입에서 실행하는 batch 편집이며 연속음 범위와 다르다. 마지막 적용 컷 다음에는 새 효과음cue를 실행하지 않으며 이미 시작한 짧은 소리를 임의로 끊는다고 주장하지 않는다.

‘3컷부터5컷까지’는 실제 선택 경로에서의 범위이고 분기 화면에서 대상 경로를 명시/확인한다. 전환 중 시간은 전환 완료 뒤 센다. 컷 대기/무한루프/replay/되돌아가기에서 연출 시계와 범위 의미를 Core가 해석한다. 다음 컷을 클릭했다는 편집 동작 자체가 원고에 범위를 새로 쓰지 않는다.

## 편집 무대와 Ren’Py 동일성

최종 목표는 **편집 화면의 이야기 무대가 재생 무대와 같은 것**이다. Web header·원고 입력·패널·키보드까지 Ren’Py에 넣는 뜻이 아니다.

1. 편집/미리보기/읽기는 동일한 영속Ren’Py runtime와 RuntimeScene을 사용한다. 도안HTML은 그림 검토 자료이며 새Web Stage renderer로 이식하지 않는다.
2. 같은story/cut·같은논리viewport·같은자산/폰트/배치에서 배경crop·actor rect·flip·depth·opacity·textbox/화자/글 스타일이 일치해야 한다. 편집핸들만overlay다.
3. 도구나 키보드 때문에 사용 가능한 공간이 줄면 같은무대를 비율대로 축소/letterbox하거나 접는다. 키보드 유무로 문서좌표/배경초점/자동구도를 재해석하지 않는다. deviceorientation/display aspect 변경은 명시적보기 변경이며 원고를 보호한다.
4. 움직임/효과/transition/audio는 edit에서 정적상태일 수 있다. 같은컷 재생 확인에서는 실제entry시점부터렌더하며 engine acknowledgements를 확인한다. 정적 편집과 애니메이션 중간프레임이 늘같다고 주장하지 않는다.
5. 실제개편완료게이트:동일viewport에서 edit/play의중립stagepixel/geometry 비교, 입력overlay와실제textbox정렬, 장면/효과의최종state, 모바일/태블릿키보드/resize/rotation, 동일iframe과원고보존. **현재도안은Ren’Py동일성검증결과가 아니다.**

## 키보드별 화면

외장키보드는가상키보드가열리지않은넓은상태다. 유무를임의user-agent로가정하지않고 실제visualViewport/입력초점/가림영역을관찰한다.

- 태블릿가로/세로·외장키보드:장면+현재글+앞뒤맥락을유지.
- 태블릿가상키보드:현재글과앞뒤요약을우선하고 장면은가능한공간에같은비율로표시. 불필요한자료조작/작품도구는접기.
- 휴대폰외장키보드:전체기본화면. 좁은가로는장면과글영역나란히.
- 휴대폰가상키보드:장면을접고현재글과앞뒤요약·현재장/컷이남음. 장면보기/키보드닫기후같은구도로복귀.
- 선택지/소리입력중가상키보드:편집대상필드와상단컷맥락,현재도구의닫기/확인을유지. 도구body는스크롤하고footer는키보드위에둔다.

가상키보드이미지는도안이며실제OS입력기크기/한글조합/키보드단축키/터치결과를증명하지않는다. 개편시물리기기와visualViewport경계값으로확인한다.

## 가상 키보드 근거 보완

기존 임의 키보드 높이를 [공식 사례·AOSP 계산·실측 경계](editor-keyboard-evidence.md)에 따라 수정했다. 현재 삼성/Gboard 실측값이 아니라 출처가 있는 참고 profile이며 실기기 JSON으로 교체할 수 있다. 이 도안의 키보드 수치를 고정된 제품 CSS 높이로 구현하지 않는다. 실제 visualViewport/가림 영역에 맞춰 글·앞뒤 컷과 도구 footer를 보호한다.

## 2026-10-11 선택지·점수 최종 반영

[선택지·점수 상세 디자인](editor-choice-score-design.md)을 추가했다. 선택 문구/도착/결과/표시 조건을 같은 카드에 묶고, 작품 점수 정의·조건 경로·결과 확인·오류와 미사용 상태를 실제 펼친 도안으로 제공한다. 웹·태블릿·휴대폰 및 삼성키보드 가림 상태를 포함해 현재47장이다. 기본 글 입력 구조와 앞뒤 컷 맥락, 기존 연출/소리/작품 도구는 유지했다. 실제 제품 개편은 아직 시작하지 않았다.

## 선택지·점수 사용 조합

[네 독립 조합](evidence/editor-redesign/choice-score-combinations.png)을 추가해 현재51장이다. 작품 점수 사용과 현재 컷 선택지 사용을 각각 판단하며, 같은 작품 안의 일반/선택/조건 판단 컷을 지원한다. 미사용 기능을 자동 생성하지 않는다. 현행 점수 변화가 선택 effects에 한정되는 점과 선택지 없는 작품의 시작값 유지도 [점수 도안 기준](editor-choice-score-design.md)에 명시했다.

## 2026-10-11 제품 개편 반영 상태

사용자의 개발 시작 요청으로 우선 범위의 실제 제품 개편을 적용했다. 위의 도안 단계 기록은 당시 상태이며, 최신 구현/검증/남은 계약 항목은 [실행 계획](approved-ui-development-plan.md)과 [검증 기록](approved-ui-validation.md)을 따른다. 미확정 삼성 실측값·임의 범위 계약·thumbnail을 구현된 것으로 바꾸지 않는다.
