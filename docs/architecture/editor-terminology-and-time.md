## 제품 용어 사용 기준 — 2026-10-19

### 우선 원칙: 역할과 대상부터 구분한다

이 기준은 사용자가 같은 기능을 두 이름으로 배우지 않도록 한다. ‘작업파일’과 ‘작품 파일’은 같은 .knolstory/.shortstory 파일이므로 **작품 파일** 하나로 통일한다. 직접 저장·다른 파일로 저장·다운로드는 동작의 차이이며 다른 파일 종류가 아니다. 이전 절에서 만든 ‘브라우저 복구본’은 주 메뉴의 정식 명칭으로 사용하지 않고 **임시 보관**으로 줄인다. 저장 위치와 한계는 도움말에서 설명한다. 이전 용어는 검색 별칭에만 남긴다.

‘읽기 기록’은 읽던 위치와 대사 목록을 혼동하므로 새 메뉴명으로 쓰지 않는다. ‘원고 기록’은 대상이 불분명하므로 ‘이전 원고’로 쓴다. 구현 문서에서 내부 저장 계약을 설명할 때만 기존 식별자를 병기한다.

### 스토리 게임에서 참고한 구분

Ren’Py는 [게임 상태 저장·불러오기](https://www.renpy.org/doc/html/save_load_rollback.html)와 [이미 본 대사를 다시 보여 주는 History](https://www.renpy.org/doc/html/history.html)를 별도 기능으로 정의한다. [공식 한국어 화면 번역](https://github.com/renpy/renpy/blob/master/launcher/game/tl/korean/screens.rpy)의 지난 대사록 개념도 참고했다. [STEINS;GATE 공식 지원 안내](https://www.nitroplus.co.jp/support/sp20/sp20a/) 역시 세이브 데이터와 백로그를 별도로 다룬다. 이 구분을 읽기 UI의 저장·불러오기·지난기록에 적용하며, 작품을 만드는 편집기의 파일 저장까지 게임 진행 저장과 같은 의미로 쓰지는 않는다. 렌더링·저장 구현은 현행 Core/Web 계약 그대로이며 Ren’Py 엔진 저장 방식으로 교체하지 않는다.

### 이름·문장 운영 규칙

1. **같은 대상은 같은 이름으로 부른다.** 저장 위치나 구현 방식이 다르다고 사용자가 배워야 할 파일 종류를 새로 만들지 않는다.
2. **상위 기능과 동작을 구분한다.** 파일의 이름은 ‘작품 파일’, 동작은 ‘저장·다른 파일로 저장·내보내기·가져오기’다. 버튼 수를 줄이는 후속 UI에서도 기능이 다른 경우만 구분한다.
3. **짧은 메뉴, 구체적인 설명.** 메뉴에 저장 구현을 길게 넣지 않는다. 임시 보관의 브라우저 위치·삭제 위험은 설명에서 밝히고 파일 저장 완료처럼 표시하지 않는다.
4. **실제 대상과 결과를 밝힌다.** 연결 안내에는 장·컷·선택 문구 또는 점수 이름·비교값을 넣는다. 오류에는 실패 동작·원고가 남은 위치·다음 행동을 적는다.
5. 설명은 ‘~해요’, 요청은 ‘~해 주세요’를 사용한다. 예시는 ‘예:’로 표시하며 사용자 원고에 자동 주입하지 않는다.
6. 이전 이름·기술어는 검색 가능하게 유지하되 접힌 ‘이전 이름·검색어’에서만 보여 준다. 사용자 원고·인물 이름·자료 ID·파일 키·이전 증거를 일괄 치환하지 않는다.
7. 변경할 때 메뉴·버튼·상태·도움말·접근성 이름·용어 안내·관련 검사를 함께 대조한다. 외부 양식의 고정 값 변경은 별도 호환·외부 앱 검증 대상이다.

## 범위와 기준

- 화자→말하는 인물, 자산→작품 자료, 무대 구성→인물 배치, 프리셋→추천 설정, 환경음→주변 소리(환경음), 점수 ‘설정’→‘이 값으로 바꾸기’, 하나 이상 만족→하나라도 만족을 사용한다. 장·컷은 현재 저작 단위를 유지하며 안내에서 뜻을 설명한다.
- 앱·새 Excel/Google 시트의 한글 이름·설명·선택 목록을 같은 의미로 맞춘다. 사용자 원고·인물 이름·자유 글·자료 ID를 번역하지 않는다. 이전 양식의 한글 선택 값은 좁은 별칭 변환으로 읽는다.
- 용어 안내는 편집 화면의 버튼으로 연다. 이름/이전 이름/설명/예시 검색, 분류, Esc/닫기, 키보드 포커스 복귀를 지원하며 원고 편집 상태를 바꾸지 않는다.
- 시간은 **초**로 입력한다. 0.1초·0.23초·0.001초는 내부100ms·230ms·1ms에 해당한다. 일반 편집 입력은 소수 셋째 자리까지 지원하며, 기존 더 세밀한 값은 변경하지 않으면 그대로 보존한다. 빈 값·음수·범위 밖 값은 원고에 반영하지 않는다.
- StoryDocument6/archive2/JSONB payload1의 시간 필드와 내부 ms 키는 유지한다. 새 workbook4의 표시/입력 단위만 초로 변경한다. 이전 workbook2/3은 시간 값이ms였음을 확인하고 명시적으로 변환한다. 이전230을230초로 해석하지 않는다.

## 2026-10-11 기능이 드러나는 이름 보완

읽기·편집의 보조 기능은 실행 결과가 드러나는 이름을 사용한다. 사용자 원고·인물 이름·자료 ID·Flow·Stage·연출 필드는 이 변경으로 바꾸지 않는다.

| 이전 표현 | 현재 표현·설명 | 실제 기능 |
|---|---|---|
| 현재 컷을 글자로 읽기 | 대사·해설 텍스트 보기 / 장면에 표시된 글을 읽거나 복사할 수 있어요. | 같은 RuntimeScene의 대사와 선택지를 DOM으로 제공하는 접근성 보조 정보 |
| 글과 장면 더 보기 | 이 컷의 글·배경·연결 정보 | 앞뒤 컷의 본문, 실제 배경 이름, 연결 유형 보기 |
| 선택지 점수·사용 조건 | 점수 변화·표시 조건 | 선택 시 점수 변화와 조건을 만족할 때만 나타나는 선택지 편집 |
| 강조 초기화 | 밝기·투명도 초기화 | 해당 방향 인물의 밝기·투명도·반투명 표현만 기본값으로 복원 |
| 효과 변경 취소 | 마지막 효과 변경 취소 | 가장 최근 효과 변경 한 번만 되돌리기 |
| 지연 후 | 컷 시작 후 대기 | 지정한 대기 시간 뒤 효과 시작 |
| 빈 작품 시작 | 새 작품 생성 | 기존 작품을 보관하고 글·배경·인물이 없는 새 작품 생성 |

선택지의 점수 편집은 바깥의 ‘선택 결과·표시 조건’을 한 번 펼치면 바로 나타나며, 같은 기능을 두 번 접고 펴지 않는다. 배경 표시 이름은 컷→장→작품 기본 배경의 현재 해석 순서를 따라 찾고, 자료 ID 자체를 사용자에게 제목처럼 노출하지 않는다. 이 절은 용어 변경의 기준이며 실행 검증 결과는 [승인 개편 검증](approved-ui-validation.md)의 현행 기록과 구분한다.

## 남은 후속 범위

| 목표 | 상태·우선순위 | 의존성 | 완료 조건 |
|---|---|---|---|
| 소리 보강 | 후보 P2 | 사용자가 선택할 장소/사건/곡 분위기와 권리·제작 경로 | 실제 미리 듣기와 작품별 혼합/반복 검증 후 안정적인 새 ID로 등록; 기존 자료를 임의 교체하지 않음 |
| 실제 기기·보조 기술 | 미검증 P2 | 학교 PC/Chromebook/Android·스크린리더 환경 | 양 방향 조작·팝업 키보드·시간 입력·복구·소리 청취 증거 |
| 서버·학급 | 미구현 P1 | 기존 STATUS의 운영·권한·배포 결정 | 별도 서버 목표의 계약/권한/복원 통합 검증 |

전달 점검: 정확성4(실제 파일/외부 앱/네이티브 증거), 완결성4(요청 UI/형식/목록 완료·실기기 별도), 명료성4(이전 이름 검색과 예시 제공), 실행 가능성4(현재 양식과 앱에 적용), 간결성4(현행 계약과 과거 증거를 분리). 평균4.0. 다음 개선은 실제 사용자 관찰과 소리 청취·보강이며, 이번 검증을 전문 음향 승인이나 서비스 배포로 확대하지 않는다.

추가 보완: 무대 제목은 장면 미리보기, 실제 실행은 이 컷부터 재생, 보기 메뉴는 화면·대본 설정, 비율 선택은 미리보기 화면 비율로 구분한다. 말하는 위치는 장면 속 화자, 패널 접기는 글 편집 영역 접기로 명명한다. 실제 겹침 교정과 새 검증은 [기능 이름·겹침 기록](ui-clarity-and-overlap-validation.md)을 따른다.
