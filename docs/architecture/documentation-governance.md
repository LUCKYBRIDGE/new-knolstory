# 문서·지침·계획 변경 관리

현재 개발의 기준은 구현·사용자 결정·검증 증거를 함께 확인한 상태다. 계획은 다음 행동의 근거이며 수정할 수 있다. 과거 계획이나 검증 수치를 현재 사실로 취급하지 않는다.

## 사실별 소유 문서

| 역할 | 정식 소유 문서 | 기록할 내용 |
|---|---|---|
| 실행 규칙 | [AGENTS](../../AGENTS.md) | 책임 경계, 보존 원칙, 읽기 순서, 정식 문서 연결 |
| 현재 상태 | [STATUS](../../STATUS.md) | 구현/부분/미구현/미검증, 다음 목표, 미확정 정책, 의도적 폐기 |
| 구조와 위치 | [최종 구조](knolstory-final-architecture.md) | 모듈 책임·탐색 위치. 전체 단계는 [Blueprint](development-blueprint.md) |
| 디자인 | [DESIGN](../../DESIGN.md) | 현행 UX/반응형/가독성 기준과 의도적 공간 여백 |
| 데이터 계약 | [저장 계약](authoring-storage-contract.md), [양식](authoring-workbook-v2.md) | 타입·버전·빈 값·참조·보존·입출력 조건 |
| 제품 완성 목표/단계 간 실행 | [목표](product-completion-goal-2026-10-15.md), [단일 실행 계획](product-completion-plan.md) | 목표는 안정된 범위/완료 기준, 실행 계획은 작업 ID/의존성/재개/질문만 소유. 제품 상태·세부 계약·증거는 복제하지 않음 |
| 목표별 실행 계획 | [저작 형식 계획](authoring-format-development-plan.md) 및 해당 기능 계획 | 범위·의존성·우선순위·완료 조건. 완료 후 다음 목표를 별도 구분 |
| 결정·역사 | [ADRs](../decisions/README.md), [STATUS 이력](../archive/status-history-through-2026-10-10.md), 날짜가 있는 감사/로그 | 결정 이유·대체 범위·당시 실행 결과. 현재 수치로 덮어쓰지 않음 |
| 작업 절차 | 프로젝트 `.agents/skills/*/SKILL.md` | 조건별 확인·구현·검증 순서와 정식 계약 링크. 현재 상태/테스트 수치 복제 금지 |

같은 사실을 여러 파일에서 독립 관리하지 않는다. 다른 파일에는 요약과 소유 문서 링크를 둔다. 통용 지침·프레임워크 생성 지침·프로젝트 규칙의 범위를 구분하고, 이 프로젝트 작업으로 공유/전역 설정을 임의 수정하지 않는다.

## 변경이 생겼을 때

1. **변경 이유와 성격을 확인한다.** 사용자 요구, 의도한 개선, 결함, 실험 또는 미확정 정책인가? 새 요구를 과거 계획에 억지로 맞추지 않는다.
2. **현재 증거를 확인한다.** 코드·테스트·artifact·실제 앱/서버 상태를 확인한다. 문서의 명령이나 오래된 성공 로그만으로 실행/배포 완료를 판단하지 않는다.
3. **소유 문서를 갱신한다.** 구조→map, UX→DESIGN, 타입/형식→계약, 범위/우선순위/의존성→계획·STATUS. 하나의 변경에서 필요한 문서/스킬을 함께 수정한다.
4. **보존과 정책 영향을 분리한다.** 문서/ID/Flow/Stage 의미나 저장 형식을 바꾸면 버전·명시적 migration·기존 작품 검사 조건을 정한다. 운영·권한·제출 정책은 미확정이면 승인된 것으로 만들지 않는다.
5. **새 완료 조건을 작성하고 검증한다.** 범위 추가/축소/대체의 이유를 날짜와 함께 기록한다. 실패·제외·실기기/외부 앱 미검증을 그대로 구분한다. 원래 목표를 이미 구현한 쉬운 부분으로 축소해 완료하지 않는다.
6. **기록과 참조를 맞춘다.** 중요한 책임/정책/폐기 결정은 ADR을 새로 쓰거나 부분 대체 범위를 명시한다. 이전 ADR/로그는 당시 기록으로 남기며, active 문서에는 새 기준 링크를 둔다.

일반적인 구현 선택과 되돌릴 수 있는 문서 정리는 이미 승인된 작업 안에서 진행한다. 미확정 운영 정책, 손실 가능한 migration 또는 필요한 외부 권한이 없을 때만 구체적인 결과와 이유를 제시하고 사용자 결정을 요청한다.

## 현재 형식 우선

작품 생성·수정·연출에 충분하고 읽기 쉬운 현재 형식·구성이 최우선이다. 과거 파일 호환을 위해 현재 모델이나 UX 개선을 막지 않는다. 기존 Next 저작 내용의 손실 위험은 별도로 검증·변환하며, 구형 codec 복원은 명시적인 요청 범위에서만 다룬다.

## 계획을 유연하게 유지하기

각 목표에는 상태·우선순위·의존성·완료 조건·증거 위치를 둔다. 새 요청이 들어오면 진행 중 목표를 유지하면서 바뀐 부분을 반영하고, 사용자가 취소/대체한 경우에만 원래 목표를 폐기한다. 선택하지 않은 대안이나 폐기한 기능은 무조건 복원하지 않는다. 짧은 목표 프롬프트는 상세 계획을 참조하며 상세 내용을 중복하지 않는다.

완료 기록은 기록 당시 범위에서 보존한다. 이후 코드가 바뀌면 해당 증거를 현재 변경의 증거로 자동 재사용하지 않는다. artifact hash가 포함된 과거 manifest도 재생성하지 않고, 필요하면 새 검증 기록을 만든다.

## 가벼운 확인

`pnpm docs:check`는 현재 진입 문서·ADRs·프로젝트 스킬의 로컬 Markdown 링크와 현재 문서·Web 소스의 명확한 이전 용어를 검사한다. `pnpm test:docs`는 검사기 자체를 확인한다. semantic drift, 사용자 결정, 실제 runtime·원격 PR·배포·권한 상태까지 자동 증명하는 검사는 아니다.

문서/스킬만 변경하면 링크·diff·관련 절차를 확인한다. 코드 계약이나 동작까지 변경한 경우에만 해당 unit/integration/E2E와 실제 외부 앱 gate를 수행한다. Runtime을 다시 만들 때는 `runtime:build → build → 검증`을 순서대로 실행한다. public/runtime를 쓰는 빌드와 정적 export를 병렬 실행하지 않는다.

## 2026-10-10 정리 결과

STATUS의 긴 일지는 archive로 옮기고 현재 구현·한계·다음 목표만 남겼다. 현재 형식 우선/legacy codec 제외는 ADR0016에 기록해 ADR0009/0010의 일부 조건을 대체했다. Blueprint/README/구조/matrix/준비 안내와 프로젝트 스킬12개를 현재 계약으로 연결했다. 초기 고정 probe·후보 명령·오래된 PR 상태와 현재 구현을 구분했다. Next.js가 관리하는 하위 AGENTS 블록과 공유/전역 스킬은 유지했다.

검증: active 문서42개 로컬 링크 오류0, 검사기3개 테스트 통과, 검사기 line86.49%/branch83.33% coverage, 변경 검사기 ESLint와 diff check 통과. 이번 문서 정리에서는 앱 동작이나 저작 데이터를 변경하지 않았으므로 이전 제품 회귀 수치를 새 실행 결과로 주장하지 않는다. 이전 형식 완료 manifest의 당시 hash도 다시 쓰지 않았다.

## 제품 용어와 개발 문서의 일치

용어 의미의 소유자는 [제품 용어 사용 기준](editor-terminology-and-time.md#제품-용어-사용-기준--2026-10-19)이며, 다른 계약·설계·실행 계획·스킬은 이를 참조한다. 사용자 화면의 파일 저장과 내부 DB/persistence의 저장, 독자의 진행 저장을 같은 기능으로 해석하지 않는다. 새 용어를 만들기 전에 대상과 동작이 기존 용어와 실제로 다른지 확인한다. 변경 시 화면·도움말·상태·접근성 이름·용어 안내·현재 문서·관련 검사를 함께 대조한다.

`pnpm docs:check`는 링크와 함께 [용어 검사](../../scripts/check-product-language.mjs)를 실행한다. 현재 진입 문서·일반 문서·프로젝트 스킬·Web 화면 소스에 남은 명확한 이전 이름을 확인한다. `pnpm test:docs`는 링크/용어 검사기의 보호 규칙을 확인하며 CI에서도 같은 명령을 사용한다. 문맥상 의미의 일치, 동적 메시지·모든 서버 오류·외부 앱 표시는 별도 검토 대상이다.

과거 evidence/archive/ADR와 검증·감사·참고 자료는 당시 기록으로 유지한다. 링크 대상·기존 heading anchor·코드 예제·원문 인용도 자동 치환하지 않는다. 현재 문서에 원문을 보존해야 할 때는 blockquote 또는 `<!-- language-history -->`와 `<!-- /language-history -->` 사이에 놓고 이유·현재 기준 링크를 함께 적는다. 이 표시는 현재 지침을 검사에서 숨기는 용도로 쓰지 않는다. 용어 소유 문서는 이전 표현과 정식 용어를 비교해야 하므로 자동 금칙어 검사에서 제외하지만 의미 검토는 필수다. 검색 별칭도 의도한 과거 표현으로 보존한다.
