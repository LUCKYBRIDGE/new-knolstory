## 판단할 점

같은 비교 원고는 세로390×844에서2페이지, 가로844×390에서1페이지였다. 세로가 항상 더 많은 텍스트를 담지는 않는다. 가로는 한 줄이 길고, 세로는 화자 한 명을 크게 보여주는 장점이 있다.

세로는 현재 화자에 연결된 인물만 중앙에 표시한다. 가로는 좌우 배치와 청자 이미지를 유지한다. 해설처럼 연결된 화자가 없을 때 세로에서 배경만 표시하는 기존 동작도 별도 캡처했다. 해설에 직전 화자를 남길지는 아직 정하지 않았다.

후보 추천: 가로/세로 모두 지원하되 세로는 화자 집중, 가로는 대화 장면 유지. 세로 약4줄/가로 약3줄을 기준으로 문장 경계를 우선하며 원고·인물 좌표는 수정하지 않는다. 이 숫자는 화면 검토용 시작점이며 최적값으로 확정한 것은 아니다.

## 증거 범위

순수 함수12개 테스트 안에 고정 시드 무작위1000사례를 포함했다. 실제Ren’Py에서 글10종×화면3종=30경우, 실제Core인물구도6경우와 세로페이지넘김3경우를 확인했다. 상자위인물픽셀 불변과 원문보존·분할한계·문자묶음·반복회전의읽던위치를 검사했다. 물리기기·실제청취·보조기술 전체검증은 아니다.

추가페이지캡처 첫실패는 테스트가화자예시간동일cutID를재사용해읽던페이지를유지한결과이며, 새읽기ID로고쳐검증했다. 실패기록은보존했다. Core기본배치와사용자원고는변경하지않았다.


## 하단 여백 수정

앞선 캡처는 펼친 읽기 도구용70px 공간을 확보하고 도구를 제외해 여백이 과하게 보였다. 최신 HTML 갤러리는 실제 기본 접힌 상태의8px 기준으로 수정했다. [전후 비교](../mobile-bottom-gap-2026-10-18/comparison.png), [검증 근거](../mobile-bottom-gap-2026-10-18/checkpoint.json). 기존 PNG는 당시 기록으로 남긴다. 인물 좌표·크기는6경우모두같으며 세로상자는62px, 가로상자는32px아래로이동했다. 펼친도구는세로58px이므로70px확보를유지해야한다.


## 최신 사용자 수정 — 큰 글 상자 우선

모바일 글 상자를 더 크게 허용하며 작은 상자 때문에 억지로 두 페이지로 나누지 않는다. [최신 비교 목업](../mobile-generous-text-2026-10-18/comparison.png), [근거](../mobile-generous-text-2026-10-18/checkpoint.json). 이전2페이지였던샘플과더긴샘플모두한페이지로표시했다. 이전PNG는당시검토기록이다. 운영에는아직미배포.
