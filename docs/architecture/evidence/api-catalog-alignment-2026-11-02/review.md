# Web와 온라인 업로드의 자료 목록 일치

2026-11-02. 새 그림을 사용하는 현재 작품은 Web에서 편집·파일 저장·읽기가 가능했지만, 운영 API 이미지는10월31일의421그림 목록을 갖고 있었다. 실제 운영 번들에서 기존그림은 허용하고 새11그림은 모두 거절하는 것을 재현했다. 서버의 `checkedSnapshot`은 이를 `CATALOG_MEDIA_REQUIRED`422로 변환한다.

## 수정과 검증

API만 현행 소스로 빌드·교체했다. DB 백업과 기존API 되돌리기 이미지를 먼저 보존했으며 스키마 변경이나 데이터 쓰기는 수행하지 않았다. 갱신 전후11테이블의 행 수·정렬된 행 내용 해시가 같았다. 현재 실제 실행 중인 이미지가 새432그림을 모두 허용하며, 미등록 그림 거절은 유지한다.

[검사 도구](../../../../server/operations/check-image-catalog.mjs)는 API이미지를 네트워크 없는 읽기 전용 컨테이너에서 확인한다. 번들을 메모리에서 읽어 검토한 `main()` 호출만 실행하지 않고 등록그림 허용 함수를 호출한다. 서비스·DB·인증은 시작하지 않으며 원본이미지 파일은 수정하지 않는다. 새번들의 진입점이 바뀌면 자동 추측하지 않고 실패한다.

```sh
node server/operations/check-image-catalog.mjs knolstory-next-api:production .cache/production-catalog-review.json
pnpm exec vitest run server/documents/catalog-current.test.ts
```

제공8판본의 현행 스냅샷을 서버 validator로 왕복하고 미등록 인물422거절을 확인했다. 실제 주소의 익명GET은 인증설정200·작품목록401이었다. 이 증거는 사람이 카카오로 로그인해 작품을 업로드한 검사를 대신하지 않는다. 그 검사는 이전 온라인 후속 큐에 유지한다.

## 다음 배포의 필수 연결

새 자산ID·저작형식 허용값을 공개할 때 Web/Pages만 갱신해 온라인 API의 validator를 뒤에 남기지 않는다. 새API 후보를 위 도구로 검사하고 백업·되돌리기·기동상태·DB보존을 확인한다. API를 사용하지 않는 정적 로컬 편집 개발/빌드에 운영 서버 접속을 강제하지 않는다.

최종 판정은 [체크포인트](checkpoint.json), 이전/후 이미지 정책·상태·데이터 보존은 같은 폴더의JSON을 따른다. 비공개 DB 백업과 상세 행 해시는 이 Mac의 보호된 로컬 보관 위치에만 남긴다.
