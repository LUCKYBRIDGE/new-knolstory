# 별주부전 선택·합류 서사 재검토

2026-11-01. 실제 `resolveProvidedCatalogStory` 결과의 292컷을 읽고 첫 초대 두 갈래, 용궁 판정 두 갈래와 육지에서의 마지막 선택을 대조했다. 완결 경로는 6개이고 결말은 3개다. 앞선 번호·제목 교정은 실제 연결이나 사건을 재배치하지 않았다.

## 선택과 합류

- `start:57`에서 잔치 손님 초대(`obey`) 또는 병든 이를 도와달라는 요청(`hesitate`) 중 하나만 말한다. 전자는 15컷에서 음식·볼거리와 귀빈 초대를, 후자는 15컷에서 병과 도움을 이야기한다. ‘바다의 숨결’을 함께 지니고 등에 타는 상태는 두 경로에서 같다.
- `sea-route:0` 합류 후 토끼가 바닷속을 구경하고 용궁에 도착하는 사건은 두 초대 모두에 성립한다. 다만 합류 뒤 토끼가 자기가 듣지 않은 초대까지 기억하는 공통 대사는 아래와 같이 바로잡는다.
- `palace:52`의 진실 선택은 토끼가 끌려가고 용왕이 회복하는 결말이다. 자라가 처음부터 감춘 사실의 책임을 없애지 않는다.
- `shield`는 간을 확인하겠다는 구실로 토끼를 풀어 육지까지 데려간다. 자라는 이미 간 이야기가 거짓임을 알고 있으며, 해변에서 “알고 있었소”라고 고백하는 것은 그 선택과 맞는다.
- 해변의 `exile`은 용궁에 설명하지 않고 남는 결말, `return`은 돌아가 거짓을 고백하고 용왕에게 징표를 돌려준 뒤 강으로 떠나는 결말이다. 세 결말 사이를 잘못 연결하거나 토끼를 두 번 구하는 사건은 없다.
- ‘바다의 숨결’은 어린 자라를 짠물에서 살게 한 징표다. 용궁과 결별한 두 결말에서 이를 잃고 강물에서 사는 결과는 앞선 설정에 맞는다. 원작 토끼의 간 거짓말과 각색의 윤리적 갈등은 의도된 이야기 장치로 보존한다.

## 확인된 공통 대사의 선택 기억 누출

| 컷 ID 끝부분 | 수정 전 | 수정 후 |
|---|---|---|
| `palace:3` | 이상하군. / 잔치라면 상부터 보여야 하고… | 이상하군. / 반기는 사람이 하나도 없소. |
| `palace:4` | 병자를 만나러 왔다면 병자부터 보여야 하는 것 아니오? | 용궁에서는 손님을 이렇게 맞는 것이오? |
| `palace:15` | 자라 선생. / 잔치 이야기를 했든… | 자라 선생. |
| `palace:16` | 병든 이를 도와달라고 했든… | 나를 이곳에 데려오면서… |

전체 ID 접두사는 `review-main-002:`이다. `/`는 표 안에서 줄바꿈을 뜻한다. 토끼가 잔치를 들었다면 도움 요청까지 회상할 이유가 없고 반대도 같다. 이를 두 경로 모두에 맞는 질문과 비판으로 바꾼다. 뒤의 `palace:17~18`에서 “가장 중요한 이야기”, “내가 죽을 수도 있다는 말”을 빠뜨렸다는 비판은 그대로 이어진다. 별도 컷·점수·조건을 추가하거나 두 갈래를 새로 나눌 필요는 없다.

`palace:1`에서 해설자가 잔치 음식이 없음을 관찰하는 것은 자라의 서술이며, 자라는 용왕이 두 가지 구실을 허용했던 사실을 모두 알고 있다. 토끼 자신의 경험을 단정하는 위 네 컷과 구분하여 그대로 둔다.

## 검증 경계

본문 수동 대조와 모든 경로의 연결 열거를 했으며, 수정 후에는 Runtime Core로 두 초대 각각의 세 결말을 실제 진행시키는 회귀 검사를 추가한다. 이 검사는 6경로의 실제 Ren’Py 화면 전체 재생과 다르다. 구현·검사·배포 상태는 [체크포인트](checkpoint.json)가 소유한다. 기존 fixture·과거 교정 목록·개인 수정본은 덮어쓰지 않는다.
