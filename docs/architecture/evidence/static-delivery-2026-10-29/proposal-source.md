# 뉴놀스토리 웹 배포·공용 자산·작품 데이터 아키텍처 정리

- 작성일: 2026-10-29
- 대상: `LUCKYBRIDGE/new-knolstory`
- 문서 성격: 사용자와 논의한 목표 아키텍처 및 단계별 실행 제안. **구현 완료 또는 배포 승인 문서가 아님.**
- 우선 목표: **작품 읽기와 편집의 완성**. 로그인·온라인 저장·학급·과제·공유 기능은 별도로 단계화한다.

## 1. 핵심 결정 방향

뉴놀스토리의 공용 작품 이미지, 표지, BGM, 효과음, 글꼴, Ren’Py Web 실행 파일은 **정적 웹 호스팅 및 CDN**을 통해 제공한다. 사용자의 브라우저는 작품 문서에 들어 있는 **자산 ID와 재생·배치 설정**을 해석하고, 공용 자산을 필요한 시점에 다운로드하여 읽기와 편집에 사용한다.

서버와 DB의 주된 역할은 로그인, 사용자별 작품 문서, 접근 권한, 온라인 저장, 버전 및 수정 기록 관리다. **공용 이미지·음원 원본을 작품별로 DB에 중복 저장하지 않는다.** 사용자가 직접 추가한 개인 미디어는 별도의 보존 정책을 따른다.

중요한 운영 목표: 개발용 Mac mini의 서버가 중단되어도 **배포된 공개 작품의 읽기와 브라우저 로컬 편집·파일 저장은 가능한 구조**를 지향한다. 단, 로그인/온라인 저장 등 서버 기능은 중단될 수 있음을 사용자에게 명확히 안내해야 한다.

## 2. 제안 구조

```text
                      사용자 브라우저
                  ┌───────────────────┐
                  │ 서재·읽기·작품 편집 │
                  │ Runtime Core       │
                  │ Ren’Py Web         │
                  │ IndexedDB/파일 저장 │
                  └────────┬──────────┘
                     ┌─────┴─────┐
                     ▼           ▼
     정적 웹 배포 / CDN              온라인 API (선택 기능)
     Cloudflare Pages             Cloudflare Tunnel
     + 필요 시 R2                 → Mac mini Docker
       - 웹앱                      → PostgreSQL
       - 공용 이미지·표지             - 사용자·권한
       - 공용 BGM·효과음             - 작품 JSON/버전
       - 폰트·아이콘                - 온라인 저장/복원
       - Ren’Py Web 빌드
       - 공개 작품 문서
```

- CDN에 배포하는 것은 공용 자료 및 재배포 권한이 확보된 파일로 제한한다.
- R2는 **선택지**다. Pages 정적 호스팅만으로 적절하다면 별도 R2가 필수는 아니다.
- GitHub는 소스·자산 목록·배포 파이프라인의 관리 지점이지만, GitHub 저장소에 업로드했다는 이유만으로 곧바로 정적 사이트에 게시되는 것은 아니다.
- Cloudflare Tunnel은 CDN 자체가 아니라 Mac mini의 API를 외부에서 접근시키는 연결 수단이다.
- 사용자별 원고와 수정 내용은 구조화된 JSON이며, 대사 외에도 분기 조건·장면 구성·좌표·시간·연출·오디오 ID를 포함한다.

## 3. 자산별 저장 및 전달 원칙

| 종류 | 권장 보관·배포 | 읽기/편집 시 사용 | 검토 사항 |
|---|---|---|---|
| 작품 이미지·배경·표지 | Pages/CDN, 필요 시 R2 | 현재 장면 우선 로딩, 다음 장면 프리로드; 편집기에는 썸네일 | 저작권, 용량, 포맷, 캐시 |
| 인물·표정 이미지 | Pages/CDN 또는 R2 | 화면 표시 전에 선택적 프리로드 | 고해상도와 썸네일 분리 |
| 공용 BGM | Pages/CDN 또는 R2 | 현재 cue에 따라 온디맨드 로딩, 재생 중 캐시 유지 | 반복·구간·볼륨·오디오 활성화 |
| 효과음·환경음 | Pages/CDN 또는 R2 | 현재/다음 장면 중심 로딩, 자주 쓰는 소리 캐시 | 지연·겹침·음량 |
| 폰트·아이콘 | 정적 웹 배포 | 핵심 UI 먼저 로딩 | 라이선스, 폰트 서브셋 |
| Ren’Py Web/WASM 런타임 | 정적 웹 배포 | 실행 시 초기화, 브라우저 캐시 | 초기 용량, 모바일 성능 |
| 공개 기본 작품 원고 | 정적 문서 또는 콘텐츠 API | 선택한 작품 문서 로딩 | 자산 ID/스키마 버전 |
| 개인 작품 원고·분기·연출 | 로컬 저장 + 선택적 API/DB | 읽기와 편집이 동일 문서를 해석 | 충돌·버전·백업 |
| 사용자 직접 추가한 미디어 | 기존 파일 첨부 계약 / 향후 별도 객체 저장 | 작품에 종속된 권한 있는 미디어 | 전송·용량·보존·권리 |
| 테스트 로그·스크린샷 | 개발 환경 | 서비스 대상 아님 | 개인정보·작품 원본 노출 |

## 4. 실제 현재 구현과 구분해야 할 사실

2026-10-29 기준 GitHub `main`에 기록된 내용:

1. `story.knolquiz.com`은 2026-10-17 배포 전환 기록상 Cloudflare Pages에서 **Cloudflare Tunnel → Mac mini Docker**로 연결이 변경됐다. 이것은 현재 기록의 내용이며, 현재 외부 서비스의 실제 응답/배포된 바이너리까지 재검증했다는 의미는 아니다.
2. `new-knolstory` 소스에는 로컬 편집/작품 파일 관리/읽기·Ren’Py 연결 및 자산 ID 기반 등록 구조가 있다.
3. 기존 작품 이미지 **421개**와 서재·소개 UI 이미지 **10개**는 README상 기존 `story-maker` 체크아웃으로부터 로컬 복원하는 절차가 필요하다. 권리 확인이 안 된 이미지와 스크린샷을 GitHub에서 제외하는 정책이 있다.
4. 공용 음원 카탈로그는 기록상 **530개(CC0 516개 + 조건부 Pixabay 14개)**이며, 추가 CC0 **469개**는 별도 Release 패키지로 복원한다. `StoryDocument`에는 공용 음원 파일 자체가 아니라 ID·cue가 기록된다. 기존 온디맨드 음원 전달 및 Ren’Py 캐시 구조를 살린다.
5. GitHub 소스 반영과 CDN 자산 배포·실서비스 가동·실기기 검증은 별개다.
6. 온라인 저장/학급/공유 등은 제품 완성 실행 계획에서 별도 후속 항목이다.

**주의:** 현재 사이트에서 실제로 어떤 이미지/음원이 어느 호스트에서 제공되는지는 배포 환경의 Network 요청, 파일 응답 헤더 및 배포 산출물을 통해 별도 확인해야 한다. 현재 문서만으로 모든 파일이 Mac mini에서 제공된다고 단정하지 않는다.

## 5. 읽기·편집 로딩 정책

### 5.1 읽기

- 서재에서 작품 선택 전: 기본 UI·작은 표지 이미지만 로딩.
- 작품 선택 직후: 해당 원고, 첫 장면의 이미지·필수 음원과 실행 자산을 우선 준비.
- 읽기 중: 다음 장면 또는 실제 선택 가능한 갈래의 가까운 자산을 제한적으로 프리로드.
- 읽지 않을 작품의 전체 이미지·530개 음원 전체를 선행 다운로드하지 않음.
- BGM은 재생이 이어지는 동안 보존하고, 오디오 자동재생 제한을 고려한 사용자 활성화 UI를 유지.
- 요청 오류/느린 망에서 재시도·실패 안내·복귀 수단 제공.

### 5.2 편집

- 이미지 선택 목록: 작은 썸네일 우선, 실제 배치·미리보기에서 필요한 해상도만 요청.
- 음원 선택 목록: 메타데이터(제목·분류·길이·권리 등)를 먼저 노출하고 미리 듣는 파일만 요청.
- 읽기와 편집이 동일 Asset ID 및 URL 해석 규칙을 사용하도록 통일.
- 새 작품 작성→이미지·BGM·효과음 설정→Ren’Py 미리보기→파일 저장→새 브라우저에서 재열기까지 검증.

### 5.3 캐시/최적화

- 이미지: 실제 품질을 비교하며 WebP/AVIF 및 용도별 크기 사용.
- 오디오: 원본·코덱·루프 연결 품질을 개별 검증하고 무분별하게 재인코딩하지 않음.
- 자산에는 버전 또는 콘텐츠 해시 기반 URL을 사용하고 적절한 Cache-Control 설정.
- 성능 지표: 첫 서재 표시, 첫 작품 장면까지의 시간, 장면 전환 대기, 편집기 썸네일 로딩, 오류율·전송량.

## 6. 단계별 실행 계획

### P0 — 실제 배포 상태 조사 및 자산 인벤토리

- [ ] 실제 `story.knolquiz.com`의 웹앱·이미지·음원·WASM 제공 호스트/경로를 Network에서 확인.
- [ ] GitHub 추적 자료, Release 자료, 로컬 복원 자료, 배포 결과물을 서로 대조.
- [ ] 각 이미지/음원의 ID, 경로, 크기, SHA-256, MIME, 사용 작품, 라이선스, 재배포 가능 여부를 표로 정리.
- [ ] 현재 `main`과 배포 후보의 빌드 일치 여부 확인.

### P0 — 배포 가능한 공용 자산 패키지 확립

- [ ] 재배포 권한이 확인된 파일만 정적 호스팅에 배치.
- [ ] 권리 미확인 레거시 이미지는 대체·재제작·권리 확보 중 선택. 임의 공개 금지.
- [ ] 조건부 Pixabay 음원의 이용 범위와 편집기 제공·독립 다운로드 여부 검토.
- [ ] 원본과 서빙용 파일을 분리하되 Asset ID/스토리 원고는 보존.
- [ ] Pages 단독/Pages+R2를 실제 용량·파일 수·업데이트 주기·비용 기준으로 결정.

### P1 — 읽기·편집에서 배포 자산 사용

- [ ] 공통 자산 URL 해석기 및 배포 환경설정 구성.
- [ ] 이미지·음원·폰트·Ren’Py Web 빌드가 CDN에서 제공되는지 확인.
- [ ] 자산 선택·미리듣기·재생·프리로드·캐시/오류 회복 연결.
- [ ] 기존 사용자 파일과 작품 원고의 Asset ID 호환성 유지.
- [ ] 공개 기본 작품은 서버 로그인 없이 읽기 가능하도록 설계.

### P1 — 핵심 제품 완성 검증

- [ ] 기존 8개 판본의 표지→전체 장면→선택지→갈래 엔딩→되돌리기 검증.
- [ ] 새 작품 만들기→장/컷/선택/조건/연출/음원→저장→재열기→실제 Ren’Py 재생 검증.
- [ ] Mac mini 서버를 사용하지 않는 환경에서 공개 작품 읽기·로컬 파일 편집 검증.
- [ ] PC·태블릿·휴대폰 및 느린 네트워크에서 기본 동작과 성능 확인.
- [ ] GitHub Actions/배포 파이프라인에서 정적 자산 누락·해시·경로 검증.

### P2 — 온라인 계정·DB 기능 통합

- [ ] 카카오 및 Google 연결 실환경 동작 검증.
- [ ] 계정별 작품 JSON 저장·버전 충돌·복구·백업.
- [ ] 온라인 기능 장애 시 로컬 작업 보호 및 이후 동기화 정책.
- [ ] 학급·과제·공유 기능은 읽기/편집 1차 완성 이후 별도 목표로 처리.

## 7. 완료 판정

1차 읽기·편집 서비스는 다음 조건을 만족할 때 완료로 판단한다.

- 웹에 배포된 공용 자산만으로 공개 작품을 처음부터 끝까지 재생할 수 있다.
- 모든 필수 이미지·BGM·효과음·선택·분기·연출이 의도대로 동작한다.
- 사용자는 웹에서 새 작품을 작성하고 미리보기·저장·내보내기·재열기 할 수 있다.
- 다른 컴퓨터에서 공용 자산을 별도 수동 복원하지 않고 파일을 열 수 있다.
- 서버 계정 기능이 없는 상황에서도 공개 읽기 및 로컬 편집이 작동한다.
- 자산 권리·보안·호환성·대상 기기·성능이 검증된다.
