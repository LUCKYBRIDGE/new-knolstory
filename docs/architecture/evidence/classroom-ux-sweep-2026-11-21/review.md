# 학생·교사 화면 점검 — 2026-11-21

학급 서비스의 모든 학생·교사 화면을 휴대폰(390×844)과 넓은 화면(1280×860)에서 열어 보고, 사용자 입장에서 이상하거나 헷갈리거나 불편한 점을 찾아 고친 기록이다. 화면은 학급 API를 흉내 낸 E2E 환경(`tests/e2e/classroom.spec.ts`의 학급 mock)으로 열었다. 고친 내용은 PR #59에 있고, 과제 단계·과제별 편집 범위 설계는 [학급 설계](../../classroom-design.md#과제-단계와-과제별-편집-범위--2026-11-21)가 소유한다.

휴대폰 화면 20개를 고친 뒤 모습으로 모은 이미지: [phone-screens.jpg](phone-screens.jpg). 휴대폰 흐름(QR 로그인 성공 → 내 과제, 미션 제출 → 다시 쓰기 → 통과, 학급 설정 전체): [phone-flows.jpg](phone-flows.jpg). 넓은 화면 사진은 PR #59 점검 때 같은 순서로 확인했다.

운영 확인(2026-11-21 배포 뒤): 공개 주소의 학생 로그인·내 과제(실제 학생 계정), 교사·학생·그림책·숏스토리 화면 응답, API 응답을 확인했다. 운영 교사 화면은 공개 주소에 배포된 웹 코드를 그대로 열고 학급 API 응답만 테스트 데이터로 바꿔 확인했다(운영 서버에는 요청하지 않음, 휴대폰·넓은 화면): `새 과제 내기` 하나의 입구, 놀스토리 과제의 `시작 방법`과 `학생이 고칠 수 있는 것`, 과제 카드의 `앞 단계 · … 통과 뒤`와 `고칠 수 있는 것`, 학생 탭의 `학급 기본`이 모두 보였다. 이어서 실제 학급(2026햇반)을 가진 관리자 계정으로 운영 교사 화면을 읽기만 해서 확인했다(학급 25명): `새 과제 내기` 하나의 입구(예전 `작품 쓰기 과제 만들기` 없음), 과제 카드의 `고칠 수 있는 것 · 학급 설정대로`, 놀스토리 과제 양식의 `시작 방법` 두 가지와 `학생이 고칠 수 있는 것` 다섯 가지, 학생 탭의 `학급 기본`. 오류 표시는 없었고 아무것도 만들거나 바꾸지 않았다.

## 기술 점검

- 휴대폰 작성 E2E(`mobile-authoring.spec.ts`)가 변경 전 main에서도 3번 중 1번 실패했다. 설정 메뉴에서 Tab 직후 Escape가 포커스 이동보다 먼저 처리되는 테스트 경합이었고, 포커스가 메뉴 안에 들어온 뒤 Escape를 누르게 해 5회 연속 통과했다.
- 과제 연결(기기 키) 저장과 편집기의 과제 확인 순서를 맞추기 위해 연결을 저장할 때 편집기에 알린다(`bindTaskWork`).

점검은 위 표의 모든 화면을 두 크기에서 마쳤다. 고친 화면은 고친 뒤 다시 찍어 확인했고, 해당 동작은 `tests/e2e/classroom.spec.ts`에 회귀 검사로 남겼다(53개).
