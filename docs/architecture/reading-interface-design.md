## 지난기록의 표시 범위 — 2026-10-20 수정

## 2. 고정 비율과 장면 보존

현재 지원은16:9(1280×720),4:3(1280×960,그림영역1280×720),9:16(720×1280)이다. 자동은 세로에서9:16,가로/정사각에가까운영역의비율1.55미만에서4:3,그외가로에서16:9를 고른다. 읽기 설정과 편집 미리보기에서 직접 선택할 수 있다. 4:3과16:9의 글 분량·페이지 경계는 동일하다.


- Core 논리 무대 후보는 가로1280×720/1280×960, 세로720×1280이다. Web은 사용 가능한 영역에 contain 투영하고 비율 바깥은 차분한 단색 여백으로 둔다. 16:10·4:3·초광폭에서도 장면 늘임·화면 채우기 크롭을 하지 않는다.
- 기본 양식은 사용 가능한 영역의 가로/세로 방향으로 선택한다. 방향이 바뀔 때만 전환하고 브라우저 주소창·미세 resize 때문에 양식을 반복 변경하지 않는다. 세로 키보드 표시 중에는 양식을 잠근다. 정사각형 근처는 직전 양식을 유지하고 첫 진입은 가로를 기본값으로 제안한다.
- 장면은 전체 무대를 차지한다. 글 영역은 무대 안의 하단 오버레이이며 별도 flex/grid 행으로 장면을 밀지 않는다. 전체 무대 contain 축소와 글 영역 때문에 발생하는 인물 축소를 구분한다.
- 배경은 글 영역 뒤까지 이어진다. 인물의 머리/발 좌표·크기·자유 배치는 패널 계산과 독립한다. 겹치는 하체는 가려질 수 있다. 패널을 피하려고 자동으로 인물을 위로 밀거나 작게 만들지 않는다.
- 가로·세로 모두 기존 Core의 해당 양식 투영을 먼저 보존한다. 앞서 논의한 ‘세로는 현재 화자만 중앙’은 비교할 추가 시안이며, 이 종합안의 기본 개편으로 인물 표시 정책을 조용히 바꾸지 않는다. 화자/해설/미연결의 실제 구도를 비교한 뒤 추가 변경이 필요할 때 따로 확정한다. 원고 구도를 수정하거나 임의로 첫 인물을 화자로 고르지 않는다.
- 배경의 기존 cover/contain·초점 설정은 보존한다. 두 양식 전환에 따른 기존 배경 프레이밍과, 패널 때문에 발생하는 재프레이밍을 구분하며 후자는 금지한다.
- 장 정보·메뉴 진입 버튼·본문·도구는 모두 고정 비율 안에 둔다. 바깥 여백에 보조 버튼을 흩어 놓지 않는다. 저장·설정 대화상자는 읽기 진행을 멈춘 상태에서 가독성과 접근성을 위해 호스트 가용 영역까지 사용할 수 있으며, 장면은 그대로 유지한다. 노치/안전 영역과 브라우저 chrome을 제외해 사용 가능한 영역을 계산한다.

## 3. 하단 종이 영역과 글 분량

하단은 기존 크림색 종이 계열의 불투명한 직사각형이다. 좌우 바깥 여백·둥근 모서리·상자 외곽선은 없애고 상단 경계만 약하게 구분한다. 읽기 도구도 같은 종이 영역 안에 둔다. 장면 위 흰 글씨/강한 그림자로 대비를 확보하던 임시 표현은 짙은 글씨로 교체한다.

패널 구성은 위에서부터 화자 → 본문 → 우측 글 넘김 → 한 줄 읽기 도구다. 화자·글 넘김·도구의 자리를 본문4/6줄과 별도로 예약한다. 화자 이름이 길 때도 본문을 밀지 않도록 화자 자리는 고정하고 전체 이름은 접근 가능한 이름/상세로 제공한다.

- 같은 양식·글자 크기 설정에서는 패널 높이를 고정한다. 짧은 대사에서도 줄 수에 따라 높이가 변하지 않는다. 기본값에서 가로4줄·세로6줄과 보조 영역이 들어가도록 실제 NotoSansKR 렌더로 산정한다.

- 자동 줄바꿈·Enter·빈 줄은 모두 실제 표시 줄로 센다. 글자 수는 보조값이며, 한글·영문·이모지·폰트·단어 길이를 무시한 고정 문자 수 제한으로 바꾸지 않는다.
- 페이지 분할은 문장 경계 → 단어 경계 → 공백 없는 긴 문자열의 안전한 글자 묶음 순이다. 원문·공백·Enter를 버리거나 원고 컷을 자동 생성하지 않는다. 지원하지 않는 문자 결합은 별도 검증하고 완전한 국제 문자 분할 지원으로 과장하지 않는다.
- 짧은 한 발화·한 호흡의 해설을 작성하도록 돕되, 최대 줄 수를 채워야 하는 목표로 안내하지 않는다.

### 선택지 팝업 — 2026-10-20 사용자 수정

선택지는 장면과 구분되는 **별도 Ren’Py 모달 팝업**에서 고른다. 어두운 배경막 위 중앙 패널에 짧은 제목과 독립된 선택 버튼을 세로로 배치한다. 본문 마지막 페이지·오디오 시작·전환 완료 뒤에만 팝업을 열고, 떠 있는 동안 장면 입력과 배경 클릭으로 진행하지 않는다. 선택 후 기존 Core의 분기 처리를 따르며, 임의 닫기/취소로 선택을 건너뛰지 않는다. 기본 엔진 저장·환경설정 메뉴는 다시 노출하지 않는다.

기본 2~4개 선택지는 스크롤 없이 한 화면에서 모두 읽고 고르는 것을 우선한다. 실제 Noto Sans KR 렌더 높이를 측정해 패널 폭을 먼저 넓히고, 필요한 때 글자 크기를34/32에서 최소24까지 조정한다. 버튼 최소 높이는 논리96이며, 긴 문구를 자르거나 말줄임하지 않는다. 지원하는 문구 상한까지의 극단적인 길이는 한 화면에 모두 담을 수 없으므로 그 경우에만 팝업 내부 목록과 스크롤바를 사용한다. 일반 문구에는 스크롤바·드래그 스크롤을 켜지 않는다. 가로1280×720/세로720×1280을 모두 확인하며 원고·장면·본문 패널의 크기와 배치를 팝업에 맞춰 바꾸지 않는다.

밝은 본문/민트 강조와 어두운 녹색 패널을 기존 읽기 톤에 맞추고 마우스 올림·키보드 초점 상태를 밝은 버튼으로 구분한다. 첫 항목부터 방향키/Enter로 선택할 수 있고 마지막 항목도 접근 가능해야 한다. 실제 모달 입력·가로/세로 긴 문구의 무스크롤·배경 차단은 native에서 확인한다. 이 수정은 이전의 본문 위 고정 높이 종이색 선택 패널을 대체한다.

`‹ 이전`은 같은 컷 안의 글 페이지 이동이며 이야기 경로 되돌리기가 아니다. 이전 페이지가 없으면 숨긴다. 글 페이지를 바꿔도 인물 motion·효과·BGM·점수/선택 기록을 다시 실행하지 않는다. 자동 읽기도 같은 진행 경로를 사용한다.

회전·양식 전환은 원문의 읽던 위치를 기준으로 재분할할 수 있다. 글자 크기 변경은 페이지와 글 위치를 그대로 유지한다. 읽기 저장/불러오기·빠른 저장·재열기에서 컷 내 위치를 복원할 수 있는지는 기존 저장 계약을 확인한 후 구현한다. 저장 구조 변경이 필요하면 기존 기록을 보존하는 명시적 migration을 둔다. 새 필드가 없는 기록은 해당 컷 첫 페이지로 복원한다. 메모리 안 회전 유지와 영속 저장 복원을 혼동하지 않는다.

## 5. 상단과 읽기 도구

읽기 좌측은 `1장 · 계곡`만 표시한다. 장 제목이 없으면 번호만 사용한다. 작품명·작가·컷 번호·편집 모드·진단은 읽기에 상시 노출하지 않는다. 긴 장 제목은 한 줄로 유지하고 전체 이름은 접근 가능한 이름/메뉴에서 확인한다. 우측은 세 개 선으로 그린 햄버거 아이콘이며 시스템 글꼴의 기호 모양에 의존하지 않는다. 보이는 배경 상자 없이 충분한 터치 영역·키보드 초점·열림 상태를 제공한다.

| 공간 | 순서와 동작 |
|---|---|
| 넓은 이야기 화면 | 지난기록 → 저장 → 불러오기 → 자동 OFF/ON → 빠른 저장 → 빠른 불러오기 |
| 좁은 이야기 화면 | 지난기록 → 빠른 저장 → 설정 |
| 모바일 설정 첫 부분 | 저장·불러오기·자동 OFF/ON·빠른 불러오기, 이어서 읽기 설정 |

기기 이름이나 물리 화면 방향만으로 메뉴 개수를 정하지 않는다. contain 후 실제 도구 영역에 여섯 동작이 읽을 수 있는 글씨·충돌 없는 터치 영역으로 들어갈 때만 넓은형을 쓴다. 고정 양식은 두 가지이며, 3/6 도구 표시는 별도의 작품 구도를 만들지 않는다.

도구는 본문보다 작게 표시한다. 권고 기본은 실제 표시11–12px, 최소10px이며 '무조건 본문 절반' 규칙보다 가독성을 우선한다. 보이는 세로 공간은24px 내외, 실제 비중첩 터치 영역은44px를 목표로 패널 보조 공간 안에 확보한다. 44px 투명 영역이 본문·이웃 버튼을 가로채지 않게 한다. 이 공간 때문에 패널/작품을 자동 축소하지 않는다. 부족하면3개형으로 전환한다.

개별 테두리·사각 배경·별도 도구 바탕은 없앤다. hover는 글자색/밑줄, 자동ON은 색+굵기/밑줄, 비활성은 색과 접근 상태로 구분한다. 키보드 초점 윤곽은 유지한다. 모바일에서 자동ON이 설정 안에 숨으면 설정 이름 옆 작은 상태표시와 접근 가능한 설명으로 알린다. 새 버튼을 추가하지 않는다.

## 6. 전체 메뉴·설정·저장·기록

상단 햄버거는 공통 읽기 메뉴 전체를, 하단 설정은 같은 메뉴의 읽기 도구/설정 부분을 연다. 서로 다른 저장/설정 구현을 만들지 않는다. PC는 작은 팝오버/대화상자, 좁은 화면은 호스트 가용 영역 안에 맞는 메뉴로 표시하고, 필요하면 메뉴 내부는 스크롤 가능하다. 본문 스크롤 금지와 설정 메뉴 스크롤을 구분한다.

전체 메뉴 권고 순서: 계속 읽기 → 저장/불러오기 → 읽기 설정 → 전체 화면 → 처음부터 읽기 → 작품 시작 화면 → 서재로 돌아가기. 작품 시작 화면 복귀는 실제 서비스 동선이 있는지 확인하고, 없다면 죽은 메뉴를 추가하지 않는다. 편집으로 돌아가기는 편집 미리보기에서만 제공한다. 브라우저 탭을 닫는 '게임 종료'는 추가하지 않는다.

설정은 현재 구현된 글 크기·자동 대기·연출 줄이기를 먼저 재사용한다. 글자별 표시 속도/음성/세부 음량 등은 현재 기능 유무를 확인하고, 존재하지 않으면 기본 개편에 장식용 컨트롤을 추가하지 않는다. 신규 설정은 별도 구현/검증이 확보된 뒤 제공한다.

- 자동은 자동 읽기이며 자동 저장과 구분한다. 선택·메뉴·확인창·전환·미준비·탭 숨김에서 정지하고 밀린 진행을 연속 실행하지 않는다. 복귀 후 새 대기를 시작한다. 불러오기/경로 되돌리기 후 자동OFF를 유지한다.
- 지난기록은 실제 읽은 글·화자·선택을 원고 단위로 묶는다. 기기별 페이지 조각을 중복 항목으로 쌓거나 읽지 않은 뒷부분을 먼저 공개하지 않는다. 기록 열기/스크롤/닫기는 경로·점수를 바꾸지 않는다.
- 기존의 명시적인 '이 지점부터' 경로 되돌리기는 이번 시각 개편 때문에 삭제하지 않는다. 일반 기록 열람과 구분된 확인 동작으로 보존하며 승인 없이 자동 되돌리기로 바꾸지 않는다.
- 수동·자동·빠른 저장, 기존 슬롯ID·작품별 격리·점수와 선택 경로·오류 시 현재 위치 보호를 보존한다. 저장 성공 후에만 완료 알림을 표시한다. 불러오기/덮어쓰기/처음부터는 기존 확인을 재사용한다.
- 메뉴 열기 중 본문 진행을 막고 닫기/Escape/초점 복귀를 보장한다. 메뉴 터치가 장면 advance로 통과하지 않는다. 선택지·저장 슬롯은 누를 수 있는 형태를 유지한다. '사각 배경 제거'를 모든 대화상자와 선택지 디자인 제거로 확대하지 않는다.

## 7. 편집 화면 적용과 보존 범위

서재·편집 도구·저장 창 자체를 고정16:9 안에 가두지 않는다. 이야기 미리보기만 가로/세로 양식으로 바꾸며 읽기와 동일한 Core·Ren’Py·글 페이지 규칙을 사용한다. 별도 Web 이야기 렌더러를 만들지 않는다.

편집기는 가로/세로 미리보기 전환, 해당 컷의 분량 참고, 실제 재생 진입을 제공한다. 초기 분량 안내는 `가로 예상3/4줄 · 세로 예상7/6줄 · 세로 글 넘김 예상`처럼 표현한다. 실제 native 측정이 없으면 '예상'을 명시하고, 글자/Enter 수는 세부 안내로 둔다. 현재18×9/162자 참고값을 새 양식의 확정 수치로 재사용하지 않는다. 정확한 기준 폰트/줄간격/내부 폭은 Runtime 측정으로 맞춘다.

원고·Asset ID·Flow·StageComposition·자유 배치·연출·오디오·작품 파일·기존 개인 보관함·legacy 저장소는 보존한다. 읽기 구도 선호와 글 크기는 원고의 인물 좌표를 자동 수정하는 근거가 아니다. ShortStory/A4 인쇄는 기존 Web 예외를 유지하며 이번 이야기 읽기 개편에 끌어오지 않는다.

## 8. 책임과 개발 단계

이 표는 기능 내부 순서다. 단계 간 작업 큐는 [실행 계획](product-completion-plan.md)만 소유한다. **사용자가 종합안을 확정하고 설정의 글씨 크기 조절을 요청했다. 아래 순서로 개편을 진행한다.**

| 단계 | 작업 | 통과 조건 |
|---|---|---|
| R1 | 두 고정 무대·contain·방향 전환 | 16:10/4:3/초광폭 여백, 실제 구도/원고 불변, 회전 위치 유지 |
| R2 | Ren’Py 하단 전체 오버레이·4/6줄 | 짧은/긴 글에서 같은 패널 높이, actor/background geometry불변, native 실측·무스크롤·문장 우선 |
| R3 | 햄버거·장 정보·도구·공통 메뉴 | 좁은/넓은 도구, 투명 상태, 클릭/터치/키보드, 메뉴 중 진행 차단 |
| R4 | 편집 미리보기·분량 안내·저장 복원 | 가로/세로 동일 재생, Enter/원문/경로 보존, 저장 후 재열기·컷내 위치 검증 |
| R5 | 통합 검증·검토 이미지 | 아래 비교 행렬 통과·초기/실패 증거 보존·미검증 범위 분리 |
| R6 | 검토 후 운영 반영 | 검증된 동일 후보를 제시하고 배포 단계의 승인 범위를 확인. 미확정 데이터 영구삭제와 분리 |

Core는 세 양식과 Stage Layout·배경/인물/Flow 해석을 소유하고, Web은 contain 투영·제품 메뉴·저장·자동 진행·접근성을 소유한다. Ren’Py는 본문·글 페이지·고정 패널·실제 장면 렌더를 소유한다. StoryDocument가 SSOT이며 Ren’Py save/rollback으로 병렬 진행 상태를 만들지 않는다. 구현 시 ADR0014의 동적 viewport 확장과 관련 계약을 명시적으로 부분 대체하고, 기존 저작 내용은 보존한다.

## 9. 검증과 검토 자료

모든 이전 테스트를 반복하지 않는다. 변경 경계의 테스트를 먼저 작성하고 새 영향이 있는 native/host 검증만 수행한다. 최종 통합 게이트는 기존 제품 검사와 충돌 여부를 확인한다.

- 양식:16:9·9:16, 바깥 영역16:10·4:3·초광폭, 작은 표시 영역·DPR·회전·브라우저 안전 영역.
- 글:한 줄 대사·정확히4/6줄·한 줄 초과·자연스러운 긴 해설·Enter/빈 줄·한영/이모지·공백 없는 긴 글·긴 화자명.
- 장면:해설·연결 화자·미연결 화자·어린이/성인·여러 인물·자유 배치·효과/소리. 같은 무대에서 패널/글 분량 변경 전후 인물/배경 rect를 비교한다. 서로 다른 양식의 rect 일치와 혼동하지 않는다.
- 진행:글 페이지→다음 컷·이전 글·선택 마지막페이지·자동ON/OFF·메뉴/탭 중 정지·빠른 저장/불러오기·재열기·방향 전환 후 읽던 위치.
- UI:상단은 장 정보만·SVG햄버거·3/6도구·투명 기본/hover/선택·비중첩 터치 범위·초점/메뉴 닫기·밝고 어두운 배경.
- 비교 자료:동일 원고를 가로/세로로, 짧은 대사·정확 상한·넘치는 글·선택지·메뉴 열림을 각각 실제 Ren’Py에서 캡처한다. 정적 도안/브라우저 에뮬레이션/물리기기/스크린리더/운영배포 근거를 구분한다.

## 10. 종합 확정한 기본값

1. **세 양식과 메뉴:**16:9·4:3·9:16을 지원, 방향에 따라 자동 선택. 16:10은 여백. 상단 전체메뉴/하단 설정은 같은 메뉴 재사용.
2. **표현:**전체 폭의 불투명 크림색 패널, 기본 가로4줄·세로6줄, 같은 설정에서 높이 고정. 숫자분수 없이 `‹ 이전`·`계속 ›`. 글/도구 배치 때문에 장면을 밀지 않음.
3. **조작:**도구 글씨11–12px/최소10px 권고, 시각24px 내외·비중첩44px 터치 목표. 세로 인물 표시는 기존 Core 정책 보존, 화자만 중앙인 대안은 별도 검토. 더 구체적인 높이·폭은 실제 렌더 검증으로 결정.

새로운 계정·교사/학급·공유/공개·보관/삭제 결정을 이 확인에 묶지 않는다. 사용자가 종합안을 확정했으므로 단계R1부터 구현하고, 변경 요구가 있으면 해당 항목만 수정한다.

## 2026-10-11 도구 바 높이와 상단 메뉴 보완

PC·태블릿의 흰 도구 바는 기존 48px에서 28px로 축소했다. 글씨는 12px를 유지하고 항목 간격은 화면 폭에 따라 16–44px로 넓힌다. 위아래 투명 영역을 포함한 클릭/초점 범위는 44px다. 글 상자와 12px 간격을 두어 입력 영역이 대사와 겹치지 않는다. 휴대폰은 버튼의 44px 행 간격을 유지하면서 각 행의 밝은 배경만 24px로 줄여 큰 흰 패널을 제거했다. 세로 2줄/가로 1줄, 기본 접힘을 유지한다.

상단 ‘···’는 **읽기 메뉴**를 열고, 글 상자 아래 ‘···’는 **읽기 도구 펼치기**다. 상단은 우측에 붙은 작은 팝오버이며 다음 네 항목을 제공한다.

| 항목 | 화면과 동작 | 복귀/보호 |
|---|---|---|
| 읽기 설정 | 글 크기·자동 넘기기 대기·동작 줄이기 | 설정 닫기는 같은 장면으로 복귀 |
| 전체 화면 | 작품 무대를 화면에 크게 표시 | Escape/전체 화면 해제로 원래 화면 복귀. 플랫폼 미지원 시 비활성/안내 |
| 처음부터 읽기 | 진행 경로 초기화 확인 창 | 취소는 현재 위치 유지. 확인 후 Core의 첫 컷으로 이동, 별도 저장 슬롯 유지 |
| 서재로 돌아가기 | 읽기 위치 보관 후 이동 확인 | 저장 실패 시 읽기 화면 유지. 취소 가능 |

팝오버는 배경 바깥 클릭·닫기·Escape로 닫고 열었던 버튼으로 초점을 돌린다. 실제 구현은 초점 이동과 자동 넘기기 일시 정지를 검증해야 한다. 이 이미지 기반 클릭 도안에서는 닫기와 Escape, 네 항목의 화면 이동을 제공한다. 전체 화면은 실제 브라우저 API 실행이 아니라 화면 상태 예시다. 처음부터/서재 확인 이후 화면도 예시이며 실제 작품 진행이나 저장을 변경하지 않는다.

## 2026-10-11 휴대폰 하단 밀착 보완

사용자 후속 결정에 따라 휴대폰은 글 상자와 읽기 도구를 하나의 하단 묶음으로 배치한다. 이전 154px 고정 하단 여백과 도구용 빈 영역은 폐기한다. 하단 안전 영역 위 8px에 고정하고 접힘 상태에서는 글 상자 자체가 하단에 놓인다. 도구를 펼치면 필요한 두 줄만큼 글 상자가 올라간다. 글 상자와 도구는 4px, 도구 두 줄은 2px 간격이며 각 행은 28px다. 접기/펼치기 버튼은 글 상자 오른쪽 아래에 합쳐 별도 세 번째 줄을 만들지 않는다. 가로 화면은 같은 하단 원칙으로 한 줄을 표시한다. 이 결정이 이전 휴대폰 44px 행/분리 배경 도안보다 우선한다. 휴대폰 터치성은 실제 제품 적용 시 별도 검증한다.

## 2026-10-11 읽기 도구 순서 확정

사용자 결정에 따라 모든 도안의 순서는 지난기록 → 저장 → 불러오기 → 자동 → 빠른 저장 → 빠른 불러오기다. 휴대폰 세로 첫 줄은 지난기록·저장·불러오기, 둘째 줄은 자동·빠른 저장·빠른 불러오기로 배치한다. 하단 밀착과 4px/2px 간격은 유지한다.

## 2026-10-11 제품 개편 반영 상태

사용자의 개발 시작 요청으로 우선 범위의 실제 제품 개편을 적용했다. 위의 도안 단계 기록은 당시 상태이며, 최신 구현/검증/남은 계약 항목은 [실행 계획](approved-ui-development-plan.md)과 [검증 기록](approved-ui-validation.md)을 따른다. 미확정 삼성 실측값·임의 범위 계약·thumbnail을 구현된 것으로 바꾸지 않는다.

사용자에게 보이는 기능 이름과 설명은 [제품 용어 기준](editor-terminology-and-time.md#제품-용어-사용-기준--2026-10-19)을 따른다. 내부 키·현재 파일 계약과 과거 검증 기록은 용어 정리로 바꾸지 않는다.


## 읽기 조작 설정과 시점 안내 — 2026-10-20

읽기 설정의 **화면 터치 방식**에서 독자가 조작을 고른다. 기본값은 ‘화면 어디든 눌러 다음으로’, 선택값은 ‘왼쪽은 이전 · 오른쪽은 다음’이다. 여러 글 페이지가 있는 컷에서는 페이지를 먼저 넘긴다. 첫 컷의 왼쪽은 그대로 유지하고, 선택지가 표시되면 오른쪽/기본 터치로 선택하지 않는다. 좌우 방식의 왼쪽 빈 영역은 이전으로 이동할 수 있고, 선택지 버튼 자체는 해당 선택을 실행한다. 메뉴·음향 시작 대기·전환 연출 중 무대 터치로 진행하지 않는다. 설정은 글씨 크기·화면 비율·자동 넘기기 대기 시간과 함께 이 브라우저에 보관하며 작품 파일의 원고에 쓰지 않는다. 이전 설정에 새 값이 없으면 기본값을 읽고 기존 보관값은 읽기만으로 덮어쓰지 않는다.

시점 전환은 작가가 정한 작품 연출이다. 명시적인 검은 시점 전환이 있고 해설 화자가 ‘시점 전환’, 본문이 전환 제목과 같은 순수 안내 컷(별도 Flow·끝맺음 없음)만 Runtime Core가 안내 전용으로 분류한다. Ren’Py에서 안내를 한 번 보여 주고 실제 전환 완료를 받은 뒤 Core 경로로 다음 본문에 진행한다. 실제 대사·해설이 있거나 선택지·끝맺음이 있으면 본문을 유지한다. 원고/컷 ID는 삭제하지 않으며, 뒤로 읽을 때는 Core 되돌리기로 안내 전용 컷을 지나 이전 본문으로 돌아간다. 시작 안내 앞에 본문이 없으면 현재 본문을 유지한다. 전환 안내를 글상자/접근성 본문으로 다시 읽지 않는다.

제공 놀스토리 옹고집전의 검토된 여섯 시점 안내 가운데 연출이 없던 네 곳에 검은 시점 전환을 추가 연결한다. 기존 두 곳의 작가 연출과 모든 본문·선택·배치를 보존한다. 정확히 알려진 제공 판본만 갱신하며, 사용자가 수정한 사본은 자동 변경하지 않는다. [검증](evidence/reader-controls-2026-10-20/checkpoint.json).
